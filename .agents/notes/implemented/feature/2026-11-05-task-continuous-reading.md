# Agent Note: 任务五视图采用连续阅读

Status: implemented

## Problem

任务内容、任务数据、资源、作答和执行记录使用不同的浏览方式。近期摘要与完整列表重复，技术说明和 JSON 占据主要阅读空间。记录详情集中放在列表末尾，难以对应正在查看的条目。

## Decision

用户确认三个原型中的 A「连续阅读」。五个顶部视图与现有三栏、六主题、字号偏好继续使用。内容保持完整铺开，目录仅滚动定位，不重建编辑器或重排已发布的 Surface。现有内容分页仍先保存输入，再检查版本切换。

`TaskInspector.RecordBrowser` 在进入视图时加载首批元数据。点击记录后，在该行下面打开一个只读详情；搜索与状态筛选明确只覆盖已加载项。列表与正文沿用原查询游标、版本约束和内存上限，不新增运行时接口。

数据对象先显示字段表，JSON 和固定 schema 在详情内切换。资源先显示受控文字或 JSON 预览，元数据放在来源页，原记录与来源导航保留。普通材料内容使用 React 文字输出，不能作为任务 HTML 执行。

作答展示不可变答案、原题版本与保存依据，并在已有近期快照范围内提供上一份作答对照。原题定义按原资源身份只读查询，不使用当前 View 替代历史。继续任务将选中作答 ID 写入确认框与新请求。取消不创建运行，不自动重放旧界面。

执行记录先呈现完整运行列表。消息、动作、审批、工具调用、事件和界面历史按分类展开，保持原记录查询与原结果核对。材料文件导入与粘贴文本入口前置，导入操作按行展开；未知结果、未保存文本、失败重试和丢弃确认沿用原约束。

## Alternatives considered

- B「列表联动」便于连续切换记录，但在现有任务栏和 Agent 栏之外又增加一列，压缩内容阅读区。用户选择 A 的原位展开结构。
- C「关联脉络」便于追踪来源，但需要持续显示任务内导航和关系链。当前来源导航保留在记录详情中，主界面采用五视图。
- 保留近期摘要与完整浏览器两套入口能减少变更，但重复条目和详情不在原行的问题继续存在。统一为自动加载的完整列表。

## Consequences

常用数据先以可读形式出现，技术细节按需展开。代价是列表详情与导航状态更多，需保护分段读取、版本冲突和异步响应隔离。搜索只覆盖有界的已加载元数据，不声称全文搜索；作答对照仅覆盖当前快照内的上一份提交。

内容目录只定位本页单元。原题定义展示保存的结构，不复活历史交互。运行结果仍区分运行终态、具体操作结果与交付事实，不把模型回复作为业务完成依据。

历史审计：[可调工作区](2026-11-04-resizable-workspace.md) 部分重叠，沿用几何与编辑器分离的约束；[统一设置](2026-11-04-application-settings.md) 部分重叠，沿用六主题和字号机制。[任务界面契约](../../proposed/architecture/2026-10-24-task-surface-contract.md)、[输入处理](../../proposed/architecture/2026-10-25-input-processing.md) 与[模型四原语](../../proposed/architecture/2026-10-25-model-tool-primitives.md) 保留业务协议和读取边界。本篇只记录宿主浏览层，不取代或归档上述决定。

## Testing

`tests/electron/task-reading.spec.ts` 验证连续内容目录、中文草稿、行内作答详情、上一份对照、资源安全显示、元数据切换、局部搜索、执行分类和六主题窄窗。既有 core、材料导入、分页续读、版本引用、证据与模型数据测试验证原流程。构建、类型检查、笔记树与格式检查通过。29 项相关 Electron 用例分批通过，包含六主题、390/720/1440px、版本引用、历史证据与长正文；材料丢弃确认有一次超时，单独及最终重跑通过。五个视图实际截图已检查。
