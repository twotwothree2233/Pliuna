# Agent Note: 统一设置与渠道模型

Status: implemented

## Problem

工作区分散了主题、模型、审批、插件和存储入口。每个模型单独配置 API 与密钥，重复输入且容易让同一服务的连接参数不一致。用户确认统一设置，并要求每个渠道可包含多个模型。

## Decision

`ApplicationSettings` 提供外观、模型服务、权限与审批、插件与主流程、存储与恢复、关于六类。右上角仅保留导出，入口在左栏底部；左栏隐藏时状态栏保留入口。设置通过 portal 覆盖工作区，并以 inert 隔离背景，保留原编辑器和草稿树。子弹层独立管理焦点，异步操作结束前不允许切页或关闭。

插件设置始终挂载，导入与查询按钮位于页首。导入固定包不依赖任务；没有当前任务时不请求 task_id 为空的 plugin.list，而是显示已有任务选择和新建入口。启用、停用、读取内容及主流程管理仍在任务关联后使用原契约。任务关联变化时以 task id 为 key 重建管理组件，避免旧任务的启用计划、确认和内容预览泄漏到新任务。

新建任务弹窗区分输入法组词与应用快捷键。任务名通过 composition 生命周期记录组词状态，并结合 KeyboardEvent.isComposing 与 keyCode 229 判断候选确认键。组词中的回车仅阻止表单隐式提交，Esc 留给输入法；组词结束同步最终文字，普通回车与按钮仍可创建任务。表单提交还检查组词、忙碌和空白名称，避免候选文本提前保存。

外观提供 90%、100%（默认）、110%、125%、140% 文字大小。`trellis-text-size` 保存本机显示偏好，非法值或存储不可用时以 100% 启动。选择更新根 `--text-scale`，界面字号以变量计算。正文样式经浏览器 CSSOM 解析，只转换字体声明内的绝对长度；相对字号沿用继承。正文表单控件显式保留原生默认字号基线，再随偏好缩放。此变换仅用于呈现，不写回 bundle 或导出。字号变化不重建 Shadow DOM，保留输入节点与草稿。

渠道持有地址、兼容 profile 和凭据，模型持有 wire ID、显示名称、容量、限额和压缩模型绑定。后端引用渠道凭据，不向 renderer 回传密钥。保存不联网，发现仅使用渠道连接，不发送任务内容。角色测试保留费用确认、取消和严格验证。

渠道修改以持久化成功为提交边界，失败保留内存原状态。共享地址、profile 或密钥变化会清空该渠道所有模型角色并增加修订。占用模型或发现请求锁住渠道连接；未占用模型的独立参数继续遵守原锁约定。取消发现后释放渠道锁。

settings v4 单独保存渠道，模型通过 channel_id 关联。auth.json 的凭据以引用共享，密钥不写入 settings.json。旧 v1–v3 只在内存归组，显式保存才升级；恢复不联网、不续跑。保留既有原子写入、未知结果禁止自动重放和存储冲突处理。

## Alternatives considered

- 保留多个独立弹窗可减少改动，但入口重复，模型与渠道仍缺少清晰关系。统一容器复用原插件和存储业务组件。
- 仅在前端复制渠道密钥到多个模型改动较少，但密钥需要重新进入 renderer，空渠道也无法独立保存。采用后端渠道实体与共享凭据引用。
- 读取旧配置时立即写入新格式可简化后续路径，但仅打开应用就改变磁盘状态。采用内存归组，显式保存才升级。

- 页面整体 zoom 可一次覆盖所有元素，但会同步改变栏宽、分隔线与断点。采用文字变量和仅显示用的正文样式转换，保留布局几何。
- 仅修改根 font-size 最少改动，但已有界面和正文广泛使用固定 px 字号。界面固定字号显式乘缩放系数，正文的固定字号仅在 renderer 转换。

- 要求先返回工作区选择任务可复用原入口，但未选择任务时插件页没有操作按钮。保留导入入口，并在页内提供任务关联；不通过创建隐式任务来填补空状态。

## Consequences

工作区更简洁，同服务多个模型只需配置一次连接。代价是新增渠道状态与 v4 持久化结构，需要覆盖旧格式、共享修改、失败和取消竞争。当前仅支持显式 Chat Completions profile，不新增自动路由或兼容性承诺。

文字缩放保留六主题的字体层级与几何基线。代价是正文 CSS 需要一次浏览器解析；极端自定义固定高度与裁剪规则仍由内容布局决定。相对单位自然继承，仅在字号声明处处理绝对长度，避免尺寸被重复缩放。

历史审计：[模型服务提案](../../proposed/architecture/2026-10-25-model-services.md) 部分重叠，保留未实现的自动目录与价格方向并互链；[可调工作区](2026-11-04-resizable-workspace.md) 部分重叠，更新入口事实并互链。任务输入、审批及存储恢复笔记仍保留独立语义。

## Testing

渠道单元测试覆盖共享密钥、跨渠道隔离、旧数据只读归组、占用、取消、空渠道与保存失败。Electron 测试覆盖真实设置分类、角色确认、凭据删除、重启恢复、六主题、窄屏、工作区状态与原插件和存储流程。字号 Electron 测试覆盖五档比例、栏宽不变、编辑器节点和草稿保留、方向键选择、暖纸主题、390px 窄屏、重启记忆及非法值回退。插件入口测试先复现未选择任务时导入按钮不存在，再覆盖导入取消、状态查询、新建任务、重启后选择已有任务。原有插件测试保留启用、停用、撤销和主流程路径。任务名 Electron 测试通过 Chromium IME 组合输入路径，先复现选词回车误建任务与 Esc 关闭弹窗，再覆盖两者修复、keyCode 229 兼容及中文定稿后普通回车创建。实际验证结果以会话报告为准。
