# Agent Note: Agent 侧栏采用连续对话

Status: implemented

## Problem

Agent 侧栏同时铺开工作摘要、运行说明、用量、审批历史和请求列表。对话空间被重复信息挤占，输入区随材料说明变高。用户选择原型 A，并要求完成状态并入 Agent 标题栏。

## Decision

显示位置与侧栏用途已由[Agent 状态栏与任务正文分工](2026-11-06-agent-status-sidebar.md)取代。以下保留原连续对话的决策依据；输入法、审批、挂载与不自动重放约束继续适用。

`AgentPanel` 管理连续对话、顶部状态及按需打开的工具。标题栏在同一行显示 Agent、当前状态、队列、更多和关闭入口。执行中、等待审批、失败、中断、取消与回复完成分别呈现，不新增独立常驻状态行。回复结束不推断整个任务已完成。

近期消息保持时间顺序，完整历史、工作摘要、运行详情与用量通过弹窗查询。待处理权限审批与界面替换继续在对话中展示，历史审批通过原记录查询。停止执行需明确确认，保留原取消接口与已提交结果。

`RequestComposer` 始终挂载，材料选择与队列按需打开。已选材料在输入区显示，可逐项取消。草稿、未知提交结果、材料部分失败及范围确认保持原流程，发送仍使用 `request.submit`，不自动重发。中文输入法组合期间的快捷键不能提交请求。模型与渠道配置留在设置中。

## Alternatives considered

- 原型 B 按请求归组便于逐次核对，但增加分组标题和折叠操作；用户选择连续对话。
- 原型 C 将对话、待办和详情分层，适合频繁处理审批；用户选择直接在对话中处理当前审批。
- 独立状态行能展示更多过程，但额外占用窄栏空间；状态合并进顶部，过程在详情中查看。

## Consequences

日常界面集中于阅读和输入，代价是查看队列与诊断需要打开工具。所有诊断入口继续调用原有只读接口。关闭或调整侧栏不卸载输入区，不新增运行时契约或持久化格式。

历史审计：[可调工作区](2026-11-04-resizable-workspace.md)、[统一设置](2026-11-04-application-settings.md) 和[任务连续阅读](2026-11-05-task-continuous-reading.md) 部分重叠，分别沿用挂载、配置入口与查询约束。[上下文压缩](../../proposed/architecture/2026-10-25-context-compaction.md) 与[输入处理](../../proposed/architecture/2026-10-25-input-processing.md) 仍定义业务边界，本篇只调整展示层。

## Testing

构建与类型检查通过。26 项 Electron 回归全部通过，覆盖真实宿主与本机合成模型的发送、标题栏完成状态、中文输入法组合保护、材料绑定、关闭重开草稿、六主题及 1440/720/390px、用量与原记录、队列取消、未知结果、部分材料失败、手动与辅助审批、停止确认、上下文整理和任务连续阅读。实际截图确认状态与 Agent 同行，正文没有独立完成条。测试使用隔离临时数据，不调用外部模型。
