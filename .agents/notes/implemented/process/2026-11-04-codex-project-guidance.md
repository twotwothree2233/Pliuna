# Agent Note: Codex 项目开发指引

Status: implemented

## Problem

仓库已有实现、专题文档、契约和决策笔记，但缺少 Codex 的项目入口。命令与模块边界需要反复发现，早期文档中的“尚未实现”也容易被当作当前事实。

## Decision

根目录的 [AGENTS.md](../../../../AGENTS.md) 提供稳定项目指引，汇总从现有代码与配置可核对的开发命令、职责边界、契约维护、前端约定和验证要求，并链接详细文档。它提醒维护者核对实现状态，不承担功能状态看板或任务交接职责。

模型服务指引引用现有渠道与模型分层设计；它不宣称新版设置原型已经接入正式代码，也不在本次修改中改变 schema 或持久化。

## Historical note audit

检索已有笔记中的 AGENTS、Codex、指引及流程后，没有覆盖项目开发入口的笔记。现有[工作台交互笔记](../feature/2026-11-04-resizable-workspace.md)与本决定部分相关：它持有布局行为依据，本文件仅导航与提醒，不替代其决定。其他架构提案及 Monty 测试笔记继续保持各自职责，无需迁移、删除或归档。

## Alternatives considered

- 只依赖专题文档：详细说明已齐备，能避免增加入口维护；但开发命令、进程边界和当前实现状态仍分散，无法满足用户要求的 Codex 项目指引。
- 在指引中复制完整架构和测试清单：单文件便于阅读，但会与专题文档及测试配置形成重复事实。采用简短规则、可执行命令与相对链接，详细内容继续由原文档维护。

## Consequences

后续任务获得一致入口，能识别原型与实现的区别，也能避开 Node/Electron SQLite ABI 混用。代价是命令、目录或开发约定改变时需要同步维护入口；因此不放入会话路径、临时产物或一次性结果。

## Verification

检查所有相对文件链接、命令对应的 package scripts、代码路径、Markdown 与差异空白；运行笔记目录、格式和归档校验。本次仅新增文档，不执行应用构建或业务测试，也不改动此前的前端实现与原型。
