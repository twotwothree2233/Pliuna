# Agent Note: 统一桌面打包与包内验收

Status: implemented

## Problem

现有分发脚本只接受 macOS ARM64。
生产依赖、worker 与目标资产需在包内保持一致。
源码冒烟无法覆盖打包后的进程入口和资源路径。
桌面快捷键提示也固定使用 Command 文案。

## Decision

统一入口复用已固定版本的 electron-builder。
只在原生主机制作统一目标表中的候选包。
Linux 必须确认 glibc，不执行未经配置的跨编译。
旧 macOS ARM64 打包与验包入口继续保留。

生产载荷在系统临时目录的独立暂存根准备。
收集器沿实际安装图解析生产依赖，再展开复制。
只选择目标 Monty 包，拒绝版本冲突和未知可选依赖。
SQLite 仅保留运行时 binding、库与许可证。

builder 不再次决定依赖闭包。
暂存 manifest 不携带开发依赖、安装脚本或用户配置。
生产依赖通过显式资源映射复制到 app/node_modules。
复制与结构检查拒绝链接、凭据和数据库。

暂存项目使用空 NPM lock 固定管理器探测。
该锁不声明依赖，也不进入安装包。
这样 Corepack 不会按环境选择并下载默认 pnpm。
真实生产依赖仍只来自已经收集的闭包。

ASAR 当前关闭，所有入口保持普通文件布局。
utilityProcess、监督进程及 Windows Job 模块显式检查。
process-control.js 导出实际进程树和 PluginRpc 模块。
验收脚本直接加载该模块，不加入生产测试后门。

macOS 默认候选格式为 ZIP，Windows 为 NSIS。
Linux 默认 AppImage，三者都支持目录包验收。
Windows 默认当前用户，不请求提升权限。
卸载保留原有用户数据，数据目录和格式不变。

构建显式禁止发布，临时屏蔽签名凭据。
macOS 使用本地临时签名并关闭公证。
签名跳过 Monty 目录，保留上游签名与字节。
构建结束直接比较原始资产字节，不计算文件摘要。

本机 Electron 的 framework 链接已被展开。
验收使用已缓存官方分发重新解压的临时目录。
--electron-dist 可显式指定同版本本地分发。
工具不修补已安装依赖，也不静默下载替代运行时。

桌面使用只读 preload 字段显示实际主机平台。
macOS 保留现有标题栏与 Command 文案。
其他系统使用 Ctrl 文案、系统窗口框及退出菜单。
包内应用忽略开发页面 URL，只加载本地页面。

计算能力继续由现有运行时验收门槛控制。
候选包存在或 binding 可加载不会开放计算。
关闭与退出仍沿用运行时清理确认及失败阻塞。
现有数据格式与默认数据目录保持原样。

新建任务按钮在业务忙碌时禁用。
这与既有快捷键及新建入口的忙碌保护一致。
桌面回归等待按钮恢复，再发送新建快捷键。
弹窗关闭也等待可见状态，不依赖固定延时。

## CI isolation and distribution links

四平台 CI 禁用 pnpm 构建副作用缓存。
依赖源码缓存继续使用，Electron 正常安装。
macOS 在签名前检查 framework 三处链接。
链接展开时明确失败，不手工改造上游分发。

文件、进程和包内探针各自保留失败结果。
前置构建和 ABI 切换成功后，独立探针继续。
任一测试失败仍使矩阵任务失败。
流程不使用 continue-on-error 掩盖持久化阻塞。

POSIX 可执行位在 POSIX 原生主机验证。
Windows 对无法保留可执行位的 POSIX 夹具明确拒绝。
Windows 仍验收本机载荷、原生模块及错误目标拒绝。
四个平台都保留实际目录包与包内启动门禁。

桌面测试启动环境彻底移除 ELECTRON_RUN_AS_NODE。
Windows 会把空值视为存在，误以 Node 模式启动。
键名按大小写不敏感规则过滤，避免继承别名。
包内 app-node 仍由生产监督入口显式启用该变量。

## Alternatives considered

- 继续逐平台手写打包器，便于细控平台步骤。
  但会重复安装器、依赖与资源布局处理。
  采用已有 builder，旧 Mac 入口保留作回退。
- 立即启用 ASAR，可缩小普通文件暴露面。
  但 worker、监督进程与原生加载已有普通文件契约。
  当前保留路径一致性，矩阵通过后再独立验收 ASAR。
- 由 builder 重新遍历生产依赖，可减少复制代码。
  但会重新引入包管理器探测与可选目标选择。
  改为显式暂存，builder 只处理分发外壳。
- 为本机展开后的 framework 修复链接，可复用依赖目录。
  但会改写上游安装内容，并掩盖分发本身的问题。
  改为显式使用重新解压的同版本官方分发。

## Consequences

统一目标、依赖闭包与包内路径都有检查入口。
包内进程链路不依赖源码 cwd、系统 Node 或 PATH。
代价是普通文件载荷较大，需持续维护入口清单。
显式复制依赖也需在依赖升级时重新审计。

本机 macOS ARM64 目录包提供真实运行证据。
四平台的发行格式仍需原生安装验收。
目录包结果由各平台 CI 单独记录。
ZIP、NSIS 和 AppImage 的安装体验不能由目录包替代。
签名、公证、正式发布与支持声明继续留在后续门槛。

执行契约、笔记目录与格式验证。

运行探针覆盖 SQLite、binding、app-node RPC 及整树退出。

随包 PDF 后端完成初始化和停止通信。

覆盖任务、快捷键、设置持久化、窄窗口及退出。
具体通过数、版本和原生缺项以会话报告为准。

独立测试分支按用户授权提交、推送并执行 CI。
