# Agent Note: Windows 测试目录的精确文件身份

Status: implemented

## Problem

Windows inode 可超过 JavaScript 安全整数。
普通 Stats 已在原生 CI 出现舍入碰撞。
原日志数值格式无法保存该身份。
用户已授权 A，旧目录升级 B 仍未授权。

## Decision

内存身份来自 BigInt Stats，使用规范十进制字符串。
普通 Stats 继续提供现有数值大小和时间。
前后精确采样须确认同一对象与元数据稳定。
不安全旧数值仍拒绝，不从路径回填身份。

新建 Windows 测试目录显式选择精确格式。
导出和 GC 新版本为 2，恢复选择器为 6。
退役和资源清理的新嵌套记录为 2。
现有目录按已存版本读取，不自动升级或迁移。

`TRELLIS_TEST_FILE_IDENTITIES=decimal-v2` 显式选择测试创建。
选择在 RuntimeStore 建立 owner 和插件控制前完成。
已有数据库、标记、配置和未知目录项阻止选择。
已有资源、恢复或插件内容也阻止选择。
Electron 的浏览器状态、日志和 HTTP 缓存可先存在。
模型目录缓存仍视为既有管理数据。
既有控制库依存储版本读取，不依赖重启时的开关。

macOS 默认继续写现有数值格式。
settings/auth、业务 schema 和内容格式保持原样。
删除、恢复和未知发布的保护边界继续保留。
新平台计算能力门槛不随格式变化开放。

## Alternatives considered

- 放宽 Number 安全整数检查，变更最小。
  但相邻文件编号已发生碰撞，不能采纳。
- 只在内存改为精确编号，可避免格式扩展。
  但导出、GC 和恢复日志仍不能保存删除权限。
  采用版本化格式，旧目录不迁移。
- 全目录自动升级，后续调用更简单。
  但用户只授权新 Windows 测试目录。
  当前采用显式启用与新目录门槛。

## Verification

相邻大编号不会被视为同一文件。
路径、句柄与父目录在替换后拒绝继续操作。
安全旧记录可读，不安全旧记录保留且拒绝。
未知版本、错误类型和非规范字符串均拒绝。

`file-identity.test.ts` 覆盖规范编码与舍入碰撞。
`file-format.test.ts` 覆盖新目录、旧目录与版本不匹配。
大编号夹具驱动真实 GC 和资源清理状态流转。
已有不安全数值的拒绝测试保留原记录。

三处控制库的版本与标记保持一致。
macOS 默认版本和数值时间字段保持不变。
新目录的完整业务与 GUI 由四平台 CI 验收。
原生结果以会话报告为准，不用本机替代。
本任务不主动计算文件摘要。

## Consequences

精确格式消除大编号舍入碰撞。
精确采样增加 stat 调用次数和拒绝变化的机会。
双版本读者增加维护成本，旧记录不转换权限。
旧版本必须拒绝新控制版本，不能降级写入。
Windows 目录断电持久性仍受 Node 能力限制。
旧目录升级、安装器和能力开放均不在范围内。
