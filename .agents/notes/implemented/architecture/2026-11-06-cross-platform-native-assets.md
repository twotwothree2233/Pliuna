# Agent Note: 跨平台测试入口与原生资产描述

Status: implemented

## Problem

Monty 与打包脚本各自固定 macOS ARM64 资产。
worker 还单独拼接 native 文件名。
平台包存在时，仍缺少统一的定位与开放依据。
测试入口也混合通用逻辑与平台专用验收。

## Decision

运行时与构建工具共用单一目标描述表。
数据位于 `src/shared/native-targets.json`。
选择函数与声明位于相邻文件。
目标包含系统、架构、libc 和资产入口。

描述表区分候选目标与运行时已验证目标。
只有 macOS ARM64 保持已验证状态。
其既有完整性元数据原样迁入描述表。
其他目标不因安装了平台包而开放计算。

Linux 必须确认 glibc 才匹配 GNU 资产。
未知 libc、musl 与未知架构明确拒绝。
资产只从应用依赖中的固定平台包定位。
不使用 PATH、外部环境变量或宿主解释器回退。

`MontyAssets` 显式携带 native 入口。
worker 不再自行推导架构文件名。
平台包校验覆盖名称、版本、系统与架构。
binary 和 native 都须留在同一平台包。

测试分为通用、原生和桌面三个入口。
通用基线覆盖描述、定位、门槛与既有纯逻辑。
原生计算和 macOS 打包保留独立入口。
`pnpm test` 仍串联完整单元与原生验收。

Node 与 Electron ABI 在同一目录顺序切换。
独立探针执行 SQLite 读写及 Monty binding 加载。
探针不创建 Monty pool 或计算进程。
桌面冒烟显式关闭计算并验证任务重启恢复。

CI 使用三个系统的四个原生执行器。
macOS 两种架构分别运行。
CI 当前只覆盖 A、B 的基线与探针。
完整文件恢复、进程树和安装包留给后续阶段。

## Alternatives considered

- 按平台继续增加硬编码，初期改动最少。
  但三个入口已有重复字段，易出现资产漂移。
  采用共同数据表，平台执行逻辑仍各自封装。
- 直接开放现有五个平台包，能快速扩大可用范围。
  但 Windows 仍缺进程树与持久化语义验收。
  当前只允许定位及 ABI 探针，不开放计算。
- 全部测试并入跨平台 CI，覆盖面最广。
  但既有文件恢复与进程语义仍待 C、D 验收。
  采用明确列出的通用基线，保留完整验收入口。

## Consequences

资产名称、版本和完整性元数据只有一个来源。
worker、运行时和 macOS 打包共享目标描述。
候选平台的安装与 ABI 问题可独立定位。
代价是需同步维护目标表及其类型声明。

当前 Windows、Linux 与 Intel Mac 仍不开放计算。
真实进程收尾与安装包验收是后续开放条件。
CI 执行器与最低系统版本分别记录。
本地结果不升级为远端平台验收结果。

凭据主入口仍使用 `FileModelStore`。
当前行为与旧系统凭据设计的差异已有说明。
本次不迁移凭据格式或改变默认数据目录。

含此行为的原生计算与包清单验收未执行。

远端 CI 尚未执行，代码未发布。
