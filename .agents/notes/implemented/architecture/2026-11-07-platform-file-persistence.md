# Agent Note: 跨平台文件操作与持久化语义

Status: implemented

## Problem

配置、资源与恢复控制各自实现文件操作。
Windows 缺少 POSIX 目录刷盘和权限位语义。
文件占用、路径别名与身份变化影响恢复判断。
统一接口需要保留已有格式与提交边界。

## Decision

文件操作集中于 `src/platform/` 的窄接口。
路径语法、文件操作与私有权限分别封装。
业务模块继续持有提交、保护和恢复状态。
平台层不推导业务成功，也不重放未知操作。

`absoluteFilePath` 验证并规范化主机绝对路径。
Windows 接受盘符、UNC 和扩展路径形式。
拒绝设备路径、ADS 和依赖当前目录的路径。
POSIX 保留合法文件名字符。

管理目录逐组件验证，不允许 junction 或链接。
用户显式选择的外部导出目录可以保留别名。
打开文件时复核句柄、目录项与父目录身份。
读取有上限，并复核读取期间的大小和时间。

默认及旧目录日志继续使用数值 `dev`、`ino`。
新 Windows 测试目录扩展见[精确文件身份](2026-11-07-exact-file-identities.md)。
身份超出安全整数范围时拒绝使用。
悬空链接按存在处理，不创建替代权威文件。
未知硬链接不得进入配置、资源或数据库链路。

POSIX 通过句柄设置 `0700` 与 `0600`。
Windows 常用路径使用[原生权限适配](../bug-fix/2026-11-08-windows-native-acl.md)。
已知不支持路径保留系统 PowerShell。
固定脚本只接收环境数据，不拼接路径代码。
权限执行或验证失败时关闭相关操作。

Windows 每次核对完整的私有 DACL。
仅当现有 DACL 与目标权限不同，才执行写入。
规则必须受保护、主体唯一且只含用户与 SYSTEM。
权限为 FullControl，并核对继承与传播标记。
已满足的隐藏属性也不重复写入。
这避免权限确认改变被冻结文件的 NTFS 元数据。
身份、ctime、发布和恢复的拒绝边界不放宽。

Windows DACL 禁止继承，仅允许用户与 SYSTEM。
权限子进程不继承模型密钥等额外环境变量。
应用目录同时设置隐藏属性。
首次读取既有配置时收紧其文件权限。

## Publication and recovery

发布前完成同目录暂存文件的写入和刷盘。
替换失败不通过删除目标绕过占用错误。
发布完成响应丢失时保留未知结果。
暂存项或锁被替换时，不删除外来项。

内部不可变资源继续使用单次 rename。
调用方持有运行时目录写锁，目标须不存在。
保留既有 staging 与恢复协议。
不为内部资源增加新的双链接中间状态。

外部新文件继续以硬链接实现无覆盖发布。
发布后清理源项前，再次核对登记身份。
外部覆盖在发布接口处复核既有目标快照。
显式选择的目录别名通过真实目录执行刷盘。

导出中断留下双链接时，允许受限恢复。
目标与暂存项须位于同一真实目录。
二者各有两个链接，并匹配已登记文件身份。
第三个外来链接阻止自动恢复清理。

配置保存保留 auth 准备、settings 提交和裁剪。
settings 发布时立即记录已跨越提交边界。
后续失败返回 `SETTINGS_RESULT_UNKNOWN`。
遗留写锁阻止加载，不自动抢占。

控制标记采用原子写入，内容和版本不变。
数据库、schema 与恢复日志格式不迁移。
恢复继续读取已提交事实，不自动重放业务。
清理失败保留原操作及其保护记录。

## Durability and platform limits

刷盘接口返回实际目录持久化级别。
POSIX 成功返回 `directory-synced`。
Windows 返回 `file-sync-only`。
Windows 文件刷盘使用可写句柄。

Windows 清理确认不标记为目录持久化完成。
macOS 保留原原因字符串与目录刷盘行为。
Windows 目录元数据断电一致性待原生验收。
UNC 共享盘还需验证服务端持久化语义。

Windows 旧后端仍需允许系统 PowerShell 执行。
旧数值身份无法安全表示的文件仍被拒绝。
既有目录的格式迁移仍需独立授权。
不要静默舍入身份或放宽到路径字符串比较。

## Alternatives considered

- 各调用方保留平台分支，初始迁移成本较低。
  但权限、文件身份和刷盘已有重复实现。
  采用共享模块，业务恢复状态仍归原调用方。
- 仅保留 chmod 和隐藏属性，无需额外子进程。
  但二者不能在 Windows 建立私有 DACL。
  采用系统 PowerShell，路径只作为环境数据。
- 新增原生权限辅助程序，可直接操作平台句柄。
  但本阶段会增加编译、签名和分发依赖。
  原阶段先使用系统能力，保留原生验收门槛。
  后续性能适配由上述独立笔记接续。
- 所有新文件统一使用硬链接，无覆盖语义直接。
  但会给内部暂存恢复增加新的双链接状态。
  内部保留单次 rename，外部保留硬链接发布。
- 失败后删除旧目标再重试，可绕过部分占用。
  但会破坏失败保留原文件的既有约定。
  采用明确失败及原操作恢复入口。

## Consequences

配置、资源和恢复共享文件安全与刷盘边界。
macOS 的格式、提交顺序和目录刷盘继续保留。
Windows 权限失败、占用和身份缺口明确可见。
代价是权限子进程开销及新增平台验收工作。

Windows ACL、共享锁和长路径已通过原生用例。
Linux、Intel Mac 与 ARM64 Mac 文件门禁均通过。
共享盘、最低版本及目录断电一致性仍待验收。
本地 macOS 测试不升级为其他平台支持声明。

进程树实现见 [D 阶段生命周期](2026-11-07-managed-process-lifecycle.md)。
候选平台与安装包仍需原生验收。
