# Agent Note: 最小本地 Harness 与受控任务界面

Status: proposed

## Problem

早期协议将 workflow 设计成阶段状态机，并未明确桌面技术栈、审批模式和普通界面的实现约束。后续访谈明确只交付 harness，不开发真实插件；需要保留界面自由度，同时避免工作流引擎、全格式解析器和持久执行工作区使内核膨胀。

## Proposal

用户已确认产品与技术方向，仍未实现，因此记录保留在 proposed，不将确认设计等同于落地完成。当前规范入口为 [Harness 文档](../../../../docs/README.md)。

采用单用户 Electron + TypeScript，React/Vite 宿主与独立 Node.js runtime；SQLite、私有文件资源、系统凭据存储；JSON Schema + Ajv 并生成类型；Vitest 和 Playwright。

单主 agent 可在无 workflow 时自主完成基础任务。Workflow 仅为说明，不建设领域状态机。审批为手动或独立无工具模型代批，硬禁止先于审批执行。

普通内容统一 DOM 受控构建，只有需要任意 DOM 脚本的区域单独隔离；不以每 View 一个 WebContentsView 为默认。只提供少量基础交互，不建设通用交互语言。

内置代码执行无宿主文件/网络、显式输入、单次销毁，输出由 tool 接管保存；不采用任务级持久执行工作区。接受 Python 子集，Monty 仅为优先验证候选，用户本次要求先写其他文档，未批准原型或最终后端。

## 2026-10-26 契约细化

工程候选确定为 pnpm workspace、electron-vite、electron-builder、better-sqlite3、json-schema-to-typescript；精确版本待原生兼容性验证后锁定。runtime 是业务数据库唯一写入者，使用窄 IPC 和短事务。UI 同步采用快照与有界内存增量，后台可有界重启但不恢复旧业务。放弃任意 IPC/裸数据库共享，避免多个写入权威及长事务堵塞。

共同制品见[核心实现契约](../../../../docs/contracts/README.md)。本次是既有决定的细化，仍为 proposed，不宣称运行时已实现；结构校验与真实行为验证分开。

## Alternatives considered

- Workflow 状态机：阶段约束可靠，但增加领域流程引擎，用户选择由 agent 解释流程说明，接受步骤遵循非确定性。
- 每个 View 一个 WebContentsView：执行上下文直观，但统一布局、滚动、浮层和拖拽复杂，改为普通内容统一 DOM，自定义脚本按需隔离。
- Docker 作为执行依赖：隔离部署成熟，但增加用户安装负担，用户明确拒绝。不因此退回宿主直接执行。
- 任务级代码工作区：跨调用便利，但违背一次性计算工具的明确要求；保留任务资源，不保留执行空间。
- 主 agent 自批：实现简单但提议与授权不独立，采用独立无工具权限的模型调用。
- 多平台同时验收：覆盖广但增加初期成本，先 macOS，集中封装平台差异而非散布专用代码。

## Acceptance criteria

- 当前文档区分已确认方向、推荐实现和待决项；不宣称已有运行实现。
- Workflow 没有领域状态机；无插件也可运行通用任务；测试夹具不是实际插件交付。
- 共享 DOM 不执行生成的任意脚本；隔离脚本不能直接外联或操作宿主。
- 两种审批、批准绑定、硬禁止和失败转人工具备明确契约。
- 代码执行工作区不持久化；Monty 选型待验证，未决项不被隐瞒。
- 文档相对链接、JSON 示例和笔记门禁通过；实际安全测试留给实现阶段。

## Risks

统一 DOM 的 CSS/HTML 约束需要真实实现和负面测试，逻辑所有权不能单独保证隔离。审批模型可能误判，不替代硬限制。SQLite 与文件存储不能假定跨介质原子提交。Electron 分发、凭据与沙箱平台能力仍待验证；当前文档不是实现验收。
