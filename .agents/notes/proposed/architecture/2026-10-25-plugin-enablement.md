# Agent Note: 插件内容形态与显式启用

Status: proposed

## Problem

所有插件统一要求进程会迫使纯技能作者编写启动程序；安装即参与任务会扩大读取范围和上下文。混合贡献、主流程和执行中配置变化需要统一边界。

## Proposal

用户已确认，尚未实现。当前规范见[插件接入](../../../../docs/harness/plugin-integration.md)和[协议](../../../../docs/protocol-v0.1.md)。

纯内容包静态校验即可，无后端运行环境或握手；执行部分需要信任、按需启动和握手。混合包只保留依赖满足的独立能力，不隐藏局部不可用，前端脚本继续隔离。

安装只供发现，用户按能力类型分类查找、按插件整体启用，主 workflow 单独选择且至多一个。Agent 可看静态摘要和建议，不能自行启用。启用不立即加载正文、启动进程或调用工具。全局插件应用级启用，不自动向全部任务注入流程。

未结束 Run 或插件动作/调用阻止普通配置变更，等待审批同样占用。紧急停用始终允许，撤销相关访问、取消依赖执行并拒绝迟到结果，保留内容；主流程插件停用清除选择、不自动替代。全局更新等待相关占用释放，停用提示影响。变更不启动 Run、不改写历史。

## 依赖与转调补充

用户后续确认：必需依赖由宿主汇总，用户一次确认共同启用；缺失、版本不符或依赖环阻止相关能力，不自动安装/启用可选依赖。敏感范围仍人工确认，停用显示影响并取消依赖执行。

跨级依赖不传递权限，工具转调保留真实来源、任务和授权，可追踪资源按本次范围检查。全局独立动作不与委托调用身份混用。宿主不能保证识别插件混入普通文本的越界数据。

宿主维护调用链，拒绝重复进入同一插件实例，避免串行实例内嵌套等待；无环链仍限制深度、总次数及耗时，继承来源取消和预算，无 Run 动作有独立限额。控制和查询保持响应。多条并发链之间的实例名额互等使用嵌套忙碌即拒绝策略，不宣称插件内部或外部系统无死锁。

本补充细化同一插件启用/依赖决定，原地同步而不另立重复笔记；保留原替代方案和历史审计。

## 嵌套调度补充

用户后续确认：顶层可有界排队，嵌套目标忙碌直接返回未执行，不排队、不自动循环重试。先审批后获取目标名额，审批立即返回动作标识，不预占目标、原 RPC 或写锁；父调用仍占自身实例及预算。批准后复核再派发，目标变忙仍未执行。

父调用结束、取消或超时使未派发子调用失效，迟到批准不转为独立执行。已派发沿取消关系处理。普通子失败由父工具处理，必要步骤缺失报告失败或部分完成并引用子结果；宿主不证明业务完整性。来源取消、超时、撤权不可忽略，未知结果不按未发生重试。

## 审批等待与超时补充

用户确认分别管理有效执行超时、审批有效期和 Run/独立动作总墙钟。仅创建审批不暂停计时；宿主核验关联未完成审批并进入显式等待状态才暂停相应有效计时，此时父调用只允许查询、取消和接收结果，业务执行先退出等待恢复计时。不冻结插件进程，其他执行和总墙钟不随之暂停，既定占用及已消耗预算保留。

审批过期仅使对应操作未执行，旧入口失效，不续期或自动重复申请。有效来源恢复处理结果；来源总墙钟到期终止关联执行。批准/到期竞态由宿主判定，迟到批准不能复活失效操作。具体时长、状态及计时机制待定义。

本补充原地细化既有嵌套审批与预算取舍，不改变先审批后取执行名额和父子取消关系。

## Alternatives considered

- 所有插件统一进程：接入形式一致，但强迫内容作者承担运行环境与协议成本。
- 安装自动启用：减少选择步骤，但扩大任务读取和上下文，改为用户明确启用。
- 任意单项能力开关：细粒度灵活，但容易拆坏内部依赖；首版整体启用，流程另选。
- 运行中随时换能力：调整方便，但破坏当前计划、工具和依赖的一致性；仅安全撤销立即生效。

- 静默启用依赖：使用方便但可能扩大权限，改为一次展示并确认，不自动安装。
- 依赖继承被调用插件权限：复用简单但可能借全局能力绕过任务范围，保留来源身份与逐次检查。
- 环形转调排队：沿用串行调度直观，但父调用等待子调用时可能互等，当前链重复实例直接拒绝。

- 嵌套调用等待忙碌实例：更少忙碌错误，但跨链可能互等；首版明确未执行，避免新增等待图与可重入调度。
- 审批时预留子目标：批准后易立即执行，但人工等待会占住共享实例，改为获批后再竞争名额。
- 子失败强制整链失败或一律成功：前者阻止部分成果，后者掩盖必要步骤；父工具如实报告，宿主强制取消及权限边界。

- 所有等待共用工具超时：实现简单，但人工考虑会耗尽短工具超时，改为有效执行、审批和来源总时限分开。
- 有审批即暂停计时：接入方便，但父调用可能继续工作，要求宿主验证等待并限制其业务入口。
- 冻结 OS 进程：可暂停计算，但会影响全局实例及控制消息，首版不采用，也不承诺暂停插件自行计算。
- 审批过期即整轮失败：传播简单，但阻止其他已授权工作，按操作到期与来源到期分别处理。

## 历史审计

检索十篇活跃架构笔记，无完全吸收或应归档项。[插件信任](2026-10-25-plugin-trust-and-task-ownership.md)、[任务界面](2026-10-24-task-surface-contract.md)、[最小 Harness](2026-10-25-minimal-local-harness.md) 部分重叠，本篇限定进程要求为后端可执行能力，细化目录和显式启用，保留既有信任理由。[任务停止](2026-10-25-task-stop-and-resume.md) 部分重叠，任务停止与插件停用仍不同。其他命中为状态恢复、输入、导出、压缩、模型服务及 Monty 的背景引用，不修改其独立取舍。

## Acceptance criteria

- 静态包无进程可用，混合包依赖缺失明确展示，不越过整体必需依赖。
- 分类中同插件共享启用状态，主流程独立且至多一个；agent 不自行启用或加载未启用正文。
- 执行占用阻止普通变更，紧急撤销及时生效，历史成果不删除。
- 全局作用域明确，无自动流程注入；配置变化不自动执行。
- 文档与示例校验通过；实际 UI、生命周期和竞态测试待实施。

- 必需依赖确认、版本/循环拒绝、跨级转调越界拒绝均需测试；当前链重入直接拒绝，预算不重置，取消传播且控制通道可用。

- 并发 A/B 互调无实例名额等待；审批不预占目标，获批变忙返回未执行；父结束与批准竞态不产生孤立执行。
- 普通失败可部分返回但必需步骤缺失不报全成功；取消、撤权及未知结果不被忽略。

- 显式等待验证、业务入口限制、计时恢复、不释放占用及预算不重置均需测试；无 Run 动作同样有总时限。
- 审批过期与来源到期结果不同，迟到批准/取消竞态不能复活执行；当前仅文档验证，无行为测试。

## Risks

依赖与执行占用关联、版本变更检测的具体字段仍待设计。纯内容仍可能包含诱导指令，静态校验不是内容可信证明；可信插件 OS 行为仍不受统一沙箱约束。全局启用和任务内容加载必须在界面上明确区分。

调用链字段、错误码和限额尚未确定；单链重入拒绝与嵌套忙碌即拒绝仍需竞态测试，不是所有并发场景的无死锁保证。
