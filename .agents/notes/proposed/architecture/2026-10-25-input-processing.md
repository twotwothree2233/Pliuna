# Agent Note: 惰性导入与按需材料解析

Status: proposed

本篇关于业务请求/写入意图/事件去重的历史表述已被[删除业务去重决定](2026-10-26-no-business-deduplication.md)取代；其他独立契约继续有效。历史理由保留，不作为当前实现要求。

## Problem

保存材料与执行解析若混为一体，会隐式启动代码、外发或产生费用。多文件部分失败、大解析结果和旧派生资源还可能让模型误以为材料完整、已读完或仍适用。

## Proposal

用户已整批确认，尚未实现。当前规范见 [输入处理](../../../../docs/harness/input-processing.md)。单独导入只保存登记；随明确请求按需处理，附件不全先由用户决定部分继续或补齐。批次逐项提交，取消保留成功项，重试只针对失败项。

首版入口为文件和明确添加为材料的文本，不内置网页抓取、目录递归或解包。解析复用工具协议，由 agent 按需求选择，不默认执行所有候选。派生结果绑定原件版本、能力版本和参数，新解析新建资源，不覆盖或自动刷新历史。

大结果保存为资源，直接响应有界，正文按范围读取并明确截断和定位局限。导入默认惰性，预览受控且不自动外联，活动内容不能直接进入任务 DOM。插件既有可信本地执行边界不变，不承诺宿主能够阻止接口外 OS 行为。

## 2026-10-26 契约细化

预览复用当前已验证的完整前端呈现能力，不另限纯文本/位图；HTML/SVG/公式/媒体可按受管理 profile 展示。只有缺能力才降为元数据/源码，不隐式运行材料代码或引入全格式解析套件。该补充保留惰性导入原则，未验证 JS profile 不自动启用。

共同制品见[核心实现契约](../../../../docs/contracts/README.md)。本次是既有决定的细化，仍为 proposed，不宣称运行时已实现；结构校验与真实行为验证分开。

## Alternatives considered

- 导入即自动解析：减少等待和操作，但会隐式执行/外发且浪费无关处理，采用明确请求按需处理。
- 独立解析调度框架：统一格式路由方便，但扩大内核并重复工具协议，沿用能力声明和 agent 选择。
- 整批原子导入：结果简单，但一个坏文件会撤销全部成功工作，采用逐项提交并让缺附件的请求先确认。
- 自动缓存命中和升级刷新：可减少重复操作，但相同参数不证明结果适用且刷新有额外成本，允许 agent 查询后复用，不自动替代调用。
- 全文直接返回模型：调用路径少，但超出上下文且难辨截断，采用资源引用与分段读取。

## Acceptance criteria

- 单独导入无自动 Run、解析或模型发送；附请求缺附件不静默继续。
- 批次失败/取消不删除成功项，未完成项不成为有效资源，重试不重复成功项。
- 派生版本和真实来源保留，读取截断可见，无自动全量重解析。
- 活动内容和外部引用不能借预览执行，不能预览不等于保存失败。
- 文档与笔记校验通过；真实渲染预览、导入故障及模型行为测试尚待实现。

## Risks

用户需显式触发处理，agent 选择能力和判断复用可能出错；声明不能证明解析质量或约束插件 OS 行为。预览解析器自身需安全验证。能力/来源字段、读取协议、配额与批次去重未定，不把文档当作已实现 SDK。
