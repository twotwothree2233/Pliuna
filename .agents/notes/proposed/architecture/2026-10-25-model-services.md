# Agent Note: 模型自动配置与占用锁

Status: proposed

## Problem

让用户手填全部能力参数增加部署负担，但兼容接口和目录声明不能证明真实能力。执行期间更换渠道、密钥或模型会使数据去向和预算漂移，跨任务调用还需要防止无界并发。

## Proposal

用户已整批确认，尚未实现。当前规范见 [模型服务](../../../../docs/harness/model-services.md)。服务接口发现模型与能力优先、models.dev 补全、关键缺失局部手动兜底；实际目录字段和匹配尚未调研，不作为已验证事实。

用户触发有界合成请求测试并启用，不用任务材料。主模型验证必要工具/流式能力，其他角色按需检查。失败不自动切换模型/渠道/凭据。

未结束 Run 和已调度独立请求占用模型及渠道，占用即禁止修改/删除；未占用模型的独立参数可编辑但不能改共享渠道。任务请求尚未启动不锁配置，记录选择，启动前复核且变更先确认。所有使用者释放后才可编辑。

目录自动刷新但确认后才改有效配置，保留手动值，价格独立用于后续估算不改预算/历史。所有角色请求统一有界公平调度，并发名额与配置锁分离。

## 2026-10-26 契约细化

明确兼容 profile，不任意 extra_body 透传；models.dev 精确 provider+wire ID，正数容量，未知能力不猜测。结构化输出不强制服务原生 schema，但本地严格校验，不提取修补 JSON。默认模型并发应用4/渠道2，价格缺失显示估算/未知，严格货币限额不能静默忽略。取舍：兼容 profile 需要显式支持服务差异，但不允许字段覆盖绕预算。

共同制品见[核心实现契约](../../../../docs/contracts/README.md)。本次是既有决定的细化，仍为 proposed，不宣称运行时已实现；结构校验与真实行为验证分开。

## Alternatives considered

- 先手工填写能力表：来源直接，但用户负担大，改为自动发现后仅补缺项。
- 容量未知用保守默认值：减少阻塞，但猜测容量仍可能失败且用户明确不接受，改为手动补充后启用。
- 运行时冻结旧版本但允许改配置：灵活，但用户明确要求占用时不能改，采用模型/渠道锁。
- 失败自动切备用模型：提升连续性，但数据去向、费用和行为变化不可静默决定，改为用户明确选择后新 Run。
- 渠道使用时锁住所有模型：实现直观，但不相关模型独立参数无需阻塞，锁共享渠道与实际占用模型即可。

## 历史审计

[最小 Harness](2026-10-25-minimal-local-harness.md) 部分重叠，保留 adapter、角色分离和简洁 loop，本篇细化配置与调度。[上下文压缩](2026-10-25-context-compaction.md) 部分重叠，压缩模型继续可另配但必须遵守占用锁与统一调度。插件信任、存储恢复、输入、导出及 Monty 决定继续有效，无需替换或归档。

## Acceptance criteria

- 自动发现/手动补缺的来源与有效性可检查，测试不泄露任务材料或凭据。
- 多 Run 与独立请求占用锁可验证，两类排队不混淆，取消后不再派发。
- 目录更新不绕锁或覆盖手动值，不自动换模型，价格不改历史。
- 应用/渠道并发上限与简单公平排队可测试，审批等待不占请求名额。
- 文档与笔记校验通过；实际服务和目录兼容性仍待调研/验证。

## Risks

目录可能过时或匹配失败，手动值也可能错误；合成测试不证明真实任务质量。占用锁会延迟配置维护，公平调度增加等待；需显式取消与清晰占用显示。schema、测试标准、配额及锁的并发实现未定，不将设计当成已完成接入。
