# Agent Note: 删除业务请求与事件去重

Status: proposed

## Problem

旧契约要求 write 和动作申请按主体/任务/意图键去重，表单事件按客户端 ID 去重。讨论记录保留期时用户先选终态后默认 1 小时，随后明确撤销整个去重功能，并确认事件提交一并删除：相同内容不能作为复用输出的理由。

## Proposal

用户已批准，仅文档落地。write、call、动作申请、业务请求及表单事件不按客户端标识/参数/内容去重；每次有效新提交由宿主分配唯一 ID 并独立校验授权、版本及状态。查询原 ID 不执行，再提交是新操作；未知结果/响应丢失不自动重发。表单提交期间禁用按钮减少误触，不合并相同答案。不实现意图键、规范化参数摘要比较或 1 小时去重窗口。

业务修改、对应业务记录/引用与 Action 成功结果同数据库事务提交，不保存去重绑定。响应失败不改变已提交成功事实；先查询持久化结果，不自动重做。文件仍先保存，不承诺跨文件系统/插件副作用事务。版本校验、原动作终态不复活及已发布草稿不再次发布继续适用，不是按新请求内容去重。

当前规范见[工具与资源](../../../../docs/harness/tools-resources.md)、[存储与恢复](../../../../docs/harness/storage-recovery.md)及[协议](../../../../docs/protocol-v0.1.md)。

## Alternatives considered

- 任务生命周期保留去重记录：可识别较晚重试，但用户不接受长期保留，曾改选默认 1 小时。
- 终态后 1 小时去重：有界存储并保护未完成动作，但用户随后拒绝整个机制，此窗口一并撤销。
- 规范化 JSON 摘要判断参数一致：确定性强且不会受键序影响，但用户不要求任何相同请求的结果复用，不实现。
- 只删除 write 去重、保留表单事件去重：可减少重复答案，但用户确认统一删除；改用提交期间按钮禁用和不自动重发。

## 历史审计

精准检索活跃笔记命中三篇，均部分重叠，无完全吸收/归档项：[四原语](2026-10-25-model-tool-primitives.md)的 write 去重及其验收被取代，其他工具与生命周期保留；[插件信任](2026-10-25-plugin-trust-and-task-ownership.md)的业务去重 ID 表述被取代，授权和可信执行保留；[输入处理](2026-10-25-input-processing.md)的去重字段待决被移除，逐项导入与失败重试边界保留。三篇互链并标记历史规则失效，不翻写旧理由。

## Acceptance criteria

- 同内容新请求获得不同宿主 ID，独立校验，不按客户端键/参数返回旧执行。
- 查询旧 ID 无执行，响应丢失不自动重发，表单有效重复提交产生新记录。
- 事务保存业务事实及 Action 成功，响应失败不覆盖提交状态，不存在去重字段/窗口。
- 版本、范围、生命周期检查保持，动作状态合法性不被误删。
- 文档与笔记校验通过，真实运行时/事务测试尚未实施。

## Risks

用户或调用方再次提交可能产生重复成果或副作用；唯一 ID 只管理操作，不保证恰好一次。宿主响应丢失且调用方尚未获得 ID 时，查询定位体验仍需设计，不能以此重新引入自动重发/去重。界面防误触不是重复提交的服务端保证。去重删除不影响受管理不可变资源的底层存储复用，也不要求禁止可信插件自己的内部实现策略。
