# Agent Note: 任务界面与插件契约

Status: proposed

## Problem

学习任务需要可持续演进的前端界面，不是一次生成静态 HTML，也不是把学科内容塞进固定教学模板。不同插件需要自由构建界面，但不能未经授权修改其他插件的内容或读取其状态。

## Proposal

采用任务界面、呈现单元、插件实例和呈现能力作为核心术语。“画布、画笔”仅为抽象，不要求像素坐标或 Canvas 实现。具体行为契约见 [协议草案](../../../../docs/protocol-v0.1.md)。

Harness 管理执行、身份、权限、状态、界面提交和交互事件；插件提供流程、知识及呈现能力。界面修改经过暂存和原子发布，运行隔离先于事后校验。工具提供者不自动取得调用方产物所有权。

v0.1 建议使用任务级界面版本比较与单个有状态写入 run，接受不相关更新发生保守冲突，以降低并发协议复杂度。原子发布只覆盖宿主模型，不覆盖外部工具副作用或所有客户端的瞬时显示。

## Alternatives considered

- 固定内容 schema 与预置教学组件：一致性与验证成本较好，但新学科常需修改核心，不能满足任务界面自由构建的要求。可作为高级呈现能力，而非唯一通道。
- 插件直接修改共同 DOM：表达自由且原型简单，但样式、事件和状态可互相破坏，事后检查不能撤销已发生的影响。
- 所有内容都强制使用隔离 HTML：自由度高，但普通插件也承担前端成本。协议保留宿主管理的呈现能力及可协商的代码隔离 profile。
- View 级自动并发合并：减少冲突，但布局和状态依赖会显著增加实现复杂度，v0.1 不采用。

## Acceptance criteria

- 两种不同任务可以不修改 harness 而构建不同的学习界面。
- 越权更新、授权撤销后提交、旧通道事件及取消后的迟到提交被拒绝。
- 批量提交失败保留原界面，重复请求不重复发布，输入中的用户内容不被静默覆盖。
- 核心不规定教学流程，公共呈现工具不改变调用者的产物所有权。
- 协议中列出的契约测试在实现后自动执行；当前只校验文档及示例结构。

## Risks

协议仍需机器可读 schema、桥接 SDK、具体配额及隔离实现；文本契约不能替代安全测试。Iframe 不是 CPU/内存硬隔离。任务级版本检查可能增加冲突，单写入限制影响吞吐。支持任意前端代码与可验证安全之间存在真实成本，不承诺静态检查证明任意脚本安全。
