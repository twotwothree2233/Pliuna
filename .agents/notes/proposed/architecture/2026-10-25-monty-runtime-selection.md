# Agent Note: 首版内置计算工具选择 Monty

Status: proposed

## Problem

基础执行工具需要显式输入输出、一次性销毁、无宿主文件/网络能力和无需 Docker 的分发方式。发布包冒烟已经提供具体证据，需要结束候选探索并明确集成基线，同时避免将选型批准误认为完整安全验收。

## Proposal

用户已确认选择 Monty，原生后端为首版集成基线，不并行实现 WASM；只提供受限 Python 计算工具，不支持任意第三方库，也不替代插件执行或前端隔离。

当前契约见 [代码执行选型](../../../../docs/harness/code-execution.md)。保持显式数据、无挂载/宿主回调、单次会话及 worker 退役、外部截止时间与输出校验。完整实现未交付，因此生命周期保留 proposed；这表示实现尚未落地，不表示用户尚未确认选型。

## 2026-10-26 契约细化

返回值采用保留类型的带标签编码，bytes资源化，循环/不支持值拒绝交付但保留执行事实，不repr替代或重跑。不承诺确定性，宿主不额外提供时钟/随机/等待回调；Monty本身行为和具体类型仍需实测。普通工具时限不能替代Monty生产计算配额。

共同制品见[核心实现契约](../../../../docs/contracts/README.md)。本次是既有决定的细化，仍为 proposed，不宣称运行时已实现；结构校验与真实行为验证分开。

## Alternatives considered

- QuickJS/WASM：适合小型 JavaScript 计算工具，但 Monty 已实测支持所接受的 Python 子集与限制，选择它作为当前唯一集成基线，避免并行平台成本。
- Pyodide：科学计算包生态更广，但当前明确不要求第三方库，为基础工具引入更多兼容和宿主桥接管理成本没有必要。
- Monty WASM：有跨平台分发潜力，但尚未实测，原生发布包已通过有界检查，先验证原生集成而不是同时建设两套。

## Acceptance criteria

- Electron 干净 macOS 安装验证通过，无系统 Python/Rust/Docker 依赖，可信运行时路径和签名分发成立。
- 取消、超时、崩溃、退出后的执行清理与迟到结果拒绝通过测试。
- 资源/输出总量、复杂返回和权限绕过完成测试；剩余风险明确，不将分配计量当 RSS 硬限额。
- 通过上述门槛前不正式启用工具，不退回宿主直接执行。

## Risks

Monty 是语言级而非 OS 级沙箱，解释器漏洞不保证有第二层 OS 隔离。已通过的 8 个用例不代表完整攻击测试。原生分发、跨平台和强制清理仍可能带来成本；严格 OS 隔离、RSS 硬限额或科学计算包需求出现时需要重访选型。
