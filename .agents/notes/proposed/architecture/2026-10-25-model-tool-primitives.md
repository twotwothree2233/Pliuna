# Agent Note: 面向模型的四个工具原语

Status: proposed

本篇关于业务请求/写入意图/事件去重的历史表述已被[删除业务去重决定](2026-10-26-no-business-deduplication.md)取代；其他独立契约继续有效。历史理由保留，不作为当前实现要求。

## Problem

按资源、界面、交互等业务分组不足以定义基础工具；将每个内部方法暴露给模型会扩大工具目录并让模型编排审批和发布细节。用户要求更基础、通用的入口。

## Proposal

用户已确认，尚未实现。当前规范见[工具与资源](../../../../docs/harness/tools-resources.md)。模型入口采用 list/read/write/call，操作受管理引用，不接受任意宿主路径。类型与能力契约按需发现，不一次注入全部 schema；未启用插件只供发现摘要。

write 一次表达完整写入意图，宿主校验、审批、暂存、发布。更新/移除需要预期版本，只允许类型定义操作，不开放任意 JSON Patch 或管理级删除。不可变资源、正式答案和历史保护保留。call 统一调用 Monty/插件能力，不改变权限和执行限制。普通提问说明用正常回复。

四入口不替代内部接口或插件 JSON-RPC，surface.stage/commit 等保留内部契约；已接收/待审批不是成功，失败保留旧状态。具体 schema 和对象目录待定义。

## 查找、读取与写入重试补充

用户确认 list 仅字段筛选及元数据关键词匹配，明示范围，不内置正文检索。read 仅读已有表示，文本/结构化有界、图片按模型支持，其他格式元数据和派生引用，不隐式解析或外发。模型不接收大段无意义二进制/Base64。

用户明确否决沿旧版本续读：版本变化中断当前续读，放弃本轮旧片段，从最新内容重新读取，重读受次数和时间预算限制。版本检查不冻结对象，write 仍检查预期版本，既有不可变引用不静默替换。

write 同主体/任务内按意图标识去重，同标识同参数返回原状态/结果，不重复执行/审批；异参数拒绝，修改内容/版本需新标识，旧终态不复活。当前权限仍检查，具体字段与参数一致性规则待定义。本补充沿用原四原语决定，原地更新。

## call 最小契约补充

用户否决调用意图去重，确认每次 call 由宿主登记并持久化唯一 ID，再审批/调度；相同参数也属不同调用。ID 管理状态、结果、取消和父子关系，不是去重键，查询用 read，未知结果不自动新建调用。write 去重及插件动作接收去重不变。

模型侧默认等待终态及有界结果，由宿主管理审批和等待，不要求主模型轮询；界面可以提前显示进度，插件 RPC 异步机制保留。不提供脱离来源执行的后台模式。一次 call 一个能力，能力自身可批量输入，但入口不提供步骤、条件、循环或跨能力事务。具体 schema 尚未确定。

本补充细化已有四原语决定，不将先前未获认可的 call 去重建议写为基线。

## 模型工具序列补充

用户确认同一 Run 按模型返回顺序串行执行工具请求，每项派发前复核权限、版本、状态与预算。审批等待暂停，不越过；前序未成功停止本批剩余项，明确记为前序失败导致未执行。有效来源有预算才交还模型重判，不自动重试整批；来源取消/超时/撤权不再推理。

多项请求不是事务，已提交成果保留，单项界面原子性不变。不影响跨任务并行、控制消息、本地交互及插件父工具对子失败的处理。该补充原地细化四原语的模型 loop 契约，未引入批处理工具。

## 参数错误与结果交付补充

2026-10-26 用户确认：参数错误不执行，结构化返回类别/位置/原因和修正提示，不猜测修复、替换能力或放宽约束，契约默认值除外。版本冲突重读不覆盖，权限反馈不提供绕过路径。模型显式修正且受预算限制，write 改参数新意图，call 重发新 ID。

小结果有界返回，大结果按权限保存资源后返回状态/引用/截断预览，不隐式模型摘要或改写。状态、错误和必要引用不被截断。接收/保存失败与执行事实分开，未知效果保持未知，不推断未执行、不自动重跑或回滚副作用，不提供有效半成品引用。本补充沿用既有原语与资源契约，原地细化。

## 通用任务数据补充

用户确认以通用带 schema 对象承载领域状态，经 list/read/write 管理，不另建记忆工具。结构化内容带来源，大内容引用资源。插件可声明 schema，无合适定义时 agent 可提供对象局部 schema；限制大小/复杂度，禁止远程引用和自定义校验代码，不注册宿主能力或授权。创建后 schema 固定，改变结构新建对象，不隐式迁移。

更新/移除校验权限和版本。默认仅当前值和必要审计，不保留完整修改史；正式作答/已发布界面等历史证据保存不可变快照或资源版本，不能仅依赖可变对象。无法解除引用时拒绝移除。保存不触发执行、不证明事实，不是秘密存储或宿主状态写入口。本补充落实原有业务状态为受管理对象，不改变四原语接口。

## 单对象写入与快照补充

用户确认普通 write 单对象，不引入通用跨对象事务，保留界面多 View 及答案/事件的既有原子保证。两次写入分别报告，不自动回滚、补偿或重试。

提交方明确声明采用的数据对象和预期版本，由宿主提交时校验并固化所需不可变快照、绑定新内容或记录；版本变化拒绝并要求重读，不静默改用新值，不复制整个任务状态或修改源对象。快照为内部产物，不增加模型工具，源对象后续变化不改历史。引用保留/回收沿用既有规则，不证明业务真实性。

## Surface、引用与结果时序

用户已整批确认：模型界面 write 唯一顶层目标为 Surface，View 是操作目标，局部变更无需重传整页，多 View 原子发布及保守版本检查保持。引用采用显式结构，普通 ID 字符串不产生权限或保留效果，HTML/CSS 资源由受控格式解析。

可变任务数据引用带预期版本，不自动跟随或展开，不因此保存旧版全文。当前引用阻止目标移除（含过时引用），先显式解除再移除，不级联处理。历史快照独立于源对象，继续保护其资源。循环引用允许，不自动递归读取、更新或复制；快照只固化明确声明对象/版本，任务删除不要求用户手动解环。

模型 write 等待终态，界面即时显示动作与审批进度，内部/插件异步接口保留。此处明确此前“待审批返回引用”的接口层次，不让主模型轮询或提前继续推理。生命周期、执行事实和结果交付分开记录，执行成功但交付失败停止后续工具，不自动重跑。字段和编码尚未确定，不将示例作为最终 schema。

## Call 派发与收尾

用户整批确认：Call 分已登记、等待中、执行中、收尾中、已结束，独立记录执行/交付事实。宿主完整发送即派发完成，不强制接收握手、不证明插件已读或执行；明确未发送与派发未知分开，发送后丢结果保留派发事实，不自动重发。

终态后来源可验证的迟到报告只补充事实及来源/时间，不覆盖原记录、不复活调用或发布产物，自报 ID 不足以认领，不保留失效连接等待。结果完成宿主接收校验和必要保存、可读即已交付，不等消费方读取，发送失败另记、不重跑。实例名额保持到 Call 收尾完成，控制消息及其他实例持续处理，不因发送失败等待重连。

本补充细化既有调用唯一 ID、结果分层和取消边界，字段与真实传输/故障测试未实现。

## 2026-10-26 契约细化

对象目录与四工具字段已有 schema 草案；显式 references 与业务内容分开，局部 schema 只开放基础类型/范围。小界面可内联，大内容引用同结构 bundle。文本按行及不透明游标读取；list 实时弱一致分页而非长期快照。无 ID 的失联请求查询近期操作，不按内容自动认领。权衡：引用声明更明确但有额外字段，弱一致分页更轻但可能遗漏或重复，查询不能证明未知操作未执行。

共同制品见[核心实现契约](../../../../docs/contracts/README.md)。本次是既有决定的细化，仍为 proposed，不宣称运行时已实现；结构校验与真实行为验证分开。

## Alternatives considered

- 按学习业务分工具：直观但不够基础，用户明确要求更底层原语。
- 通用文件路径读写：编码风格熟悉，但不匹配宿主管理资源与权限边界，采用对象引用。
- 模型手动 stage/commit：灵活但增加调用与错误编排，宿主承担完整提交流程。
- 独立 delete/发现工具：职责清晰但可由受类型约束的 write 和 list/read 表达，不新增入口。
- 一次注入全部 schema：减少查阅但插件增多会膨胀上下文，按需加载。

- 内置通用正文/语义检索：定位更强，但扩大基础设施范围，首版留给扩展能力。
- read 自动解析非文本：操作便捷，但可能隐式产生费用和外发，读取与 call 处理分开。
- 绑定旧版本继续读取：能保持单版本完整，但用户要求变化后以最新内容为准，采用中断重读并限制预算。
- 重试即重新写入：逻辑简单，但返回中断可导致重复成果，复用动作意图去重。

- call 按意图去重：可减少重复副作用，但用户要求每次调用唯一 ID 分别管理，明确不采用；不自动重跑未知结果的保护保留。
- call 立即返回并要求模型轮询：接口异步统一，但增加 loop 和查询成本，宿主默认等待，插件控制仍异步。
- 通用批处理/流程参数：可减少调用但引入编排机制，首版只调用单能力。

- 同一响应工具自动并行：独立操作更快，但增加读写竞态和调度复杂度，首版按返回顺序串行。
- 前序失败仍继续后项：可完成独立工作，但宿主不能可靠判断业务依赖，停止剩余项交还模型重新判断。

- 猜测性参数修复：降低模型重试次数，但可能改变目标与意图，采用结构化反馈后显式修正。
- 自动总结大结果：可缩短上下文，但增加隐藏成本及信息损失，改为资源引用和明确截断预览。
- 保存失败按未执行重试：表面易恢复，但可能重复已发生副作用，分开记录执行与结果交付。

- 仅插件可提供数据 schema：控制更集中，但无插件任务无法保存局部结构化成果，允许受限对象局部定义。
- 模型自由注册对象类型/能力：表达力强，但扩大权限与动态注册面，局部 schema 只约束数据。
- 保留所有业务数据完整修改史：追溯方便，但增加存储/回放负担，当前值加必要审计，正式证据显式快照。

- 通用跨对象事务：原子组合灵活，但扩大基础 write 和业务补偿复杂度，首版保留特定原子操作。
- 模型手动复制快照再引用：流程显式，但易漏且增加调用，改为明确声明对象/版本后由宿主提交时固化。

- 独立 Surface/View 双写入口：直接操作单元方便，但增加重复契约，统一 Surface 目标承载局部操作。
- 普通字符串隐式识别引用：内容书写自由，但无法可靠鉴权/回收，采用显式引用与受控资产格式。
- 自动跟随最新对象及递归展开：读取便利，但数据依据悄然变化且扩大执行范围，要求版本和显式读取。
- 自动级联删除或改写引用方：清理方便，但隐含修改其他对象，拒绝删除并要求先解除关系。
- 强制无环：遍历简单，但限制合理业务关联，允许循环而不提供自动递归处理。
- write 待审批即作为模型工具结果：接口表面统一，但可能提前推理或轮询，异步状态仅供界面/内部/插件，模型等终态。
- 单一成功/失败字段：消费简单，但混淆执行效果与产物交付，分别记录事实。

- 发送异常按未执行重试：恢复方便，但可能重复已发生效果，未知事实保留且不重发。
- 强制接收确认握手：能提供额外接收证据，但增加协议且不能保证恰好一次，首版不强制，宿主发送事实与执行事实分开。
- 迟到成功改写终态或恢复执行：可找回成果，但破坏已确定结束边界，只追加来源可信的事实。
- 消费方确认才算交付：语义贴近收到，但把调用绑定后续模型/连接，改以宿主可读结果为准。
- 返回结果即释放实例：吞吐更好，但增加上次收尾与下次调用并发关系，首版名额保持到收尾结束。

## 历史审计

[最小 Harness](2026-10-25-minimal-local-harness.md) 部分重叠，基础职责仍保留，业务分组不再等于模型工具清单。[任务界面](2026-10-24-task-surface-contract.md) 的阶段发布继续内部适用，不要求模型手动编排。[插件启用](2026-10-25-plugin-enablement.md) 的摘要/正文边界保留。本篇细化模型入口，不吸收其他架构理由，无需归档。

## Acceptance criteria

- 模型仅四入口，引用每次鉴权，类型/schema 自报不扩权。
- 契约按需读取，未启用插件正文不可见，call 遵守调用链及授权。
- write 失败保留旧状态，待审批可查询，不自动合并或覆盖不可变数据。
- 不开放管理级删除或通用 JSON Patch，内部校验与插件协议不被绕过。
- 文档校验通过；真实模型适配与类型校验尚待实施。

- 元数据匹配不冒充全文结论，read 不隐式解析，图片不支持须提示。
- 变更后重读不混读且有预算上限；重复 write 不创建新动作，参数冲突拒绝，旧状态不复活。

- call 相同参数两次产生不同宿主 ID，不复用结果；read 查状态不执行，未知结果不重跑。
- 等待由宿主承担，插件控制响应正常，无脱离来源执行或通用流程参数，write 去重保持。

- 审批等待不越过，前序失败后剩余未派发；来源终止不再推理，成功成果不回滚。
- 每项前重新校验，跨任务和控制响应可用；实际 adapter 与序列竞态测试待实现。

- 参数错误不执行且结构化反馈，声明默认值不与猜测修复混淆；大结果有界且状态不丢失。
- 超限/保存失败不伪报未执行或自动重跑，无隐式摘要调用，真实故障测试待实现。

- 局部 schema 不远程取数或执行代码，不注册权限，创建后固定；更新/移除版本鉴权有效。
- 当前值修改不影响历史证据，引用不可解除拒绝移除，保存不触发执行；实际 schema/事务测试待实现。

- 多次 write 不自动回滚，已有特定原子保证保留；数据版本不符拒绝提交，快照不改源对象。
- 历史快照不随源对象更新/移除变化，引用保护和提交竞态待实现验证。

- Surface 局部写不重传整页，多 View 原子和版本检查有效；显式引用与普通文本严格区分。
- 旧版本引用冲突、不隐式保留全文；当前引用阻止删除，独立快照不阻止源移除但保护资源。
- 循环可表达但无递归副作用，快照仅覆盖明确对象；删除/回收竞态待实现验证。
- write 待审批不向模型提前交付结果，插件异步响应正常；执行事实与交付失败分别记录，不自动重跑。

- 五阶段不混淆执行/交付，发送未知不重发，无强制接收握手也能接入。
- 可验证迟到报告只追加事实，不能复活或发布产物；无来源证明不得认领。
- 结果可读即交付，发送失败不覆盖保存事实；慢保存和异常收尾不提前释放实例，控制消息可用。
- 实际传输、取消与存储故障验收尚未运行。

## Risks

四个入口不意味着参数简单；类型目录、嵌套 schema 与错误返回仍需明确。通用 call 不降低服务端校验要求，不把工具数量减少等同于 token 成本已经降低。

持续变化可能使读取无法完成；要求模型放弃旧片段不等于从所有历史上下文中物理删除，宿主须提供明确失效反馈，实际模型行为与竞态仍需验证。

call 不去重意味着误重复调用可能重复执行并产生费用/副作用；唯一 ID 仅用于管理，不证明外部恰好执行一次。登记与返回中断的实际恢复体验仍需测试。

局部 schema 的安全子集、引用追踪和提交时快照的具体事务实现仍需细化；结构校验不能证明业务数据真实或推断正确。

循环和过时引用可能增加显式维护成本；单对象写不能保证整条关联链同步更新。快照未纳入的关联对象不获得历史保留保证，不能把循环可表达误解为整个关联图永久一致。

大结果保存期间占用实例会降低同实例吞吐；宿主完整发送不能证明远端执行，派发未知须明确展示。迟到补充不是自动对账服务，也不保证一定取得最终执行事实。
