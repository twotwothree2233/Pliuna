# Agent Note: 可信插件分层访问与任务内容归属

Status: proposed

本篇关于业务请求/写入意图/事件去重的历史表述已被[删除业务去重决定](2026-10-26-no-business-deduplication.md)取代；其他独立契约继续有效。历史理由保留，不作为当前实现要求。

## Problem

旧方案把 Monty 的限制扩大成统一插件沙箱，并用插件实例所有权/私有读取状态解释单主 agent 的产物，造成权限来源与任务归属混淆。用户已明确插件自行运行代码，需按任务级/全局级开放只读查询，修改统一审批。

## Proposal

本轮已确认但尚未实现，故保留 proposed。当前规范见 [插件接入](../../../../docs/harness/plugin-integration.md)、[安全审批](../../../../docs/harness/security-approval.md) 和 [运行时](../../../../docs/harness/runtime.md)。

内容归任务，来源只追踪；主 agent 的 Run 执行范围由宿主建立，加载知识不增加权限。插件注册级别独立控制基础读取：任务级读所属任务全部业务数据，全局级跨任务，均排除宿主秘密，不逐次审批。任务级动作不能跨任务，全局级动作一次一个任务。

可信插件通过本地子进程、双向 JSON-RPC 2.0 over stdio 接入，不由 harness 提供 OS 沙箱。静态注册、人工信任确认、启动握手；全局启用和升级不可模型代批。任务级按任务、全局级按应用复用进程；取消宽限后可终止直接管理进程，不保证回滚或清理后代进程。

Task 与 Run 分开，每任务最多一个未结束 Run。插件动作可以无 Run，待审批独立保存，不占写队列或通信通道，通过后排队复核。工具派发前授权，返回修改提案再检查；审批模型不代办用户意图。Monty 单次受限运行规则保持不变。

## 固定副本与环境职责补充

用户已确认：安装仅静态校验并复制为应用管理的固定版本副本，保存包内摘要和声明配置，不运行安装脚本。静态内容及包内入口从副本加载，原目录变化不影响已安装内容，不提供热加载。更新显式重新导入并遵守占用限制，代码或启动声明变化重新确认。副本文件或声明配置不符，拒绝按旧批准启动/加载，要求重新导入，不静默接受。

用户明确否决管理外部环境：harness 不固定外部解释器路径、不检查其摘要、不扫描第三方依赖，也不因外部环境变化重新确认。环境缺失/启动失败仅报告，不自动修复。插件间声明依赖检查保留，但不是外部运行环境完整性证明；不承诺 OS 不可变、运行中防篡改或跨环境一致性。

本补充收窄原先尚未定案的变更检测范围，沿用本篇可信本地代码边界，不另立重复记录。

## 默认授权与可信声明

用户整批确认：普通请求及 View 事件创建的 Run 可读本任务业务数据并新增任务数据/View，不默认改已有内容或布局。本 Run 新建且未受用户/他方改动的内容可继续完善，每次检查版本；用户输入/作答或他方改动后重新判断，不包含移除，Run 结束失效。View 事件只提供上下文，不授予原单元修改权。一次批准仅当前动作，可含明确多 View 操作，不产生长期/通配许可，assisted 同样不能扩权。

用户明确拒绝要求 harness 证明插件真的只读：已获信任启用的插件只读声明可信，合法范围调用默认免逐次审批，不审查代码或自行 OS 行为，风险由用户承担。接口身份/范围/参数/配额/生命周期与业务修改授权保持。Monty 计算及有界输出保存默认允许，限制和正式启用门槛不变。

获准调用正常结果资源化无需另批，由宿主确定归属/位置并校验、保存；修改提案另行授权，不能通过结果执行。此规则避免大结果仅因大小变化新增审批，亦不授予插件独立任意资源写权。具体 schema 与状态关联未实现。

## 调用、动作与审批记录细化

用户整批确认：Call 始终登记，默认允许记录依据而不建空 Action；需审批才关联调用授权 Action，批准后继续原 Call。调用授权 Action 成功派发即完成，Call 单独记录执行结果；修改 Action 以提交完成，可无 Call，结果修改提案不复用派发批准。

每个 Action 最多一条独立 Approval，默认授权覆盖可无审批。决定、有效性、处理方式分开，后续撤权不抹去批准事实。转人工保留原记录/期限；deny 结束审批，仅 escalate 或评估失败转人工，用户不同意可明确新请求手动审批，不复活旧记录。

期限检查点是调用最终派发或修改最终提交，排队/暂存不延长许可；合法派发后自然到期不单独终止工具，调用时限、来源总墙钟、取消/撤权保持。已完成 Action 不提前结束 Call/Run 或释放其占用。具体 schema 与竞态验证尚未实现。

## 2026-10-26 契约细化

协议错误与已受理业务结果分层；不可恢复帧污染关闭连接，已派发事实不改写、不重放。上传顺序有界，暂存准备不产生业务修改权。Action四阶段与审批绑定已补齐，不增强插件OS沙箱或审查实际只读行为。

共同制品见[核心实现契约](../../../../docs/contracts/README.md)。本次是既有决定的细化，仍为 proposed，不宣称运行时已实现；结构校验与真实行为验证分开。

## Alternatives considered

- 插件拥有 View 和私有业务状态：来源清晰，但共同创作、停用和单主 agent 身份复杂，改为任务归属与范围授权；命名空间只组织数据。
- 任意插件统一受控沙箱或仅允许 Monty：可约束执行，但限制插件语言与依赖，不符合用户明确要求。选择信任本地代码并准确限定接口保护承诺。
- 插件只被动返回结果：协议简单，但无法主动查询上下文或在无 Run 时申请动作，采用双向查询和异步动作申请。
- 每次调用新建插件进程：无状态简单，但浪费初始化；按级别复用并明确取消导致的状态丢失。Monty 不采用此复用规则。
- 所有审批都冻结任务：串行直观，但阻塞查询和用户操作，改为等待不占队列，执行前版本复核。

- 直接引用源码目录或热加载：迭代方便，但同版本内容可静默变化，首版固定副本并显式更新。
- 固定启动程序路径、摘要并检测外部环境：可发现更多变化，但用户明确不需要由 harness 管理，删除此职责，只校验受管理包。

- 每次完善新增内容都审批：粒度严格但打断渐进生成，采用本 Run 未受他方改动内容的临时资格，不授予永久所有权。
- 单次批准扩展到未来同类操作：减少弹窗，但扩大用户实际确认范围，首版仅具体动作，默认允许规则独立管理。
- View 提交自带来源区域修改权：反馈方便，但作答不等于同意改题，事件仅提供上下文。
- 要求证明插件只读且不外发才免审批：可降低对声明的依赖，但用户明确要求充分信任插件，不承担代码/OS 防御职责。
- 大结果落盘另行审批：将存储视为单独写入较统一，但使同调用因结果大小产生不同审批，正常产物保存纳入调用，修改提案仍独立授权。

- 每 Call 必建 Action：关联统一，但默认允许路径多空记录，按需建立，始终保留 Call 授权依据。
- 调用授权 Action 跟随工具到结束：容易展示总体结果，但重复 Call 职责，派发完成与工具结果分开。
- 同 Action 反复审批或转人工刷新期限：交互方便，但覆盖旧决定或无限延长，单条审批且失效后显式新请求。
- 单状态混合批准和失效：存储简单，但抹去历史决定，决定/有效性/处理方式分别记录。
- 模型 deny 自动再问人工：可能挽救误拒绝，但使拒绝语义模糊，仅升级/评估失败转人工。
- 审批自然到期终止运行中工具：限制直观，但混成第二套执行超时，期限约束准入，执行另受预算/取消管理。

## Acceptance criteria

- 当前协议不再要求插件拥有 View、同任务业务数据私有或全部插件进入 Monty/统一沙箱。
- 注册级别、人工信任和查询免逐次审批明确；宿主秘密排除，越级动作拒绝。
- JSON-RPC 与业务去重分开，回调查询/取消不被串行工具调用堵塞。
- Run 暂停与任务可继续交互并存；独立插件动作不因无关 Run 取消失效。
- 意图确认不能模型代答；修改结果不能继承未包含它的调用批准。
- 当前仅更新文档，schema、存储结构、配额及代码变更检测继续待定。

- 原目录修改不影响固定副本；已安装包文件/声明配置不符拒绝旧批准启动/加载，更新遵守占用与信任。
- 外部环境变化不触发 harness 检测或重新确认，启动失败报错但不修复；真实文件系统校验仍待实现。

- 默认读/新增不跨任务或改旧内容，临时完善资格按版本/用户交互/来源检查且随 Run 结束失效。
- View 事件无隐含改题权，单次批准不产生未来许可；只读声明被信任但接口越界仍拒绝。
- Monty/正常结果免额外审批，失效产物不发布，结果修改提案不自动执行；真实权限与并发测试待实现。

- Call 默认允许无空 Action，获批不新增 Call，派发 Action 与执行结果/修改提交分别记录。
- 每 Action 最多一审批，转人工不延时，deny 不自动复问，迟到批准不覆盖历史。
- 排队/暂存到期不执行，合法派发后自然到期不独立终止，取消/撤权依旧有效；实际竞态测试待实现。

## Risks

可信本地插件可能绕过接口读取或外传数据，撤销无法收回副本；这是真实信任代价而非已解决的隔离。全局进程被终止会影响多个任务。授权异步排队需要严格版本复核。确认代码变化的技术机制尚未定义，不能仅凭 manifest 摘要承诺依赖完整性。
