## 1. 范围与原则

本文使用 MUST（必须）、MUST NOT（禁止）、SHOULD（建议）、MAY（可选）表达约束强度。

已确定的产品约束：

- 主形态是持续连接 agent 的任务前端界面；独立材料是可选导出结果。
- 每个任务可以具有不同的界面，并可渐进式生成、交互和更新。
- “画布、画笔”仅为抽象比喻，不要求 HTML Canvas、坐标系统、绘图编辑器或固定教学组件。
- Harness 提供运行设施、基础工具、呈现能力与校验；插件决定领域内容和任务流程。
- 插件可以贡献不同种类的能力，不要求插件类别互斥。
- 插件通过 harness 接口修改任务界面、状态或资源必须经过授权；本地插件的 OS 行为不属于统一沙箱保证。

单用户本地 Electron、单主 agent、流程说明而非工作流引擎、统一 DOM 优先及两种审批模式已确认。下文具体字段、提交机制、配额和隔离 profile 仍是推荐规则。当前只开发 harness 与测试夹具，不开发实际插件。

非目标：通用教学法、完整前端框架、插件市场、分布式工作流、多 agent 同时写任务状态、任意代码安全性的静态证明。

## 2. 运行角色与信任

| 角色 | 权责 |
| --- | --- |
| Harness | 认证调用者、分配身份、授权、持久化、工具执行、界面发布与故障隔离 |
| Agent | 按当前插件上下文提出工具调用与界面修改，不自行授予权限 |
| 插件实例 | 提供能力和领域方法，以任务级或全局级注册身份访问业务资源 |
| 呈现执行环境 | 执行已发布的交互界面，不能持有模型密钥或宿主凭据 |
| 用户 | 提交输入、授权敏感操作、取消或恢复任务 |

插件包在人工信任确认前不得执行；启动后的后端代码属于用户信任的本地代码，不承诺 OS 隔离。所有协议消息、模型输出、材料、工具结果和浏览器事件仍必须校验。Harness MUST 在自身接口执行点强制约束，不得只靠提示词保证权限。

身份与权限绑定到宿主建立的执行上下文，MUST NOT 信任请求 JSON 自报的 plugin_instance_id。纯 skill 没有自己的运行权限；agent 使用 skill 后的操作仍属于当前执行主体。

无插件任务由宿主创建 task-agent 主体，不因此获得全部插件权限。

## 3. 共同数据约定

- 消息采用 UTF-8 JSON；时间为 UTC RFC 3339；schema 使用 JSON Schema 2020-12。
- ID 是宿主生成的不透明字符串，不得以拼接文件路径或猜测 ID 的方式获得访问权。
- 能力名称格式为 `publisher.plugin/local-name`；插件版本使用 SemVer。
- v0.1 的 protocol_version 精确匹配 `0.1`，不推断跨版本兼容；未来通过显式协商扩展。
- 安装后使用受管理的固定版本副本，记录包内容摘要及依赖声明；运行中的任务不自动升级。不固定或验证外部解释器、第三方库和运行环境版本。
- 未声明字段默认拒绝；扩展字段只允许出现在明确声明的 `extensions` 对象中。
- 所有请求大小、资源体积、执行时长和事件频率必须有有限上限；具体上限由宿主协商返回。
- 敏感状态与浏览器可见状态分开；评分密钥、私有答案、凭据不得自动下发。

插件传输 MUST 使用双向 JSON-RPC 2.0，经 stdin/stdout 每行一条完整 UTF-8 JSON 消息；stdout 只传协议，stderr 为有界日志。JSON-RPC id 用于响应关联，不是持久化操作去重键。没有 id 的通知不得用于需要确认接收的修改申请。此约定不意味着 MCP 支持，也不要求内部模块调用使用相同传输。

请求示例（方法名与字段仍待 schema 固化）：

```json
{"jsonrpc":"2.0","id":"plugin:1","method":"actions.submit","params":{"task_id":"task_01","action":{"type":"surface.commit","draft_id":"draft_01"}}}
```

```json
{"jsonrpc":"2.0","id":"plugin:1","result":{"action_id":"action_01","status":"awaiting_approval"}}
```

```json
{"jsonrpc":"2.0","method":"actions.changed","params":{"action_id":"action_01","status":"succeeded"}}
```

每次动作申请由宿主登记新 action_id，不提供客户端幂等键或同参数结果复用。JSON-RPC id 仅关联消息响应，不用于业务去重；协议错误使用 JSON-RPC error，业务错误映射待 schema 化。

查询、响应、取消和关闭消息 MUST 独立处理，不被工具调用或审批等待阻塞。消息大小、日志和查询频率必须有限；大资源通过受控读取，不使用无界消息。身份和级别来自认证连接，不来自消息自报。

## 4. 插件包与能力发现

插件包包含 manifest、其引用的文件、内容摘要；不得含逃逸包根目录的路径或符号链接。入口是包内相对路径，不是安装时下载或执行任意脚本的指令。

manifest 示例：

```json
{
  "id": "example.math",
  "version": "0.1.0",
  "protocol_version": "0.1",
  "access_level": "task",
  "requires": {
    "capabilities": ["core.surface/stage", "core.surface/commit"],
    "render_profiles": ["web-sandbox-v1"]
  },
  "contributes": [
    {"id": "tutor", "kind": "workflow", "entry": "workflows/tutor.md"},
    {"id": "explain", "kind": "skill", "entry": "skills/explain.md"},
    {"id": "plot", "kind": "presentation", "entry": "presentation/plot.json"}
  ],
  "permissions": {
    "required": ["surface.modify", "state.modify"],
    "optional": ["compute.sandbox"]
  }
}
```

kind 可为 workflow、skill、tool、presentation、resource、evaluation。一个包可以混合贡献；没有界面需求的工具插件不必创建 View。未知 kind 必须拒绝安装，不能静默忽略必需能力。

每个贡献项的描述文件 MUST 提供用途、适用条件、依赖；可调用能力还必须提供输入/输出 schema、错误、权限、副作用等级和示例。副作用等级为 read、task-write、external-write。

技能正文可以是 Markdown；其发现元数据由描述文件或 manifest 的贡献项提供。Workflow 的具体描述见第 10 节。Presentation 能力还必须声明支持的 render profile、浏览器状态 schema、事件 schema 及可用的导出表示。

注册只读取静态 manifest，显式声明 task/global 级别；可执行入口还声明命令、参数与依赖要求。人工信任确认前不得启动进程或执行安装脚本。全局启用与任务级升级必须人工确认，不能模型代批；代码或启动配置更新重新确认。握手不能扩大声明范围。具体入口字段和变更检测待 schema 化。

安装过程 MUST 检查名称唯一性、文件摘要、schema、依赖循环和必需能力。缺少必需项时拒绝激活相应依赖能力，插件整体必需项缺失则不能绕过；缺少可选能力时仅禁用相应功能并明确报告。混合包可保留依赖满足且独立于不可用执行部分的静态内容能力，必须显示局部不可用。权限声明是申请，不是授权。

能力目录 MUST 支持按用途检索静态摘要；未启用插件仅供发现和建议启用，用户启用后才允许按需读取其完整描述与正文。上下文不一次加载全部正文。发现不代表激活，激活不代表授权。插件内容不得覆盖宿主安全规则。

任务记录主 workflow 与插件实例。v0.1 每个任务至多激活一个主 workflow；其他 workflow 不自动叠加。无 workflow 时只提供通用 agent 运行，不偷偷加入教学步骤。

## 5. 任务界面与所有权

Task Surface 是一个任务的界面模型，不等于单个 HTML 文件。它包含：

- surface_revision：每次成功发布单调递增。
- slots：宿主管理的挂载位置及其布局约束。
- views：归任务所有、具有独立修改授权的呈现单元。
- composition：View 之间的顺序、分组、相对布局关系。

View 记录 task_id、view_id、view_revision、bundle_ref、state_schema_ref、event_bindings 和可选来源 provenance/export_ref。所有呈现单元归任务所有；来源记录不授予权限，不再使用 owner_instance_id 表示插件拥有内容。

宿主授予执行方限定目标和动作的修改权限，包括呈现、状态与布局。读取插件知识不改变主体，不合并权限。主 agent 的执行范围由请求来源和授权建立；内容归任务不意味着主 agent 可以覆盖全部区域。

插件读取遵循注册级别：task 读取所属任务全部业务资源，global 跨任务读取，无需逐次审批，不受单 Run 临时范围限制。命名空间可用于组织数据，但不是同范围插件间私有读取屏障。凭据、授权凭证、宿主内存和模型私有推理链永不作为业务查询资源开放。

插件修改 MUST 通过统一动作与审批入口；task 只能申请所属任务，global 每次明确一个目标任务。审批不能提升级别，也不支持跨任务原子修改。布局权单独检查，不允许靠布局覆盖宿主或未授权区域。

插件停用撤销其接口和动作权限，任务内容继续保存，不发生所有权转移。重新执行依赖该插件的功能需要有效实例，历史可保留只读或静态表示。

## 6. 绘制与发布接口

“绘制”指构建前端界面，不是像素绘图。核心接口保持少量高层操作：

| 方法 | 契约 |
| --- | --- |
| surface.inspect | 返回读取范围内的界面摘要、版本和挂载位置，不暴露宿主秘密 |
| surface.stage | 提交一批局部修改，产生不可变 draft_id 和检查报告，不改变当前界面 |
| surface.commit | 重新检查版本与权限后，原子发布一个草稿 |
| surface.discard | 丢弃未发布草稿；重复丢弃无副作用 |
| surface.operation.get | 查询提交结果，处理超时后的结果不确定性 |

呈现工具可以产生可直接提交的 bundle 或变更集，避免每个 DOM 元素消耗一次模型调用。基础层不要求插件使用题目、讲解等固定组件。

stage 示例：

```json
{
  "base_surface_revision": 12,
  "operations": [
    {
      "op": "view.replace",
      "view_id": "view_graph",
      "expected_view_revision": 3,
      "bundle_ref": "resource_bundle_02",
      "state_transition": {"mode": "preserve", "expected_state_revision": 8, "compatibility_version": "answer-v1"}
    }
  ]
}
```

v0.1 操作只有 view.create、view.replace、view.remove、layout.set，替换是整个呈现单元，不开放任意 DOM 节点编辑。本地即时交互不逐次发布新内容版本。Create 由宿主分配 ID，并返回草稿内临时引用到正式 ID 的映射。布局只能引用已存在或本草稿创建的 View，必须满足 slot 约束且不得形成循环。

发布过程 MUST：

1. 认证主体，校验 schema、操作目标、资源访问和当前配额。
2. 校验目标任务范围、动作授权和布局权限。
3. 检查 bundle、依赖、事件绑定、状态兼容及渲染 profile。
4. 在无真实副作用的预览环境启动检查；不得触发真实提交事件或外部写操作。
5. 在提交时再次检查权限、任务状态、所有相关版本和已检查 bundle 的摘要。
6. 经统一动作入口获得授权并进入任务写入队列后，原子更新界面模型及其绑定状态，记录提交事件。待审批不持有写锁；排队后必须再次复核。

任一步失败 MUST 保留旧界面。这里的原子性指宿主持久化模型，不承诺所有浏览器在同一时刻完成像素切换。客户端按 surface_revision 应用快照，失败时请求重同步。

草稿绑定提交主体、任务、基础版本、内容摘要和到期时间；到期或权限撤销后不得发布。已提交草稿不得再次发布，重复提交该草稿应拒绝；查询原动作可获取提交事实，不以再次提交代替查询。

v0.1 使用任务级界面版本比较，允许不相关 View 的同时修改发生保守冲突；不做自动合并。版本冲突返回最新摘要，由调用者重新读取和生成修改。

替换 View 时，state_transition 必须为 preserve 或 reset。Preserve 要求同一单元、相同状态 schema 摘要、相同兼容版本标识和匹配的状态版本，并保留已保存值而非新初值；reset 必须提供合法初值且丢弃用户作答或草稿必须由用户确认。兼容标识在换题或字段含义变化时必须更新，schema 无法单独证明语义兼容。v0.1 不执行任意状态迁移代码。浏览器未保存输入期间必须阻止该 View 替换或先完成草稿保存，不允许静默丢弃。

首版不提供任意历史版本回滚或完整历史编辑器。保留已发布版本用于只读查看与解释作答，不重跑旧代码或回放外部副作用。

## 7. 前端执行与隔离

bundle 包含入口文件、资产摘要、render_profile、浏览器可见状态 schema、事件声明及静态表示声明；自定义脚本区域 MUST 提供与内容版本绑定、经校验的静态 HTML/CSS，缺少则拒绝发布。HTML/CSS/JS 是可选的界面实现手段，而不是插件越过宿主权限的通道。

v0.1 定义两个 profile：

- managed-v1：在统一任务 DOM 中受控构建界面，不执行生成的任意脚本。HTML/CSS 必须经过允许列表、作用域和资源检查；交互只提供输入/选择、展开/隐藏、局部状态绑定和受控事件，不建设通用交互语言，也不限定教学模板。
- web-sandbox-v1：允许 bundle 内前端代码，在宿主隔离容器中执行。不得与宿主共享脚本全局、DOM 或可读存储。

宿主 MUST 至少支持 managed-v1；web-sandbox-v1 为显式协商能力，不支持时不得偷偷在宿主页面执行。本文不固定使用哪种前端框架。

Web sandbox 可验证 sandbox iframe 和独立来源/不透明来源策略，具体容器尚未锁定。不以每 View 一个 WebContentsView 为默认实现。禁止同源特权、顶层导航、未授权弹窗和直接外联；资产随包或通过获准本地资源通道提供，不提供任意 URL 代理。Shadow DOM 不能替代安全隔离，View 所有权也不等于浏览器进程隔离。

桥接通道必须绑定实际窗口/通道实例、任务、View 和有效租约；仅验证消息里的 ID 或 origin 不足够，不透明来源的 origin 还可能都是 null。View 被替换、删除、停用时立即关闭旧通道并废止租约。

隔离脚本只能修改容器内部；普通呈现通过受控提交修改本 View，不持有共享 DOM 脚本权限，CSS、URL、布局和行为目标也必须检查。跨 View 更新、宿主存储和工具调用必须走协议。宿主保留加载、失败、暂停和权限提示的控制权，不允许插件伪造宿主授权窗口。

有限 DOM/资产大小、事件频率、计算时长与错误预算必须执行。Iframe 不保证 CPU/内存硬隔离；面向恶意代码的部署必须提供更强的执行隔离或禁用 web-sandbox-v1，不能声称仅凭校验即可完全阻止拒绝服务。

普通呈现使用 HTML、CSS、行为声明与状态声明；行为通过稳定本单元元素标识绑定状态和事件，禁止任意表达式、脚本或全局选择器。状态声明包含结构、初值和兼容版本。一个单元可有多个表单，提交明确表单和字段集合，不能默认提交全单元状态；字段细节待 schema 化。

## 8. 交互事件契约

本地交互在 View 内处理；保存状态和请求 agent 通过宿主桥接。不是每次点击都调用模型。

事件声明 MUST 包含名称、payload schema、delivery（state-only 或 agent）、过期策略（reject 或 record-only）。过期策略由发布时注册，客户端不能修改。

浏览器提交：

```json
{
  "client_event_id": "evt_client_01",
  "view_revision": 4,
  "type": "answer.submitted",
  "payload": {"answer": "我认为变化来自斜率。"}
}
```

Harness 从认证通道补齐 task_id、view_id、actor_id 和适用时的 plugin_instance_id，并产生 event_id、task_sequence、received_at 和处理状态。任何客户端自报身份不得覆盖这些值。

- 每次有效的新事件提交由宿主分配新 event_id；客户端关联 ID 不作为去重键，不按相同内容合并事件。
- 只有事件持久化后才回复 accepted。Accepted 不表示 agent 已处理完成。
- 状态依次为 accepted、queued、processing，再到 succeeded、failed 或 cancelled；state-only 可以直接从 accepted 到 succeeded。
- v0.1 按宿主 task_sequence 串行处理同任务的 agent 事件；顺序是接收顺序，不声称等同于用户实际操作时间。
- 旧 View 版本的事件默认 reject；record-only 只能记录证据，不触发当前 workflow 推进。撤销授权或废止租约的通道一律拒绝，不因 record-only 而放行。
- 请求超过频率或队列上限返回 RATE_LIMITED 及 retry_after_ms，不默默丢弃已经确认接收的事件。
- 重连时按 last_task_sequence 补取获准事件；游标已过保留窗口则返回 RESYNC_REQUIRED 和可访问的最新快照。

输入草稿自动合并保存，允许不完整内容，仅校验字段、存储类型与体积，不唤醒 agent。该保存属于用户操作的预先授权，插件/agent 主动改写仍走动作入口。显示保存状态，关闭/替换前保存或由用户确认丢弃；不保证崩溃前每次按键已保存。

提交必须由用户明确触发，宿主重新校验格式、必填和范围，教学正确性另评。失败保留草稿、不产生正式作答事件。答案不可变快照与对应事件 MUST 在同一数据库事务保存，提交后再确认；停止中的或已停止任务仅保存并标明尚未处理，不进入推理队列；其他任务按有效执行状态处理；绑定 View/内容版本、资源版本、表单、字段和提交序号。后续草稿不能改写历史答案；再次明确提交生成新记录，再次发送是新请求，不自动重发或按内容合并。

作答证据 MUST 引用当时内容，不仅指向当前题目。历史查看只读，禁用提交修改，不执行自定义脚本/插件/agent；复杂区域使用保存的静态表示，缺失明确提示，不执行旧代码补齐。

## 9. 状态、资源与工具

状态分为运行状态、任务业务状态、浏览器可见状态和宿主秘密。业务状态中的插件命名空间用于组织与追踪，不对同范围插件构成私有读取屏障；浏览器只接收当前界面必需的可见数据，不因插件全局级身份获得全部数据。

state.read 按注册级别检查；state.compare_and_set 等写操作必须通过动作审批和目标版本检查。学习观察与推断分别保存，推断关联证据；不规定掌握程度算法。

资源通过 resource_id 访问，保留原件与派生表示关系、MIME 类型、摘要和来源定位。解析能力返回支持的页码、时间戳、单元格等定位类型；不能将缺失定位伪造为精确引用。

工具描述必须包含输入/输出 schema、权限、时限、副作用等级以及错误约定。执行结果包含 status、结构化数据或资源引用、truncated 标记；成功、未执行、失败、取消与结果未知必须区分，部分完成不得伪装为全部成功；具体编码待 schema 化。

派发工具调用前检查主体、实际参数和授权，必要时先审批；返回的修改提案另走动作入口。调用批准不覆盖新增目标/参数/权限。可执行插件是用户信任的本地代码，其副作用声明不构成 OS 行为强制约束；不能承诺它只拥有调用方的系统权限。插件主动查询独立按注册级别检查。

外部写工具禁止自动重试，不提供宿主幂等键机制。宿主崩溃后无法判断外部操作结果时返回 OUTCOME_UNKNOWN；不得宣称恰好执行一次。界面提交不与外部写操作组成跨系统原子事务。

内置代码执行 MUST 显式输入、单次运行、无网络和宿主文件访问，不保留执行状态；输出由环境外 tool 校验保存。已确认采用 Monty，原生后端为集成基线，支持受限 Python 子集；完整接入和安全验收尚未完成，正式启用前须通过 [代码执行门槛](harness/code-execution.md)。插件可执行工具自行选择运行环境，通过本地子进程和 JSON-RPC 接入，不导入主进程；这不是统一插件沙箱。Monty 限制不适用于插件自身代码。

## 10. Workflow 与 agent loop

Workflow 是带发现元数据的流程说明，正文可为 Markdown，描述目标、步骤、分支、等待和完成标准。Harness MUST NOT 要求 entry_stage/stages 或执行领域阶段状态机；由主 agent 理解并推进，步骤遵循不由宿主确定性保证。

Harness 只强制管理通用运行状态、权限、schema、预算和工具执行。模型记录的计划和学习判断是可修订数据，不是授权或宿主验证过的事实。

Task 长期保存学习目标、业务资源和界面。Run 处理一次用户请求或推理事件，可包含多轮模型调用；Run 状态为运行中、等待中、已完成、已失败、已取消、已中断，字段编码待定，不是任务教学状态。Task 自身生命周期字段待定。

每任务至多一个未结束 Run，waiting 也占用该名额；新推理请求排队，用户可明确取消旧 Run 后处理新请求。审批等待暂停依赖该结果的 Run；学习提问或意图选择交还用户控制权时结束 Run，回复开启新 Run。

Run 结束/取消不删除 Task 或已提交内容。临时扩权默认随 Run 结束失效；取消使关联待审批请求和迟到结果无效。Run 恢复必须重读可能变化的状态，使用有效租约和版本提交。

插件无活跃 Run 也可主动提出动作，具有独立 action_id，可无 run_id。待审批不占写队列；批准后排队，执行前复核；确定性动作不调用模型，需要推理才申请新 Run。独立插件动作不因无关 Run 取消自动失效。

只读查询、输入保存、本地交互和其他获准动作不因审批等待冻结。模型和工具预算有限，持久化事件先记录再确认，未知外部副作用不自动重放。

## 11. 插件协作与生命周期

首版每任务一个主 agent，插件不默认运行独立 agent，不建设插件间自主协商系统。Skill/workflow 作为数据加载，工具走授权后的执行接口。

插件可主动通过双向协议查询上下文、资源、工具目录/描述和运行状态；只读不得有业务副作用，执行工具不是查询。任务级按“任务 × 插件”建实例，全局级按应用建实例；首版每实例工具调用串行，但通信和控制消息持续处理。

关闭任务页面不停止执行；显式停止任务停止任务级实例，全局实例可继续只读查询但不得修改该任务；停用或应用退出关闭相应进程并撤销访问。进程可复用，重启不承诺恢复内存。插件自己的持久化不受 harness 自动清理保证。

取消/超时先禁止结果提交，发送取消请求；宽限后终止直接管理的进程，下次调用重新启动，不自动重试。不能保证回滚外部效果或清理插件所有后代进程；全局进程被终止可能影响所有任务后续调用。

查询范围内不再设置跨插件业务读取屏障。协作修改仍经动作审批，不直接操作其他呈现单元 DOM。删除任务撤销其访问和动作，清理宿主管理数据，不承诺删除插件此前读取并保存的副本。

详见 [插件接入](harness/plugin-integration.md)。

## 12. 导出

首版唯一正式格式为 static-html：自包含、离线阅读的单文件静态 HTML，无自定义 JavaScript、宿主连接或学习提交入口。保留基本阅读操作，折叠内容展开，资产内嵌而非远程加载；不提供并行的 ZIP/PDF/资源目录导出实现。

导出绑定指定 surface_revision 及选中单元、资源、作答和反馈的版本快照。预览与文件一致，新内容不自动混入；刷新后重新预览并必要时重新确认遗漏。快照不是权限凭证，任务删除或撤权停止未完成导出。

内容及静态表示 MUST 显式分类。默认学习材料，用户明确选择才附带正式作答及对应反馈，绑定当时题目版本。View 可包含分别选择的导出片段；不可拆混合内容整体按个人内容处理，未分类为完整性问题。始终排除草稿、审批、工具日志、内部标识和凭据，不序列化整个任务状态。分类不证明无隐私，必须提供预览与检查提醒。

export_ref 或“不支持”仍为草案表达，片段/分类字段待 schema 化。缺少表示、资源缺失或无法安全转换时默认失败；partial 需用户本人确认，文件内在对应位置标记缺失并附遗漏清单。体积超限提示缩小范围，不静默丢资源或替换远程链接。

导出 MUST NOT 调用模型、插件或工具补齐内容，不执行旧脚本。整理、补全和重写由用户另行发起 Run，单独说明成本与权限，不要求必须由插件提供。

系统保存对话框由用户选择位置；agent 仅建议文件名，插件不能指定宿主写入路径。覆盖文件必须本人确认；临时生成校验后受控发布，失败保留原文件，取消未完成操作清理临时产物，成功后不因迟到取消删除文件。跨平台原子性不作无验证保证。导出副本不随任务更新或删除而撤回。详见 [导出契约](harness/export.md)。

## 13. 标准错误与兼容性

标准错误码：INVALID_ARGUMENT、UNSUPPORTED_PROTOCOL、UNSUPPORTED_CAPABILITY、DEPENDENCY_MISSING、PERMISSION_DENIED、TASK_NOT_FOUND、TASK_CLOSED、REVISION_CONFLICT、DRAFT_EXPIRED、VALIDATION_FAILED、STALE_EVENT、SCHEMA_MISMATCH、RATE_LIMITED、QUOTA_EXCEEDED、CANCELLED、TIMEOUT、OUTCOME_UNKNOWN、RESYNC_REQUIRED、INTERNAL_ERROR。

错误可以附带字段路径和恢复建议，但不得泄漏级别范围外的数据或宿主秘密。retryable 不构成自动重发授权，不覆盖第 40 节的独立提交规则；响应丢失或执行结果未知时不得自动重发业务操作。模型请求的有限重试另遵守第 18 节的中断边界，具体错误字段仍待 schema 化。

可执行插件握手时读取 host.describe，纯内容包由宿主静态校验相同兼容性要求而不启动进程：协议版本、支持的能力、render profiles、配额和 schema 摘要。协商失败必须停止激活；不能自动降级权限检查或执行隔离。

## 16. 审批契约

权限审批支持 manual/assisted，用户意图确认不可模型代办。可执行插件信任、全局级启用/升级必须人工确认；学习回答、目标选择及未明确确认的破坏性操作不能当作普通权限批准自动完成。

Assisted MUST 独立、无工具权限，主 agent 不自批。宿主提供实际请求与必要上下文，输出 approve/deny/escalate，经 schema 校验；错误、超时、不确定转人工。硬禁止和注册范围不能审批放行。

批准绑定动作、任务、主体、参数、权限、必要版本和期限；仅 Run 发起的请求绑定 run_id。待审批独立保存，不占写队列或通信通道；通过后排队再复核。参数变化、撤销、取消或过期使旧批准失效。

工具调用前授权与返回修改提案的检查分开；有效批准仅供其绑定的具体 Action 继续执行，不能复用于新 Action 或推导新增权限。默认允许的依据按第 36 节判断，不来自旧审批的长期授权。权限审批不能限制可信本地插件绕开接口的 OS 行为。详见 [安全与审批](harness/security-approval.md)。


## 17. 存储、资源传输与重启

当前状态是恢复依据，保留必要历史，不做完整事件溯源，不重放历史模型/工具调用。自动恢复已保存界面、草稿和答案；未结束且未确立结束边界的 Run 按中断收尾，已确立边界的保留拟结束状态及首要原因；旧执行临时授权/审批入口失效，完成必要残留清理后进入终态。用户明确继续后创建新 Run 并复核；待处理动作不在启动时自动执行业务操作，未知外部副作用不重试。

导入保存副本，资源版本不可变；修改/重新导入创建新版本，不同步原路径。先校验保存文件，再在数据库事务登记引用，成功后报告完成；失败允许孤立文件，回收必须避开进行中保存。已登记文件缺失/损坏明确报告，不替换历史。

插件产物显式传输，小结果有界返回，大文件受控分块上传。资源创建经统一动作授权，临时内容不等于任务资源；插件返回的路径不自动读取，文件名不控制落盘路径。失败/取消清理临时内容。具体消息与配额待定义。

保留已发布界面及正式答案历史，输入草稿只留最新；未发布呈现草稿可清理。历史只读规则见第 8 节。

任务删除由用户本人确认永久执行，不做回收站。先持久化删除中并撤销接口/Run/动作/上传，停止任务级实例，再清理记录与独占资源，保留其他任务仍引用的资源。中断后继续清理是已确认维护，不是自动恢复 agent；不承诺回收插件/外部副本或安全擦除磁盘。详见 [存储与恢复](harness/storage-recovery.md)。

## 18. 上下文、压缩与模型中断

活动上下文由宿主规则、工作摘要、最近完整交互和按需读取原记录组成。摘要 MUST NOT 作为授权、用户确认或权威业务记录；压缩不删除原记录。请求前核算全部输入与输出/误差预留，依次按需装载、确定性缩减、必要时同步压缩。首版无并行后台压缩，不切割尚未结束的工具交互。

摘要请求独立且无工具权限，默认使用当前主模型，可另行配置满足容量/格式要求的模型；不得静默跨服务降级。成本计入当前 Run。候选先检查结构、长度、当前任务引用、历史范围及请求余量，再替换有效摘要；可纠正错误预算内最多纠正一次，仍失败结束 Run。取消后迟到摘要不得安装，新输入不得被旧快照覆盖。

通用摘要结构由 harness 管理；插件只能提供可选、有界、相关的保留说明，不替换宿主规则、不新增压缩执行 hooks。精确信息另行持久化。摘要增量更新并保留来源，冲突和精确判断回查原记录，不按固定轮数重总结全部历史。

自动整理默认开启，状态和摘要详情可见；手动整理在安全边界执行，无活跃 Run 时创建仅整理 Run，结束后不启动业务动作。纠错走正常输入，无专用摘要编辑器。字段、消息方法、预算及提示词版本尚未固化，详见 [上下文管理](harness/context-management.md)。

模型输出断开保留已提交结果；不派发残缺调用、不自动重试未知执行效果。仅本次请求无任何输出且属暂时性错误时预算内有限自动重试；认证/参数错误直接提示。部分输出后断开标记 Run 中断，用户继续开启新 Run，不重放整轮。详见 [运行时](harness/runtime.md)。

## 19. 输入与解析契约

单独导入只复制、检查、识别基本类型、计算摘要并登记，不自动启动 Run、解析插件或模型调用。已导入 MUST NOT 等同已解析/已发送/已理解。首版入口为一个或多个文件及明确添加为材料的文本；不内置网页抓取、目录递归或压缩包解包，链接不等于网页已获取。

批次逐文件提交，允许部分成功；失败/取消项不能登记为可用资源，取消不删除成功项，重试只针对失败项。附明确请求的附件未全部成功时 MUST 等待用户决定部分继续或补齐，不自动启动不完整请求。批次状态编码与操作关联字段待定义。

解析能力复用工具协议，声明输入、操作、输出与限制，由 agent 按需选择，不默认全部执行；未明确的费用/外发/结果取舍先确认，失败替换不扩大范围。派生资源关联原件确切版本、能力版本、参数与真实定位，明确部分成功/截断/识别失败。重解析新建结果，不覆盖旧结果，不自动升级重解析或缓存替代调用。

大结果保存为资源，直接返回有界状态、引用、定位与预览；正文范围读取明确范围、后续与续读方式，不伪造页码/章节索引。图片按需且仅向支持视觉的模型提供，转换由相应能力完成，不强制建设语义检索。

导入资源默认惰性，受控预览不执行宏/脚本或自动外联；不支持预览不影响已成功保存。用户 HTML 转任务界面仍检查授权、内容及发布规则。具体 schema、预览格式和配额待定，见 [输入处理](harness/input-processing.md)。

## 20. 模型服务、占用与调度

模型配置关联渠道，共享地址/认证/凭据与模型独立能力参数分层管理。优先服务接口查询可用模型并补全元数据，缺失再匹配 models.dev；目录候选不等于账号可用。关键参数缺失/冲突要求局部手动补充，补齐前不启用，不猜测容量。models.dev 公开字段与匹配边界已有[研究](research/models-dev.md)，字段级接入规范与各渠道接口仍待验证。

用户触发测试并启用，合成请求有界、不用任务数据、提示费用；主模型需基本响应/流式/工具能力，审批与压缩按角色检查，不执行真实业务工具。测试不证明全边界或质量。Key 不发往外部目录，记录不含明文凭据。

未结束 Run 及已进入模型调度的独立请求 MUST 占用相关模型和渠道，占用中禁止修改/删除，包括凭据。共享渠道被锁不连带锁定未占用模型的独立参数。所有使用者释放后才可编辑，目录刷新不得绕过。尚未启动的任务请求仅记录选择，不持锁；启动前复核，所选配置变化先由用户确认，默认变化不静默替换选择。

主推理、压缩、辅助审批、连接测试统一受应用级/渠道级请求并发限制和公平排队，等待审批/本地工具不占请求名额但不释放 Run 配置锁。取消排队请求不得再发送，失败不自动切换服务/模型/凭据。

目录刷新只发现差异，用户确认且无占用后才能更新有效配置，手动值不自动覆盖。价格独立刷新供后续估算，不改预算或历史估算。目录不可用不阻断已配置已验证模型。具体字段、限额及测试判定待定，见 [模型服务](harness/model-services.md)。

## 21. 任务停止、恢复与静态兜底

页面可见性 MUST 与执行生命周期分离，切换任务/关闭页面不停止后台执行。显式停止任务不同于取消单个 Run：经统一任务写入协调机制先置为停止中，拒绝新业务执行并废止旧结果提交资格，取消该任务所有未完成 Run、未启动请求、未完成动作及审批（含无 Run 动作）。停止边界前已提交成果保留，未提交修改和迟到业务结果拒绝。

随后取消模型/工具、卸载脚本区域、停止任务级插件；宽限后可终止直接管理的插件进程，不保证撤回外部副作用或停止所有后代进程。全局实例可保留既定只读范围，但不得修改停止中的或已停止任务。宿主管理范围清理完成才进入已停止，异常明确显示，停止中 MUST NOT 恢复。

用户基础阅读、表单输入、草稿保存和明确提交答案仍可进行；正式答案与事件事务保存，但 MUST NOT 触发推理/工具或排入恢复后的执行队列。界面区分已保存和已处理，具体事件/执行状态编码待定义。历史查看仍保持只读，不因这项例外开放历史提交。

自定义脚本区域发布时 MUST 附带版本绑定的最低可读静态 HTML/CSS，缺少则拒绝发布。用于停止、加载失败及历史查看，不要求交互等价或逐帧保存；需要持久化的实验结果显式存入任务数据/内容。静态表示的存在不证明教学语义完整，也不免除导出分类/完整性检查；损坏或缺失不允许运行旧脚本补齐。

打开已停止任务 MUST NOT 自动恢复。用户显式恢复仅重新开放执行，允许有效脚本重新初始化、仍可信且启用的任务级插件按需启动，以及加载当前版本兼容的已保存状态；不恢复旧内存、不自动提交。代码或启动配置变化重新确认信任。恢复本身不创建 Run、不调用模型、不重放旧请求/工具/审批/作答；新用户请求可读取旧记录，新插件动作仍走授权。应用退出后不承诺后台继续，重启不自动续跑。见 [运行时](harness/runtime.md)。

## 22. 插件形态、选择与配置占用

纯内容插件 MAY 仅包含静态 manifest、技能、流程和资源，无后端入口、运行环境或进程握手要求。后端可执行能力才要求代码信任确认、按需启动与握手；混合包不能把执行部分不可用伪装成完整可用，只有依赖满足的独立内容能力可继续提供。前端脚本仍受既有界面隔离规则约束。知识加载不增加权限。

安装 MUST NOT 自动启用插件。新任务默认仅有基础能力，用户在按能力类型分类的界面按插件整体启用；同包可出现于多个分类但共享状态，显示全部能力、级别、本地代码执行及依赖就绪情况。首版不提供任意拆分包内能力开关。Agent MAY 搜索静态摘要并建议，MUST NOT 自行启用或加载未启用插件正文。启用仅使符合依赖条件的能力可用，正文按需读取，不立即启动进程或执行工具。

主 workflow 由用户另选，至多一个；启用插件不自动采用其流程。全局级插件在应用层由用户明确启用并确认范围，任务界面展示真实应用级状态，不逐任务重复批准，也不自动向所有任务注入全部技能和流程。

任务存在未结束 Run（含等待审批）或插件动作/调用时，MUST NOT 新增启用、切换主 workflow、更新或替换其使用版本。全局插件更新/替换等待相关任务全部释放占用。用户停用/撤销信任不受此等待限制，立即拒绝相关后续访问和调用，取消依赖执行并拒绝迟到结果，保存内容保留；主 workflow 所属插件停用后清除选择，不自动替换，全局停用明确提示影响范围。

配置变更不创建 Run、不改写历史，新请求才采用新配置。占用与依赖关联字段仍待 schema 化，不能借紧急停用绕过普通变更限制。见 [插件接入](harness/plugin-integration.md)。

## 23. 插件依赖与有界工具转调

选择插件时，harness MUST 汇总已安装必需依赖及原因，由用户一次确认共同启用；缺失、版本不符或声明依赖循环阻止相关能力启用，不自动安装。全局范围和本地代码执行风险必须显式展示并完成既有确认，不自动启用可选依赖。依赖启用仍遵守配置占用、必需条件和主流程单独选择规则。停用依赖展示受影响能力和任务，使依赖能力不可用并取消相关执行，不自动替换或删除成果。

跨级依赖 MAY 存在，但 MUST NOT 传递访问级别或扩大调用方权限。经 harness 转调绑定真实来源、目标任务和本次授权；全局工具返回、引用或修改的资源按本次范围检查，范围外拒绝，审批不能提升任务级主体。全局插件独立查询/动作按原注册级别处理，不与受委托调用身份混用。检查只覆盖宿主接口及可追踪引用，不保证识别普通文本中混入的越界数据或约束可信插件 OS 行为。

Harness MUST 维护不可由插件伪造或清除的调用链；目标插件实例已在当前链中时直接拒绝，不排队等待，包括自身转调。静态依赖环与运行时调用环分别检查。转调深度、总调用数、耗时有限，继承来源取消关系及预算，无 Run 动作也有独立限额；控制消息、状态响应和只读查询不得因此阻塞。

身份关联字段、错误码和限额待 schema 化；单链重入检查之外，嵌套转调遇到忙碌实例直接拒绝，不等待实例名额；不构成插件内部或外部系统无死锁保证。详见 [插件接入](harness/plugin-integration.md)。

## 24. 嵌套转调调度与结果处理

顶层工具调用 MAY 有界排队。嵌套转调目标忙碌时 MUST 返回未执行，不排队等待实例名额，不自动循环重试；同链重入、权限、预算和取消检查仍生效。只读查询和控制消息持续响应。这解决宿主管理的实例名额互等，不保证插件内部或外部系统无死锁。

嵌套转调先审批后获取目标名额，不预留。缺授权时创建动作并立即返回标识，通过通知/查询获取结果，不挂住原 RPC。审批期间不占目标名额或任务写锁，父调用仍未结束并占自身实例及原预算。获批复核来源、版本、取消状态与调用链，再尝试派发；目标此时忙碌仍返回未执行。

父调用结束、取消或超时使未派发子调用失效，迟到批准 MUST NOT 转为独立操作；已派发子调用沿取消关系处理，不承诺回滚。结果须区分成功、未执行、失败、取消和未知，不能以空成功掩盖忙碌/拒绝。

普通子失败由父工具决定结束、部分完成或在授权及剩余预算内继续。必需步骤缺失必须报告失败或部分完成并引用子结果，宿主校验结构与执行事实，不证明业务判断。来源 Run/动作/父调用取消、超时或撤权必须停止相关执行，不得改换工具绕过；未知结果不得按未发生自动重试。具体编码、关联字段及限额待定义。

## 25. 审批等待、有效执行计时与到期

有效执行超时、审批有效期与来源总墙钟 MUST 分开管理。Run 和无 Run 独立动作均有包含审批等待的总墙钟上限，具体时长与编码待定义。模型请求、实际工具运行及普通执行等待仍受各自超时限制。

仅创建审批 MUST NOT 暂停计时；宿主验证有关联未完成审批并进入显式等待状态后，才暂停相应有效执行计时。等待父调用只允许查询、取消和接收结果，MUST NOT 派发其他工具或提交业务修改；继续业务先退出等待并恢复计时。主 agent 的审批等待同样由宿主管理。此规则不冻结其他主体的获准操作或用户输入。

审批有效期与来源总墙钟始终继续计时，既定实例/Run/配置占用不释放，已消耗时长、调用数、token 和成本不重置；其他执行计时不随父等待自动暂停。不得将此机制描述为冻结可信插件进程或阻止其 OS 行为。

审批到期而尚未派发/提交时返回“未执行：审批已过期”；已合法派发调用不因审批自然到期单独终止，旧批准入口失效，不自动续期或重复申请。有效父调用恢复计时，按普通子失败处理；有效主 Run 接收结果后可在剩余预算内解释或处理，不执行原操作。再次执行需用户新请求并重新检查。来源总墙钟到期 MUST 终止来源及关联子调用，不可按普通失败忽略。

批准与到期竞态由宿主统一判定，迟到批准不得重新激活失效操作，过期结果不得恢复已终止来源。具体状态、错误码和时间判定实现仍待 schema 化与验证。见 [运行时](harness/runtime.md)。

## 26. 插件固定副本与外部环境非目标

插件安装 MUST 静态校验并复制为应用管理的固定版本副本，记录版本、包内摘要及声明配置；MUST NOT 执行安装脚本。启动和静态正文加载使用固定副本，不直接运行或跟随原目录，不提供首版开发热加载。

更新必须显式重新导入并遵守占用规则；可执行代码或启动声明变化需重新确认信任。受管理文件/声明配置与记录不符时，MUST 拒绝按旧批准启动或加载，要求重新导入和适用的确认，不静默接受。具体校验实现待定义，不承诺 OS 级不可变或运行中防篡改。

外部解释器、第三方依赖和运行环境由用户及插件负责，harness 不固定路径、不检查摘要或因外部环境变化要求重新确认。环境缺失/启动失败仅报告，不自动安装、修复或升级，不保证跨环境行为一致。插件间声明依赖的版本和启用检查继续适用，不能误解为对外部运行环境的验证。

## 27. 数据库迁移与恢复点

宿主启动 MUST 先检查 schema 版本再开放正常任务/插件访问。首版仅受控向前迁移；旧版遇到更高版本拒绝打开，不自动降级。迁移维护期停止业务执行和写入，先完成并校验迁移前备份；失败或空间不足不迁移，不删除唯一恢复点腾空间。首版迁移不得原地改写或删除既有不可变资源文件。迁移失败阻止业务启动，报告并保留恢复入口，不使用部分迁移数据继续业务。

恢复点采用 SQLite 一致性备份、版本信息、必要非敏感配置及资源/插件副本引用清单，不直接复制存在未合并日志风险的数据库文件，不明文导出凭据。保留期间保护关联文件不被普通回收删除，不每次复制所有资源。恢复前检查文件完整性；恢复仅数据、不续跑旧执行/审批，凭据缺失重新配置。本机制不是磁盘灾备。

首版最多一个有效恢复点，新候选创建并校验成功后替换旧点；失败保留旧点并阻止迁移。迁移成功保留恢复点，直到新点替代、用户明确删除或任务删除使其失效，不自动按天过期。显示创建时间、版本及额外保留文件空间估算。候选临时文件不构成第二个有效点，具体发布/崩溃边界待定义。

永久删除任务须提示连带清理包含该任务的恢复点；先废止恢复资格，再清理备份及引用保护，清理中断可续但不得恢复失效点。不得让旧备份撤回失效判断；不修改备份内部剔除单任务。释放引用仍保护其他任务/有效备份所需文件。可以没有恢复点，不自动创建新备份；外部副本及介质安全擦除不在保证内。具体 schema、迁移脚本和失效记录实现待定义，见 [存储与恢复](harness/storage-recovery.md)。

## 28. 面向模型的四原语

首版模型入口限定为 list、read、write、call。此为模型接口，不要求插件 JSON-RPC 或宿主内部方法压缩为四项；此前 surface.stage/commit 等契约继续作为内部或插件接口适用。

list 列出获准对象、类型或能力摘要及引用/可用状态，支持分页过滤；read 按引用读取内容/片段或完整契约。对象不必对应文件，MUST NOT 以任意宿主路径替代引用，每次操作仍检查权限。契约按需加载，不一次注入全部 schema，不强制每次重读稳定约定。未启用插件只暴露静态发现摘要，不允许借契约加载正文或执行。

write 表达完整意图：创建指定类型/内容/目标，更新和移除提供对象引用、预期版本及类型允许的变更。支持小内容直接传入、大内容资源引用及既定界面多操作；MUST NOT 提供任意字段/通用 JSON Patch 或无类型限制的删除。宿主负责校验、授权、暂存、预览及提交，模型无需手动暂存发布。内部/插件异步接口明确区分提交成功、待审批、失败，待审批返回可 read 的动作引用；模型侧 write MUST 等待终态才返回工具结果，界面即时显示进度，不以模型轮询驱动审批，不将接收当成功。失败保留原状态，不自动合并或扩权，其他执行中状态字段待定义。

不可变资源改动创建新版本，正式作答不任意覆盖；View 移除不删历史/资源，回收由宿主负责。运行记录/授权/凭据不可任意改写，永久删除任务或卸载插件等管理操作不经通用 write 向模型开放。

call 根据已启用能力标识及参数调用 Monty 或插件工具，参数/结果可引用对象，仍遵守能力 schema、授权、预算和调用链规则。模型自报类型或 schema 不创造权限。普通提问和说明使用正常回复，审批/调度等内部机制不独立暴露为模型工具。具体四入口 schema 与对象类型目录待定义，见 [工具与资源](harness/tools-resources.md)。

## 29. list/read/write 的基础行为

list 提供已定义字段筛选及名称/简短描述等元数据关键词匹配，MUST 明确匹配范围，不将未匹配解释为正文不存在。首版不自动扫描正文、解包或建立语义索引，扩展检索经 call 且引用继续鉴权。

read 仅读取已有表示：文本/结构化内容有界，包含版本、范围、截断与续读信息；权限允许且模型支持的选定图片可进入模型，不支持必须提示。PDF/音视频/Office 等返回元数据、资源及已有派生表示引用，不隐式解析、OCR、转码或外发；转换需显式 call。模型侧不返回大段无意义二进制/Base64，插件可通过受控资源接口读取字节。

续读 MUST 携带版本并检查变化；变化即中断，不返回新版本后续片段，要求放弃本轮旧片段，从最新内容重新开始，不沿旧版续读或混读。重读受次数和时间预算限制，持续变化明确提示无法完成一致读取。检查不冻结对象，write 仍检查预期版本；指定不可变资源/历史引用不因此静默变为新版本。

每次 write/动作新提交由宿主分配新唯一 ID，独立检查授权、版本并处理，不按标识、参数或内容复用旧结果。查询原操作使用原 ID；重发是新操作，未知结果不自动重发。call 同样每次独立登记。

## 30. call 调用身份与返回方式

每次模型 call MUST 由 harness 在登记时生成并持久化唯一调用 ID，再进入审批/调度；调用方不得指定或复用。相同能力及参数也表示新调用，不做调用意图去重或结果复用。ID 关联审批、执行状态、结果、取消和父子调用，不是去重键，不与模型服务或 JSON-RPC 消息关联 ID 混淆。write 与动作申请同样不去重。

查询已有调用使用 read，重复 call 不是查询/续接。未知结果 MUST NOT 自动重新调用，不保证外部副作用恰好一次。模型侧默认由宿主等待终态及有界结果，审批与调度不要求模型轮询；界面可独立显示调用 ID 和进度。插件间 RPC 仍可立即返回动作引用，不阻塞控制通道。

首版不提供脱离来源执行的后台 call，继续遵守取消、超时与父子生命周期。一次 call 只包含一个能力标识及符合其 schema 的参数，真实主体/任务/范围由宿主绑定。能力可自定义批量输入，入口不提供多步骤、条件、循环或跨能力事务，插件转调继续受调用链限制。具体 ID 和返回 schema 待定义，见 [工具与资源](harness/tools-resources.md)。

## 31. 模型响应内的工具请求顺序

同一 Run 的模型工具请求 MUST 按响应返回顺序串行处理，首版不自动并行。每项派发前重新检查授权、版本、取消状态及预算。审批等待暂停本批，不能跳过；批准且成功后继续，已接收/登记不等于成功。

前序未成功（失败、拒绝、过期、忙碌、结果未知）时 MUST 停止本批剩余项，并标记“未执行：前序请求未成功”，不误记为已执行失败。有效来源和预算允许时将结果交还模型重新判断，不自动重试或重发整批。来源取消、超时或撤权终止相关执行，不再调用模型规划。

序列不构成跨调用事务，已提交成果不回滚；单项界面提交的原子契约保留。此规则不替代插件父工具对普通子失败的处理，不阻止跨任务并行或控制消息/本地交互响应。具体序列与结果 schema 待定义，见 [运行时](harness/runtime.md)。

## 32. 参数错误与有界结果

参数契约不满足时 MUST 不执行并返回错误类别、字段位置、原因及必要修正提示；不猜测目标、替换能力、放宽 schema 或强制转换错误类型。明确声明的默认值可应用。版本冲突仅返回当前获准的信息/引用供重新读取，不自动覆盖；权限反馈不得泄漏数据或提供绕过路径。

修正由模型显式重发，受原有预算及序列停止规则约束；write 每次新提交均登记新 ID，call 每次生成新宿主调用 ID，不自动续接或重复执行旧请求。

小结果直接有界返回，大结果按资源授权/配额/提交规则保存，返回状态、有效资源引用与明确截断的预览。状态、错误和必要引用 MUST NOT 随正文过大被截掉；进一步内容通过 read 获取，不隐式调用模型摘要、筛选或改写结论。

体积超限、无法安全接收/保存时明确报告结果交付失败，区分已知执行情况和保存情况，未知效果保持未知，MUST NOT 推断未执行或自动重跑。不把未完成保存的引用当作有效产物，不承诺回滚已有外部副作用。具体错误/结果 schema、预览与体积上限待定义，见 [工具与资源](harness/tools-resources.md)。

## 33. 通用任务数据对象

Harness 提供带 schema 的通用任务数据对象，经 list/read/write 管理，不新增记忆工具或内置教学领域模型。对象含类型、结构化内容及来源，大内容经资源引用关联；更新/移除检查授权及预期版本，允许整体替换而非任意字段修改。

schema 可由插件声明，或由 agent 在创建通用对象时提供局部定义。宿主 MUST 校验 schema 本身、限制大小/复杂度，禁止远程引用与自定义校验代码。局部定义不注册宿主类型/能力/权限或触发规则。schema 创建后固定，结构改变新建对象，不自动迁移。

普通数据只保留当前版本及必要审计，不默认完整历史或任意回滚。正式作答、已发布界面及历史证据 MUST 保存当时所需的不可变快照或资源版本，不只指向可变对象。更新/移除不能改变历史证据，引用无法安全解除时拒绝移除。

访问遵守既定任务/全局范围，命名空间不隔离同范围读取，数据不是秘密存储，不能改写宿主 Run/授权/审批/凭据。保存不自动执行、不证明事实，观察与推断仍区分。对象、局部 schema 子集及审计/引用字段待定义，见 [工具与资源](harness/tools-resources.md)。

## 34. 单对象 write 与提交时证据快照

普通 write 一次只针对一个目标对象，首版不提供通用跨对象事务。界面对象内多 View 发布、正式答案与事件同事务保存等已确认特定原子性保留。多次 write 分别返回结果，不自动回滚、补偿或重试。

界面/正式记录采用任务数据时，提交方 MUST 明确声明数据对象及预期版本。宿主在提交时校验版本，匹配后固化所需不可变快照并绑定新内容/记录；变化则拒绝提交、要求重读，不静默采用新版本或拼接旧片段，不默认复制整个任务状态。

快照为提交内部产物，不新增模型工具、不允许附带修改源对象，不构成通用跨对象写事务。源对象之后更新/移除不改变快照，其资源引用沿用历史保留及回收规则。快照证明采用了哪份数据，不证明数据真实或教学判断正确。具体引用、快照 schema 与事务实现待定义，见 [存储与恢复](harness/storage-recovery.md)。

## 35. Surface 目标、显式引用及结果事实

模型界面 write MUST 以 Surface 为唯一顶层目标，View 作为其中操作目标，不另设独立 View 模型写入口。局部变更即可，不重传整页，多 View 发布原子性和 Surface/相关版本校验保持；不相关修改仍可能冲突，不自动合并。

任务数据、工具参数及结果中的对象/资源引用 MUST 使用宿主可识别的显式结构，鉴权并在保存时登记引用关系；普通字符串不产生引用语义或权限。HTML/CSS 使用专门受控资源格式，由解析器校验登记。具体字段尚未确定，不将访谈示例作为 schema。

可变任务数据引用 MUST 绑定预期版本，不自动跟随最新值。read 默认不展开关联对象；显式读取目标时版本不符返回冲突，由调用者重读最新内容并决定是否更新引用方。不因引用保留旧版全文，长期依据使用不可变快照。

当前对象引用 MUST 阻止目标移除，即使引用已因目标更新而过时；目标更新仍允许。先显式更新或移除引用方解除关系，再移除目标，不自动级联或跨对象事务，拒绝仅提供获准引用来源。独立历史快照不阻止源对象移除，但保护所需资源；永久删除任务不要求逐个解除内部引用。

循环引用 MAY 存在，不要求业务关系无环；MUST NOT 自动递归展开、更新或复制关联链。快照只固化明确声明的对象与版本，未声明关联对象不隐式获得历史保留保证，显式读取仍受预算限制。

模型 write 待审批只向界面即时显示进度，并暂停工具序列与后续主模型请求；内部/插件异步接口保留动作引用返回。终态才向模型返回工具结果，来源取消/超时不再推理，不冻结其他获准操作。

生命周期、执行情况与结果交付 MUST 分开记录。执行情况区分未执行、成功、部分完成、失败、取消及未知；交付情况区分不适用、待处理、已交付及失败，字段/编码待 schema 化。执行成功但交付失败不等于未执行，不自动重跑，并停止本批后续工具；执行失败但错误报告交付成功不等于执行成功。取消不证明副作用已撤回。

## 36. 默认权限、单次批准与可信工具

普通请求及 View 事件创建的主 agent Run 默认可读所属任务业务数据（排除宿主秘密），可新增任务数据和 View，不跨任务、不默认覆盖已有内容或调整已有布局。新增必须位于宿主允许位置，不遮挡已有内容，统一检查 schema、范围、配额和任务状态。

本 Run 新建且未被用户/其他执行方改动的 View 和任务数据 MAY 在该 Run 内继续替换/更新，每次检查预期版本。用户输入、作答或他方修改后 MUST 重新判断授权，不能仅凭创建来源放行。资格不包含移除、其他对象或整体布局，Run 结束失效，不产生所有权；丢弃用户输入须本人确认。

批准 MUST 绑定当前具体动作的目标、操作、内容和必要版本，可包含明确的多 View 操作。同动作继续执行/查询不重复审批；后续内容/目标/操作变化不得沿用。首版 MUST NOT 提供长期或通配授权，assisted 不能扩大未来权限；默认允许规则独立于单次批准。

View 事件只提供来源、表单及版本上下文，不自动授予来源 View 修改权，不把作答当作批准；可新增反馈，修改已有内容仍走统一授权。页面不得自报用户已批准来绕过判断。

Harness 信任已获用户信任并启用插件的只读声明，合法范围内默认免逐次审批；不要求证明其代码只读/不外发，不额外审查其 OS 行为，风险由用户承担。基础 list/read 也在已有范围内默认允许。身份、参数、范围、配额、生命周期和宿主修改授权仍强制执行，声明不能提升接口权限。

Monty 计算及其正常有界输出保存默认免逐次审批，仍受正式启用门槛、显式输入、无网络/宿主文件和预算等约束，不附带修改已有内容权限。不可用不得靠审批放宽限制或降级宿主执行。

获准调用的正常结果保存 MAY 直接完成，无需另批；宿主决定任务归属和位置，小结果直接返回、大结果保存为新资源并返回引用/有界预览。格式、引用权限、体积和有效性检查保持，不发布取消后的迟到产物。结果中业务修改提案 MUST 另行授权，不随输出自动执行。具体权限字段与状态关联仍待 schema 化。

## 37. Run 六状态与不可逆收尾

Run 生命周期 MUST 区分运行中、等待中、已完成、已失败、已取消和已中断；等待原因、拟结束状态、首要结束原因分别记录，字段编码待定。运行中包括模型/工具处理；等待中包括审批、请求名额及结束清理；失败包括已知错误/预算耗尽；取消包括用户取消、任务停止或撤权；中断包括部分流断开、崩溃/重启不能继续。各调用执行事实独立，不因 Run 中断全部变为未知。

未启动请求属于任务请求队列，MUST NOT 提前创建占位 Run。交还用户的提问/选择使 Run 正常结束，原因区别于普通响应完成；问题存任务记录，界面等待回答不占活跃名额或配置。审批等待仍占用，终态不可恢复，后续回答/继续创建新 Run。

所有结束路径统一处理：宿主确立边界时停止后续派发、废止关联继续提交资格及适用的待审批/未派发工作，固定拟结束状态和首要原因。有必要清理时保持等待中并明确结束清理原因，完成后才进入终态并释放该 Run 名额及相应配置占用。正常完成也不得留下仍获准执行的关联工作；读取和用户输入继续。清理异常不得伪称完成。

结束清理 MUST 不可逆。迟到批准不派发，迟到结果不提交业务成果，仅可补充必要执行事实。重试清理只停止/关闭/释放宿主管理资源，不重跑业务，不提供忽略清理恢复旧 Run 的入口。

首要原因按宿主确立边界的顺序固定，MUST NOT 按跨进程时间戳或后续错误/取消改写。正常完成的业务结论不因关闭失败改写，但完成清理前仍非终态。重启废止旧许可、不等待已消失内存执行，核对必要残留；已确立边界的保留原因，其余未结束 Run 按中断收尾。不续跑，不承诺回滚外部副作用或停止插件所有后代。

## 38. Call、Action、Approval 与执行准入

每次 call MUST 登记独立 Call。默认允许路径记录授权依据后调度，不要求额外 Action；需审批才建立关联调用授权 Action，批准后继续原 Call，不生成第二次调用。write、插件主动修改及结果修改提案各有适用 Action，可以没有 Call，不强制一一对应；结果修改不得复用调用批准。

调用授权 Action MUST 以成功派发为完成点，不以批准为完成点。批准后复核来源/权限/预算并取得名额；获批后来源失效或嵌套目标忙碌，记录未派发原因和 Call 未执行。成功派发后 Call 独立管理结果，工具失败不改写 Action；业务修改 Action 以提交成功为完成点。Action 完成不提前结束 Call/Run 或释放其占用，界面区别批准、派发和执行结果。

Approval 独立保存，单个 Action 最多一条；默认授权覆盖时可以没有。转人工沿用原记录和期限、保留评估，不重开计时。参数变化、过期或动作失效不得复活旧记录或在旧 Action 上反复审批，重新尝试必须按规则显式新请求。

审批决定、执行有效性和处理方式 MUST 分开表示，决定保留主体/时间/理由，后续失效不抹掉曾经批准。转人工不是批准/拒绝。Assisted deny 结束本次审批，不自动转人工复问或让模型改写理由重申；只有 escalate 或评估失败/无法判断才转人工且不延长期限。用户不同意可明确新请求并选择手动，旧决定保留，硬规则不可放行。迟到批准不得覆盖过期事实。

调用 MUST 在最终派发时检查有效批准，排队不延长期限；合法派发后自然到期不单独终止工具，执行超时、预算、来源总墙钟、取消/撤权继续有效。业务修改 MUST 在最终提交时检查有效批准，校验/暂存不算准入完成。工具结果修改提案另授权，不沿用派发许可。具体 schema 与状态编码待实现。

## 39. Call 五阶段、派发不确定性与结果可读性

Call MUST 区分已登记、等待中、执行中、收尾中、已结束，字段编码待定；等待原因、执行情况和结果交付情况独立。执行中包括派发和等返回，不证明插件开始；收尾中接收/校验/保存正常结果或执行取消/异常清理，不再派发新业务。必要收尾完成才已结束，终态不倒退。

首版不强制插件接收握手。宿主确认完整请求写入受管理传输通道即派发完成，适用的调用授权 Action 完成，不证明插件已读/执行。明确未发送记录未派发/未执行；发送不确定 MUST 记录派发未知，不伪报 Action 成功或明确未派发，不推断 Call 未执行。完整发送后丢结果保留派发完成事实并记录 Call 结果未知；MUST NOT 自动重发，调用 ID 不保证恰好一次。

终态后若收到可由宿主验证原连接及调用来源的有效报告，MAY 补充执行事实、来源和时间，但 MUST NOT 改写原结束记录、恢复执行、继续工具或发布迟到产物/修改提案。自报 ID 不足以认领，不要求保留失效连接等待。后续 Run 可读取获准补充事实。

“结果已交付”表示宿主完成接收、校验及必要保存，形成可读记录/有效资源引用，状态、错误、截断信息齐全，不表示消费方已确认读取。后续模型/连接/发送失败另记，MUST NOT 覆盖已保存事实或重跑工具。校验/保存失败仍为交付失败，界面可将已交付显示为结果已保存。

插件实例工具名额 MUST 保持至 Call 必要收尾完成并进入已结束，不因已返回结果/取消响应提前释放。期间控制消息持续处理，其他实例/任务不冻结。已保存结果发送失败不等待消费方重连。取消/失效后的迟到输出不得发布为有效产物。

## 40. 取消业务去重与提交事实

Harness MUST NOT 对 write、call、动作申请、业务请求或表单事件按客户端标识/参数/内容去重或复用旧执行结果。每次有效新提交由宿主分配新唯一 ID，分别检查授权、版本及状态；JSON-RPC/客户端事件 ID 只关联消息，不赋予幂等性。查询原 ID 不执行，再次提交是新操作；响应丢失/结果未知不自动重发。此前去重键、参数摘要比较及终态后默认 1 小时窗口撤销。

每次明确有效表单提交生成新记录，界面提交期间禁用按钮减少误触，不提供内容/事件 ID 合并。业务变更、对应记录与 Action 成功结果 MUST 同数据库事务提交，不含去重记录；文件先保存，失败孤立文件回收，不扩展跨文件系统事务。提交成功后的响应失败只影响传达，不改成功、不重做；提交不明先查持久化事实。版本控制、许可失效和动作生命周期继续有效，已提交草稿不能再次发布，不能把拒绝非法状态转移当作业务去重。
