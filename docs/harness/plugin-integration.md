# 插件注册、分层访问与进程通信

状态：接入规则、消息大小和开发时限已确认；manifest 和部分消息已有 schema，方法目录已有草案，完整 params schema 与联调仍待完成。

## 信任边界

可执行插件是用户主动信任的本地代码。插件自行选择语言、依赖、网络和运行方式；harness 不提供统一插件沙箱，不限制其全部系统行为。Monty 只是内置计算 tool，其无网络、无宿主文件和单次执行规则不能扩大到插件进程。

Harness 管理自己的接口、业务数据、状态和任务界面。插件通过接口提出的查询和动作受本规范约束；这些规则无法阻止本地插件绕过接口直接访问其 OS 用户有权访问的文件或网络。生成前端仍受任务界面安全规则约束，不继承后端插件的系统能力。

## 静态注册与信任确认

1. 读取静态 manifest：插件标识、版本、任务级/全局级、能力描述与依赖要求；只有声明后端可执行能力时才要求启动命令和参数。
2. 校验静态包结构、引用和能力描述；纯内容包直接供发现和按需读取，无进程或握手要求。可执行部分展示代码信任、访问级别和范围，由用户本人确认后才允许启动；不得为了发现能力先执行插件。
3. 后端可执行部分按需启动并握手校验协议和已声明能力；握手不能扩大级别或权限。
4. 代码或启动配置变更需要重新确认；任务级升全局级需要重新注册和人工确认，不能模型代批。

注册不执行安装脚本，agent 不自动安装依赖。首版由插件提供安装说明，用户准备环境。插件级别必须显式声明，缺失不得默认为全局。

变更检查限定于宿主管理的插件包文件和声明配置；外部解释器、第三方依赖和运行环境不管理、不做完整性检测。具体包内摘要及信任绑定字段仍待定义，不能把包摘要当作整个执行环境的完整性证明。

## 分层读取与动作范围

| 级别 | 实例范围 | 通过 harness 可读的业务数据 | 可申请动作的目标 |
| --- | --- | --- | --- |
| task | 所属任务 | 该任务全部材料、交互、界面、工具结果、公开运行状态和其他插件产生的业务数据 | 仅所属任务 |
| global | 应用 | 全部任务的上述业务数据 | 任意一个明确指定的任务 |

启用后范围内查询无需逐次审批，每次仍检查连接身份、实例有效性、注册级别、目标和数据类别。查询有分页、体积、速率限制。插件的基础读取范围不随某个 Run 的临时范围缩小；主 agent 的 Run 权限与插件注册级别是两套不同规则。

任何级别均不能查询模型密钥、系统凭据、内部授权凭证、宿主内存或模型私有推理链。工具目录和描述可查询，但执行工具不是查询。插件内部秘密自行管理，写入任务业务资源后不再默认对同范围插件保密。

全局级启用必须由用户确认跨任务读取风险。撤销后立即拒绝后续接口访问，但无法收回已读取的数据，也不承诺阻止插件自行传输这些数据。

任务级不能通过一次审批越过所属任务；全局级没有默认修改权。首版动作一次只针对一个任务，不支持跨任务原子提交。

## 进程生命周期

以下进程规则仅适用于后端可执行插件，纯内容包不创建进程。任务级按“任务 × 插件”创建实例与进程；全局级按应用创建实例与进程，跨任务复用。进程可处理多次调用，每实例首版串行执行工具调用；查询、响应、取消、关闭等控制消息必须持续处理，不能被工具执行或审批等待阻塞。

切换任务或关闭任务页面不停止任务执行。显式停止任务时停止该任务的任务级实例，不停止全局实例；停止中及已停止任务拒绝插件业务修改，全局插件仍可按既定范围只读查询。插件停用或应用退出时关闭相应实例，撤销连接权限。重启后创建新进程，不承诺恢复内存状态。插件自行持久化的系统数据不属于 harness 自动清理保证。

取消或超时：先废止本调用结果提交资格，再发送取消请求；宽限期后仍未确认停止则终止直接管理的进程，下次调用重启。不自动重试中断调用，不承诺回滚外部副作用或停止插件自行创建的所有进程。终止全局进程可能使后续所有任务的调用失去该实例内存状态。

## 双向 JSON-RPC 2.0

本地子进程通过 stdin/stdout 交换 UTF-8、每行一条完整 JSON-RPC 2.0 消息；stdout 只传协议，stderr 传有界日志。不是 MCP 兼容承诺。两端独立处理并关联请求 ID，传输接收不等待某个调用完成。

- Harness 发起：工具调用、取消、关闭等。
- 插件发起：上下文/资源/工具信息/状态查询，以及动作申请。
- 修改请求先返回 action_id 与当前状态，审批与执行完成后通过通知或状态查询获知结果，不长期占用原 RPC。
- 身份、级别与所属任务由连接绑定，消息内自报身份不能覆盖。
- 资源使用 ID 和受控读取方式；大文件不塞入无界单条消息，也不暴露任意宿主路径。

以下方法名称为示意，最终名称以 schema 为准；JSON-RPC id 只负责请求/响应关联，不能代替宿主生成的动作 ID。

```json
{"jsonrpc":"2.0","id":"plugin:1","method":"actions.submit","params":{"task_id":"task-1","action":{"type":"surface.commit","draft_id":"draft-1"}}}
```

```json
{"jsonrpc":"2.0","id":"plugin:1","result":{"action_id":"action-1","status":"awaiting_approval"}}
```

```json
{"jsonrpc":"2.0","method":"actions.changed","params":{"action_id":"action-1","status":"succeeded"}}
```

协议错误与业务拒绝必须明确区分；消息大小、帧错误处置、业务错误码到 JSON-RPC error 的映射、握手字段和取消方法仍需 schema 化，不把示例当作完整 SDK。

## 调用与修改的两个检查点

Harness 派发插件工具前检查实际参数、声明副作用和授权，需要审批时先批准再调用。声明是可信插件提供的说明，不是对其 OS 行为的强制限制；审批无法阻止插件在调用之外自行行动。

返回数据经过 schema 和大小检查。结果内的界面/状态修改提案必须走统一动作入口，调用批准不自动覆盖新增目标、参数或权限。一次明确批准可覆盖已知操作集合，但新操作需要重新检查。

无活跃 Run 时插件也可主动申请动作。确定性动作不必唤醒模型；需要推理才创建或排队新 Run。审批等待独立保存、不占任务写入队列，通过后排队，执行前复核版本、范围和授权。查询与用户意图确认不能借此被自动执行。

## 产物传输与重启补充

插件返回的本机路径是数据，宿主不自动读取。小产物显式返回，大文件受控分块上传，资源创建走动作授权；文件名不控制宿主路径。未完成的上传不可正式引用，失败/取消回收，见 [存储与恢复](storage-recovery.md)。

重启先恢复数据，不按旧执行状态自动继续工具调用或恢复插件内存。旧临时许可/待审批入口失效，用户继续后重新检查；已派发结果未知不重试。历史查看不得为了呈现旧内容调用插件或执行自定义脚本。

## 上下文压缩保留说明

插件可声明可选、有界的摘要保留说明；harness 只纳入当前任务启用且相关的说明，通用摘要结构优先，不能替换整个压缩提示词。说明不扩大读取范围、不授权工具执行、不保留凭据、不把推断升级为事实。

精确数据仍经既有受控接口保存，摘要仅概括并引用，不能以保留说明替代持久化。首版不提供压缩前后执行插件代码的专用 hooks，不改变插件本身的可信本地执行边界。具体声明字段和长度预算待 schema 化，详见 [上下文管理](context-management.md)。

## 材料解析能力

解析沿用已有工具发现与调用协议，不新增独立执行机制。能力说明声明输入类型、操作、输出形式及限制，供 agent 按需选择，不把格式支持理解为所有内容均可解析。未明确的费用、外发或结果取舍应向用户确认，声明仍不是 OS 行为保证。

结果通过既有产物接口保存为派生资源，关联原件版本、工具/插件版本与影响结果的参数；大结果直接响应只含有界状态、引用、定位及预览，正文按范围读取。重新解析产生新结果，升级不自动全量解析。字段待 schema 化，详见 [输入处理](input-processing.md)。

## 纯内容包与任务选择

插件可以仅提供静态 manifest、技能、流程说明和资源，无须后端入口、解释器或握手。加载知识不增加 agent 权限。一个包可同时包含静态内容和执行能力；执行部分不可用时，只有依赖条件满足且不依赖该部分的内容能力可继续使用，明确显示局部不可用，不能宣称完整可用。前端脚本仍走任务界面的隔离、发布与静态表示规则，不因无后端进程获得执行豁免。

安装只登记能力，不自动启用。新任务默认仅有 harness 基础能力，用户显式选择插件并另选至多一个主 workflow。Agent 可检索已安装插件的静态摘要并建议启用，不能自行启用或加载未获准插件正文。启用后正文按需读取、能力进入可用目录，不立即启动进程或执行工具，调用另行授权。不按学科隐式自动启用，也不在首版加入未经确认的默认组合。

选择界面按 workflow、skill、tool 等贡献类型分类，同一插件可出现在多个分类但共享整体启用状态。卡片显示全部能力、task/global 级别、是否执行本地代码及依赖就绪情况。首版不提供任意拆分包内能力的开关；依赖不满足的能力明确不可用，不能绕过已声明的必需依赖。选择主 workflow 与启用插件分开，启用不自动采用流程。

全局级插件由用户在应用层明确启用并确认跨任务范围，不逐任务重复批准；任务选择界面显示应用级状态，不伪装为普通任务勾选。应用级启用不自动向所有任务注入全部技能或流程，任务正文仍按需加载，主 workflow 仍显式选择。

## 配置变更与紧急停用

任务有未结束 Run 或尚未结束的插件动作/调用时，禁止新增启用、切换主 workflow、更新或替换任务使用的插件版本；等待审批也占用。正常变更等待执行空闲，变更本身不启动 Run，下一次新请求使用新配置，不改写历史。

用户随时可停用插件或撤销信任：立即拒绝后续相关访问与调用，取消依赖它的未完成执行并拒绝迟到结果，保留已保存内容。停用主 workflow 所属插件同时清除流程选择，不自动替换。此为安全撤销例外，不允许借停用绕过占用限制即时替换或新增能力。

全局插件更新/替换必须等待相关任务全部释放占用；紧急停用立即生效并明确展示跨任务影响。停用不保证撤回已读取数据或外部副作用，依赖执行的精确关联字段与占用释放时点仍待 schema 化。

## 依赖启用与停用传播

用户选择插件时，harness 汇总必须同时启用的已安装依赖及原因，由用户一次确认共同启用，不静默扩大范围。缺少必需插件、版本不匹配或声明依赖循环时阻止相关能力启用并说明原因，不自动下载或安装。插件整体必需项与单项能力依赖仍分别检查，不能借局部可用绕过整体必需条件。

依赖涉及全局范围或本地代码执行时，显式展示新增范围和风险，完成既有人工确认，不隐藏在普通依赖列表中。可选依赖不自动启用，缺少时显示受影响功能。共同启用仍受执行占用限制，不因依赖解析绕过用户选择或主 workflow 单独选择规则。

停用依赖时展示受影响能力和任务；确认停用后这些依赖能力不可用，相关未完成执行依撤销规则取消，迟到结果拒绝，不自动寻找替代插件或删除已保存内容。

## 工具转调的身份与范围

允许跨级依赖，但依赖不传递权限或继承被依赖插件的访问级别。经 harness 转调工具必须绑定真实调用来源、目标任务和本次授权，不能伪装成被调用全局插件自行发起的动作。执行工具不是只读查询，仍走调用前授权及结果修改的统一动作入口。

全局插件为任务提供工具服务时，经 harness 返回、引用或修改的资源必须符合本次调用范围；范围外拒绝，不能用审批提升任务级主体。全局插件自身独立查询和动作按注册级别处理，不与某个工具调用身份混用，也不因此缩小既定独立读取范围。

上述检查约束宿主接口和可追踪资源引用，不保证识别可信插件将其他数据混入普通文本的情况，不承诺恶意插件间信息隔离或控制其 OS 调用。

## 有界转调与运行时调用环

Harness 维护工具转调链，插件不得自报、清除或伪造。目标插件实例已在当前调用链中时直接拒绝并返回明确错误，不排队等待，包括自身转调；与安装时的声明依赖环检查分别执行。

无环转调也限制深度、总调用次数和耗时，沿用来源执行的取消关系与预算，不因切换插件重置预算。无 Run 动作必须有独立执行限额。控制消息、只读查询和状态响应仍持续处理，不被串行工具执行阻塞；插件自行 OS 调用不属于此调度限制。

具体身份/父子调用字段、错误码和限额仍待 schema 化。单链拒绝重入之外，嵌套转调使用下述忙碌即拒绝策略；不承诺消除插件内部或外部系统的所有死锁。

## 嵌套转调的名额、审批与父子生命周期

顶层工具调用可以有界排队；正在执行的工具发起嵌套转调时，目标实例空闲才派发，忙碌立即返回“未执行：实例忙碌”，不等待其执行名额、不自动循环重试。调用方可以返回局部结果或失败，由后续执行重新安排。此规则避免宿主管理的实例执行名额互等，不保证插件内部或外部系统无死锁。

嵌套调用先授权再尝试获取目标名额，不提前预留。缺少授权时创建审批动作，原 RPC 立即返回动作标识，父工具通过通知或查询等待结果；控制通道保持响应。审批不占目标实例名额或任务写锁，但父调用仍未结束，继续占用自身实例并计入原执行预算。

获批后重新检查来源、版本、取消状态和调用链，再尝试获取目标名额；此时目标忙碌仍返回未执行，不因已批准而排队。父调用结束、取消或超时后，尚未派发的子调用失效，迟到批准不能转成独立后台操作。已派发子调用沿既定取消关系处理，不承诺回滚外部副作用。

## 子调用结果与父调用处理

子调用结果区分成功、未执行、失败、取消和结果未知；忙碌或审批拒绝不能包装为空成功。普通忙碌、拒绝或失败不自动终止父调用，父工具可结束、返回部分结果，或在已有授权与剩余预算内继续其他工作。

必需步骤未完成时，父工具必须标明失败或部分完成并保留子调用结果引用；宿主校验结构和执行事实，不保证插件业务判断正确。来源 Run、动作或父调用被取消、超时或撤权不是可忽略的普通失败，相关执行必须停止，不能换工具继续被禁止的操作。结果未知不能当作未发生自动重试；已提交成果保留，外部副作用不自动重放。结果编码和父子关联字段仍待 schema 化。

## 等待审批的计时契约

父调用创建审批后仍计时；只有明确进入宿主核验的关联审批等待状态，才暂停该调用相应的有效执行计时。等待期间允许查询、取消和结果接收，禁止该父调用派发其他工具或提交业务修改；继续业务需先退出等待。父实例和既定 Run/配置占用保留，预算不重置，审批有效期与来源总墙钟持续计时。独立动作同样有总墙钟上限，不冻结进程或控制插件自行 OS 操作。

审批到期使尚未派发的子操作未执行、旧入口失效；已合法派发调用不因审批自然到期单独终止，不自动续期或重复申请；有效父调用恢复计时并按普通子失败处理。来源总墙钟到期终止整条关联执行，迟到批准或过期通知不得恢复已终止来源。具体计时字段与方法待 schema 化，见 [运行时](runtime.md)。

## 受管理的固定版本副本

首版安装仅静态读取、校验并复制插件包到应用管理目录，记录版本和包内文件摘要，不执行安装脚本。已安装插件从固定副本加载和启动，技能等静态内容也从该副本读取；不直接运行或跟随原目录，不提供源码目录热加载。

原目录变化不影响已安装版本。更新必须显式重新导入，遵守已有任务/全局占用限制；可执行代码或启动声明变化需重新确认信任。受管理副本文件或声明配置与记录不符时，禁止按旧批准启动或加载，要求重新导入并按既有规则确认，不静默接受变更。具体校验字段与实现待定义，不承诺 OS 级不可变或运行中防篡改。

外部解释器、第三方依赖及运行环境由用户和插件负责。Harness 不固定其路径、不检查摘要、不扫描外部依赖，也不因外部环境变化要求重新确认。环境缺失或启动失败只报告错误，不自动安装、修复或升级；不保证同一插件版本跨环境行为一致。插件间声明依赖的启用/版本检查仍适用，不应与外部运行环境管理混淆。

## 模型 call 与插件传输的关系

模型每次 call 由宿主生成持久化调用 ID，分别管理执行，不进行调用意图去重；调用 ID 不能由插件指定或复用，也不等于 JSON-RPC 消息 ID 或宿主动作 ID。动作申请也不接收去重，每次新提交独立登记。

模型侧一次调用一个能力，默认由宿主等待终态，不要求模型轮询；插件仍用异步动作引用、通知和查询保持控制响应。首版没有脱离来源执行的后台 call，现有父子取消/审批等待关系不变。能力可定义自身批量输入，但 call 不提供通用流程编排。详见 [工具与资源](tools-resources.md)。

## 信任只读声明与结果保存

已获用户信任并启用的插件，其声明为只读且范围合法的工具调用默认免逐次审批。Harness 不要求验证其代码真的只读或不外发，不增加 OS 行为审查；插件使用风险由用户承担。此为调用前授权判断的默认允许规则，不取消身份、范围、参数、配额、生命周期或嵌套调用检查，也不允许通过宿主接口绕过业务修改授权。

获准调用的正常结果由宿主有界接收，必要时保存为新资源，无需额外审批；这与插件独立资源创建/业务修改动作不同。位置与任务归属由宿主决定，引用权限、取消及结果有效性仍检查。结果内修改提案不自动执行，批准只覆盖当前具体动作，不授予长期或通配权限。详见 [安全与审批](security-approval.md)。

## 动作完成与调用审批

默认允许的插件只读调用有独立 Call 和授权依据，不强制附带 Action；需要审批时建立调用授权 Action，批准后派发原 Call。Action 完成只证明已经成功派发，不能报告工具已成功；获批后忙碌/来源失效仍记录未派发和 Call 未执行。插件主动修改及返回修改提案有独立 Action，以业务提交为完成点。

每 Action 最多一条 Approval，转人工保留原期限；deny 结束本次审批，不自动人工复问或重复申请。审批决定与当前有效性分开，取消/撤权不覆盖旧批准事实。已获批准但未派发仍检查到期；合法派发后自然到期不取消调用，执行时限、来源总墙钟及取消/撤权规则继续。字段/方法尚待 schema 化，见 [安全与审批](security-approval.md)。

## 派发边界与实例收尾

首版不强制工具接收确认握手；宿主确认完整请求写入受管理通道即派发完成，不证明插件已接收或执行。发送中失败且不能判断是否完整送达，Action/Call 保留派发未知事实，不伪报未执行或自动重发；完整发送后丢失结果保留 Action 派发完成，Call 结果未知。

Call 经已登记、等待中、执行中、收尾中到已结束，执行/交付事实独立记录。插件返回后名额仍保持至校验、必要保存及异常清理完成；收到取消响应不单独释放。控制消息持续响应，不阻塞其他实例。结果已保存而向消费方发送失败，不等重连、不重跑工具。

终态后能验证原连接/调用来源的迟到报告仅补充执行事实，不改原结束记录、不复活执行或发布产物。自报调用 ID 不足以认领，不要求保留失效连接。完整定义见 [工具与资源](tools-resources.md)。

## 字段草案、错误分层与上传

manifest、能力描述和 RPC 方法目录见[接入契约](../contracts/integration.md)及[核心 schema](../contracts/schemas/core.schema.json)。这些是根据已确认规则起草的编码，不代表完整 SDK 或实际插件。

协议结构/未知方法错误走 JSON-RPC error，已受理操作的审批拒绝、冲突、执行失败使用持久操作关联的业务结果。可靠定位的非法 JSON 可报告解析错误；超长、非法 UTF-8 或不可恢复 stdout 污染关闭连接并清理，已派发事实不被抹掉，不自动重放。持续错误必须有界。

资源按顺序分块接收，重复/乱序拒绝，不跨连接续传；完整暂存产物跟随所属 Action 生命周期，不因为原 RPC 结束就立即删除。配置、并发及预算见[开发默认值](../contracts/development-defaults.json)。
