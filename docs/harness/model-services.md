# 模型服务配置与请求调度

状态：正式应用已提供渠道配置、多模型共享连接、显式发现与角色测试。服务商预设、公开目录补全和价格刷新仍保留为后续设计。真实服务兼容性需按具体服务验证。

后续研究更新：已完成 [models.dev 公开目录调研](../research/models-dev.md)，记录实际快照、字段与源码边界。本文保留原契约，研究建议尚未固化为字段级接入规范；各渠道服务接口和真实能力测试仍待验证。

## 渠道与模型

渠道是连接服务的配置，包含服务地址、认证方式、凭据引用及渠道级参数；模型配置关联渠道，包含模型标识、角色所需能力与容量等独立参数。主推理、压缩和辅助审批可使用相同服务/模型，但消息上下文和职责保持独立。

首版仍按明确能力约定接入 OpenAI-compatible Chat Completions，不以兼容名称推断全部特性，也不增加自动模型路由。配置契约见 `core.schema.json`。显式保存使用 settings v4，将渠道与模型分开记录；凭据引用 auth.json，同渠道多模型复用一份密钥。旧 v1–v3 读取时在内存归组，不改写原文件。运行记录不保存 API Key。

应用设置集中管理模型、审批、插件和存储。保存渠道不联网；发现模型需主动确认。模型表单不包含 API 或密钥。修改渠道连接会使其模型角色失效，改名称或保存方式不改变已验证能力。

## 自动发现优先，手动局部兜底

用户选择服务商并填写凭据；预设服务自动填写地址，自定义服务需补充地址。取得连接信息后主动查询服务可用模型供用户选择。模型列表接口不支持或失败时，可尝试匹配的模型目录，最后允许手动输入模型标识。目录中的候选不等于当前账号可用，必须区分。

选定模型后优先采用服务接口实际返回的能力、上下文容量、输出上限等元数据，缺失部分再按服务商和模型标识从 models.dev 匹配补齐，不只按相似名称猜测。记录来源、获取时间与用户覆盖。第三方目录不能证明自定义代理实现了相同能力。

上下文容量等运行必需参数仍缺失或存在无法解决的冲突时，仅要求用户手动补充对应字段，保留已获取值；补齐前不启用对应角色。不得用猜测性的保守预算冒充模型容量或绕过补充配置。手动值也不能替代真实能力测试或授权检查。

凭据只发往用户配置的服务，不发给 models.dev 或其他渠道。自动目录查询不包含任务材料；实际推理测试另行明确触发。

## 测试并启用

用户点击“测试并启用”后发送有界的合成请求，提前说明可能产生少量费用，不使用真实任务数据。只测试选中配置，不遍历全部模型，也不测试上下文窗口极限。

主模型验证基本响应、流式输出与工具调用，工具调用仅返回测试结果，不执行真实业务操作。不支持工具调用时不能作为主模型运行，不从普通文本提取命令冒充工具能力。审批与压缩模型仅验证各自必需的响应格式，不强制要求工具能力。

视觉能力不足不能静默丢图继续回答；文本任务不因此被禁止。必要能力及容量满足相应角色后才能启用，具体测试判定和可选能力状态待定义。

区分认证失败、模型不可用、接口不兼容与暂时性服务错误。通过测试仅证明当前样例可用，不证明教学/摘要质量或全部边界正确。服务地址、模型或关键能力参数变化后，旧测试不能证明新配置有效，需重新验证；测试请求自身也计入统一调度与配置占用。

## 不自动切换

失败仅按 [运行时](runtime.md) 已确认边界有限重试，不自动换模型、渠道或凭据。用户明确取消/结束旧执行并选择后，以新 Run 继续；保留已提交结果，重新检查容量、能力和上下文，不继承旧模型假设。不因便宜、繁忙或不可用而静默转发任务数据。

## 占用即锁定

未结束 Run 持有主模型、压缩模型及该 Run 使用的审批模型配置的占用；等待审批、执行本地工具和等待模型请求名额期间仍占用。无 Run 的辅助审批、连接测试等独立模型请求，检查配置并进入请求调度时开始占用，直到成功、失败或取消。

模型被占用时禁止修改或删除该模型配置；关联渠道被占用时禁止修改或删除渠道地址、认证方式、凭据和共享参数。即使只有一个模型在用，渠道也锁定；同渠道下未占用模型的独立参数仍可编辑，不能借此修改共享渠道。

多个使用者分别释放占用，只有最后一个释放后才可修改。用户可以明确取消相关执行，不通过编辑/禁用配置绕过锁。界面展示占用来源，避免为改配置强制终止无关任务。自动发现和目录刷新同样不能改写被锁定的有效配置。

独立动作仅等待人工审批、没有模型请求时不构成模型占用；若属于未结束 Run，该 Run 的占用仍保持。任务不是永久锁定单位：Task 保存着但没有相关执行占用时可改配置。

## 两类排队与配置选择

任务请求提交时记录所选主模型和相关角色配置及识别变化所需的版本依据，不因默认模型变化而替换选择。尚未启动的任务请求不持执行锁；启动前再次检查配置存在、必要参数齐全且验证有效，再启动 Run 并占用。

排队期间所选配置被修改或不可用时，暂停启动并提示，需用户确认更新后配置或重新选择，不自动发送任务数据。默认值变化不等于所选配置变更；已记录的选择不漂移。

模型请求队列不同于尚未启动的任务请求队列。已启动 Run 的模型请求，以及已进入调度的独立模型请求，即使尚未获得并发名额也持有模型/渠道占用。取消后不得再发出请求，不能因排队而允许中途改配置。

## 目录刷新与价格

新配置使用最新获取的资料。目录可以自动刷新，但不自动改写已保存配置；发现差异展示给用户确认，未释放占用前不得应用。手动覆盖值不被目录静默替换，可提示新的参考值，允许批量接受更新。

价格是独立的费用估算信息，可刷新供后续估算，并标明来源与时效；不改用户预算、不回写历史估算，也不能以刷新价格为名绕过锁修改有效配置。价格元数据与配置参数的具体存储边界待定义。

目录暂时不可用不阻断已配置且验证过的模型，提示元数据可能过时。实际调用错误按既有规则处理，不自动切换服务。

## 有界并发与公平调度

允许不同任务并行，同一任务仍最多一个未结束 Run。主推理、压缩、辅助审批和连接测试统一受应用级及渠道级模型请求并发上限约束，超限排队，不为内部请求开无界通道。

实际请求执行才占并发名额；等待人工审批、执行本地工具或两次模型请求之间不占名额，但相关配置占用仍在。不同任务等待同一服务采用简单公平排队，避免长 Run 连续抢占全部机会，不建设复杂智能路由。

界面区分等待服务与正在生成，队列可取消。并发默认值、排队上限、调度公平算法及生命周期竞争处理待实现验证，不将请求名额与配置锁混为一谈。

## 未决项与验收

待补齐实际服务列表接口验证、基于 models.dev 研究的字段映射与目录匹配/冲突策略、配置 schema、测试标准、必需参数清单、并发/队列限额和锁的实现。不新增已验证的服务兼容性承诺，模型 adapter 尚未实现。

验收覆盖自动发现与局部手动兜底、凭据不外泄、角色测试、无自动切换、占用锁与两类队列、目录更新和手动覆盖、公平调度及取消竞争。见 [测试计划](testing-delivery.md)、[上下文管理](context-management.md) 和 [安全与审批](security-approval.md)。

## Run 结束清理与占用释放

Run 确立结束边界后不再发起业务模型请求，但有必要清理时仍为未结束的等待状态，相关配置占用保持，清理完成进入终态后才释放其占用；不释放其他使用者的占用。不以用户点击取消或服务已返回为由提前开放配置修改。正常交还用户在收尾完成后释放占用，界面等待用户回答不保留活跃 Run。重启废止旧执行并核对必要残留，不恢复旧请求；具体收尾见 [运行时](runtime.md)。

## 字段级接入基线

采用显式兼容 profile，定义参数映射而非任意 extra_body；不按模型名称猜 max_tokens/max_completion_tokens 等参数，不能确定时局部手动选择或报告不支持。

models.dev 精确匹配明确 provider 和 wire ID，不用相似名称或 canonical 替换；容量须有效正数，缺失能力记 unknown，流式和工具仍实测，自定义代理不自动继承同名服务模型能力。字段来源、获取时间、手动覆盖保留，配置锁规则不变。

审批与摘要不强制提供方原生 JSON Schema，必须本地严格 JSON/schema 校验，不做宽松修复。应用/渠道实际模型并发开发基线 4/2、应用模型等待队列 100，按任务简单轮转公平调度。费用缺乏依据标未知/估算；无法可靠遵守用户严格货币上限时阻止或由用户明确更改预算，不默默忽略。见[接入契约](../contracts/integration.md)。
