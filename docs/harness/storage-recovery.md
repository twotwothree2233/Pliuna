# 存储与恢复

状态：行为、保存频率及开发配额已确认；初始 SQL、上传及事务已有草案，尚未实现真实持久化或迁移恢复。

## 当前状态与必要历史

SQLite 中的当前状态是恢复依据，不要求重放所有事件来重建任务，不建设完整事件溯源系统。保存任务、Run、动作、当前界面版本和最新输入草稿，并保留已提交作答、已发布界面版本和必要事件、审批、工具调用记录。

同一次业务变更涉及的数据库状态与对应记录 MUST 在同一事务提交。例如正式作答快照与提交事件一起持久化，成功后才确认接收、允许后续 agent 处理。不能先唤醒 agent 再尝试保存答案。审计记录不作为恢复所有状态的唯一来源。

工作摘要是派生的模型上下文，不替代对话、作答和资源原件。压缩不删除原记录，候选通过校验才替换有效摘要，失败保留旧状态；历史范围、引用和安装机制见 [上下文管理](context-management.md)。这不增加全量事件溯源要求，也不改变任务删除规则。

## 草稿与正式作答

输入草稿只保存最新状态，不记录每次按键。前端即时响应，合并自动保存到 harness；保存检查字段、类型和体积，允许不完整输入。正式提交另行验证必填、格式和范围，并生成不可变快照。

每个提交关联任务、呈现单元、内容版本、表单标识、所提交字段、对应资源版本及提交序号；具体字段名称待 schema 固化。继续编辑草稿不能改写既有答案。用户再次明确提交形成新记录；不自动进行网络重发，再次提交属于新请求并可形成新答案。

保存与提交不是同一件事，格式有效也不代表教学答案正确。前端显示保存中、已保存或失败；关闭或替换前先保存或由用户确认丢弃。突发崩溃可能丢失最后未持久化输入，不承诺每次按键已落盘。

## 重启：恢复数据，不自动继续执行

- 自动恢复材料、已提交界面、已保存草稿和答案，不等待模型。
- 未结束且未确立结束边界的 Run 按执行中断收尾；已进入结束清理的保留拟结束状态和首要原因。旧租约与临时权限失效，核对必要残留，不等待已消失的内存执行；完成必要清理后进入终态。具体编码待定。
- 不依据中断前的执行状态自动恢复插件进程、沙箱或模型调用。后续插件激活仍遵守注册、信任与生命周期规则。
- 待审批和未完成动作保留展示，但旧入口/执行许可失效；继续前重新检查参数、版本和授权，必要时创建新请求。无 Run 的动作同样不得在重启后静默执行。
- 用户选择继续后开启新 Run，读取已保存记录理解进展，不从中断的代码位置继续。
- 已派发且未记录结果的插件调用标记结果未知，不自动重试或宣称已回滚。

已确认删除的清理作业可以在重启后继续，这是完成用户已确认的维护动作，不是自动恢复 agent 业务执行。

## 不可变资源

用户导入文件时保存副本，不长期引用原始路径。源文件被移动、修改或删除，不影响任务已有内容。重新导入或通过宿主修改资源产生新版本，历史引用保持指向具体不可变版本；不做目录监听或双向同步。

相同不可变资源可复用，引用计数/引用关系实现待定。资源 ID 不是访问授权，查询始终遵守插件级别或相应宿主授权。导入过大或复制失败明确报告，不悄悄退回源路径引用。

## 文件与数据库提交

1. 在有界临时位置接收数据，校验大小、完整性及摘要。
2. 将校验后的文件发布到不可变资源存储。
3. 在数据库事务中登记资源，并更新使用它的界面、作答或结果引用。
4. 数据库提交成功后才向调用方报告保存成功。

不假设数据库事务能原子提交任意文件系统操作。第三步失败允许留下无引用文件，后台后续回收；回收必须识别进行中的保存，不能仅因尚无数据库引用就立即删除。具体保护标记、租约或扫描机制待实现。

重启发现已登记资源缺失或摘要损坏时明确报告，不静默替换或重新生成历史内容。文件发布、刷盘及崩溃边界需真实测试，不能把普通重命名等同于已证明断电持久性。

## 插件产物显式传输

小结果通过有界 JSON-RPC 返回，大文件通过受控上传接口分块传输。资源创建经过统一动作授权；临时接收数据不等于任务资源，校验与提交完成前不能被正式引用。

Harness 不自动读取插件返回的宿主路径。路径字符串只是数据，文件名只是显示元数据，不决定实际保存位置。插件本身仍可自行读写文件，本规范只约束宿主接收产物的接口。

上传失败、取消、授权失效或目标任务删除时终止发布并回收临时数据，不留下可引用半成品。上传授权、分块格式、总量预算和恢复策略待 schema 化，不引入无界共享目录。

## 已发布历史与只读查看

保留已发布的界面版本及关联资源，用于解释学生当时看到的内容；未发布或校验失败的呈现草稿不作为长期历史，可清理。输入草稿与呈现发布草稿是两个不同对象。

历史显示保存的题目、内容和答案，不用当前数据重生成。普通表单显示快照并禁用提交/修改，纯展示展开折叠可以保留。历史不执行自定义脚本、不调用插件、不唤醒 agent。

复杂区域使用该版本保存的静态表示；缺失时明确说明无法还原，不能运行旧脚本补齐。用户继续学习回到当前任务发起新请求。首版不建设完整历史编辑器、差异比较或任意版本回滚。

## 永久删除

首版不做回收站。用户本人确认后先持久化“删除中”状态，立即拒绝新访问和写入，停止 Run、撤销未执行动作/审批/上传，关闭任务级插件。全局插件继续运行但不能经接口访问此任务。

先废止包含该任务的本机迁移备份，阻止恢复，再清理这些备份及引用保护；随后清理任务业务记录、作答、界面历史与独占资源。仍被其他任务或有效备份合法引用的文件保留。清理中断后重启继续，不将任务重新暴露为可用。删除进度的内部记录与清理必须可重复执行，具体表和事务边界待定。

删除只覆盖 harness 管理的数据，不保证收回可信插件、导出文件或外部服务的副本，不承诺磁盘取证意义上的安全擦除。不得因删除最后一步失败恢复旧执行授权。

## 待决与验收

表结构/具体迁移脚本、状态编码、保存节流、非迁移备份的保留期限、回收保护实现与上传字段仍待决定；迁移和恢复点行为以下文已确认规则为准。测试必须覆盖提交事务失败、文件与数据库之间崩溃、回收与上传竞争、旧审批迟到、多次提交独立登记、历史脚本不执行、删除中断重试和共享引用保留。参见 [测试计划](testing-delivery.md)。

## 导出快照与外部副本

导出固定内容/资源/作答版本，预览与保存使用同一快照，不锁住任务。期间更新不混入，资源不可用不替换为新版本；任务删除或撤权停止未完成导出。快照引用保护机制待实现，不将导出快照解释为延续权限。

宿主临时生成并校验后，保存到用户通过系统对话框选择的位置，覆盖须本人确认；失败保留原文件，取消清理未完成临时产物，成功保存后不因迟到取消删除文件。跨文件系统安全替换与崩溃边界需要测试。导出文件不随任务修改/删除自动更新或撤回，详见 [导出契约](export.md)。

## 输入批次与派生资源

多文件导入逐项提交，成功即成为有效资源，不因其他项失败整批回滚。失败/取消的未完成项不得登记为有效资源，清理临时数据；取消保留成功项，界面重试仅针对失败项。附带请求缺附件时先确认，不静默只用部分材料启动 Run。

派生结果绑定原件确切版本、处理能力版本和参数，并保存实际可用的定位与处理局限。重新解析产生新结果，不覆盖既有引用；允许查询后按需复用，不做自动缓存替代或升级重解析。具体批次/来源/操作关联字段待定，详见 [输入处理](input-processing.md)。

## 停止任务的持久化边界

任务执行状态独立于页面可见性。停止与业务提交通过同一任务写入协调机制确定先后，停止边界前已提交成果保留，之后旧业务结果不可提交。停止后的草稿与正式答案仍可保存；答案和事件同事务持久化，但不生成待恢复的推理请求。记录保存与请求执行必须区分，具体状态字段待 schema 化。

停止状态不能因重新打开页面或应用重启而自动解除。恢复任务是重新开放执行，不续跑旧 Run、动作、审批或工具，也不自动处理停止期间的提交；需新请求按需读取记录。停止中清理异常如实显示，完成前不允许恢复，重启仍不得恢复旧业务执行。

脚本区域的静态表示在发布时必需，并与相应内容版本一起保留引用；损坏/缺失是完整性问题而非允许执行旧脚本的理由。恢复仅加载与当前版本兼容的已保存界面状态，不恢复脚本内存。见 [任务界面](surface.md) 和 [运行时](runtime.md)。

## 已安装插件副本

插件安装保存应用管理的固定版本副本、包内文件摘要及声明配置，不长期跟随源目录；静态技能也读取固定副本。原目录改动不更新已安装版本，更新需重新导入并遵守占用和信任规则。副本文件/声明配置与记录不符时拒绝按旧批准加载或启动，不自动接受新内容。

包内校验不证明运行中不可变或外部环境一致；解释器、第三方依赖由用户/插件管理。副本记录与校验的具体 schema 待定义，见 [插件接入](plugin-integration.md)。

## 数据库向前迁移

数据库记录 schema 版本。启动先检查版本，再开放正常任务及插件访问；旧版遇到更高版本数据库拒绝打开，不猜测兼容、不自动反向迁移。

迁移在业务执行与写入停止的维护阶段进行。先建立并校验可恢复的迁移前备份，成功后才开始受控向前迁移；备份失败或磁盘不足则不迁移，不静默删除唯一恢复点腾空间。首版迁移不原地改写或删除既有不可变资源文件，避免数据库恢复后引用已被破坏。

迁移失败阻止进入正常业务界面，明确报错并保留恢复入口，不以部分迁移状态继续业务。表结构、迁移脚本、维护互斥和崩溃发布机制仍待实现验证，不声称数据库与资源目录具备跨文件系统原子事务。

## 迁移恢复点的内容与引用保护

使用 SQLite 支持的一致性备份机制，不直接复制可能存在未合并日志的数据库文件。恢复点包含数据库一致性副本、schema/应用版本、必要非敏感配置，以及资源与已安装插件副本引用清单；系统凭据不明文导出。

不每次复制全部资源文件，而是在有效恢复点保留期间保护其引用资源及插件副本，普通垃圾回收不得删除。恢复前检查引用文件是否齐全及完整性；缺失/损坏不得伪称可完整恢复。该机制仅用于本机迁移失败恢复，不承诺抵御磁盘损坏、外部手工删除或整目录丢失。

恢复只恢复数据，不续跑旧 Run、工具、插件调用或审批；缺少凭据时由用户重新配置。恢复后的执行继续遵守重启不续跑、插件信任和停止状态规则，不将旧授权恢复成可执行许可。

## 恢复点保留与替换

首版最多保留一个有效迁移前恢复点，不自动按天过期。新迁移先成功创建并校验新的恢复点，再替换旧点；创建/校验失败保留旧点且不迁移。准备新候选期间可临时存在旧点和候选文件，不表示同时发布两个有效恢复点，安全替换及清理实现待验证。

迁移成功仍保留该点，直到下次有效替代、用户明确删除或任务永久删除使其失效。界面显示创建时间、应用/schema 版本以及额外保留文件空间估算。磁盘不足阻止迁移，不静默删除唯一恢复点。用户删除后允许没有恢复点，不自动开启新的备份流程。

## 永久删除与恢复点失效

任务永久删除确认说明：同时清理包含该任务的本机迁移备份，可能失去整个恢复点。确认后先将相关备份标记为不可恢复，再清理备份及引用保护；中断后继续清理，期间不得恢复失效备份，让已删除任务重新出现。

不修改旧备份内部数据来剔除单个任务。释放备份引用不直接等于删除文件，仍被其他任务或有效备份引用的资源/插件副本保留。失效记录和恢复入口需协调，不能依赖加载旧备份本身来撤回失效判断；控制清单与数据库投影方案见[执行契约](../contracts/execution-storage.md)，需真实崩溃验证。

不承诺清除用户复制的外部备份、SSD 残留或文件系统快照；应用层永久删除不等于介质安全擦除。

## 工具大结果持久化

工具大结果沿用受控资源保存与提交流程，成功后才返回有效引用，预览明确有界/截断。结果体积超限或接收/保存失败时分别记录工具已知执行情况和产物保存失败，不将其等同于工具未执行，不自动重跑未知外部效果，也不隐式调用模型总结替代原结果。状态、错误及必要引用不随正文截断丢失。信封与开发配额已有契约草案，见 [工具与资源](tools-resources.md)。

## 任务数据当前值与证据快照

普通任务数据对象保存当前版本和必要的来源/操作/版本审计，不默认保存完整修改历史，不建立事件溯源或任意回滚。整体替换和允许的移除均检查授权及预期版本。创建时绑定固定 schema（插件声明或 agent 提供的受限局部 schema），结构变更创建新对象，不隐式迁移。

正式作答、已发布界面和其他需要历史解释的记录保存当时所需不可变快照/资源版本，不能只引用可变数据。当前对象更新或移除不能改写这些历史证据，无法安全解除引用则拒绝移除。大内容资源化，审计和引用关系具体 schema 待定义；保存数据不自动执行业务。见 [工具与资源](tools-resources.md)。

## 提交时固化数据依据

界面或正式记录采用可变任务数据作为历史依据时，提交方明确指定对象与预期版本；宿主在提交时校验并固化所需快照，与新内容/记录绑定，不复制整个任务状态。版本不符拒绝提交并要求重读，不静默切换到最新值或修改源对象。快照属于内部提交产物，不要求模型额外复制。

源数据后续改变或移除不改变快照；关联资源继续受历史引用保护及回收规则约束。普通 write 单对象，多次写入不构成事务，不自动补偿或回滚；单次界面发布和答案/事件等已有特定原子性保留。具体快照字段与数据库/文件提交实现待验证，不承诺任意跨文件系统事务。见 [工具与资源](tools-resources.md)。

## 显式引用与移除保护

资源和对象引用必须采用宿主可识别的显式结构；HTML/CSS 的受控资源格式另由解析器识别。普通 ID 字符串不产生引用保护。可变对象引用绑定预期版本，不自动跟随或要求保留旧版全文；当前对象引用阻止目标移除，目标更新仍允许，旧引用随后冲突。引用保护检查和业务修改需协调，不能因并发写入遗漏保护。

引用方先显式更新/移除解除关系，再移除目标，不自动级联修改，也不引入跨对象事务。循环引用允许，但不自动递归处理。独立历史快照不要求保留源对象，继续保护所用资源；快照只固化提交方明确声明的对象及版本，不递归复制整条引用链。任务永久删除沿用已确认整体清理，不要求逐个手动解环。

工具生命周期、执行情况和结果交付分别记录，输出保存失败不能覆盖已知执行事实或触发自动重跑。具体结构及事务测试待实现，见 [工具与资源](tools-resources.md)。

## 获准调用的输出保存

获准调用的正常结果资源化属于该调用，无需额外审批，不等于插件可独立任意创建/修改业务数据。宿主决定位置及任务归属，照常执行有界接收、引用鉴权、校验、发布和数据库登记；失效调用及取消后的迟到结果不得成为有效产物。结果中的业务修改提案另行授权，不因输出落盘而执行。

## Run 结束记录与重启收尾

持久化 Run 生命周期、等待原因、拟结束状态和首要结束原因，字段见[SQL 草案](../contracts/sql/001-core.sql)。结束边界固定原因、撤销继续提交资格；有必要清理时仍为等待中，完成后才终态并释放名额/相应配置占用。后续取消、工具结果或清理异常不得覆盖首要原因；迟到结果仅可补充执行事实，不发布业务成果。

重启废止旧许可、不续跑旧业务，不等待已消失的内存执行。已记录结束边界的沿既定原因收尾；其余未结束 Run 按中断收尾，核对必要残留后完成。清理失败保留真实状态，可重试维护清理但不重跑业务。未启动请求不提前创建 Run；用户问题保存在任务记录，交还用户的 Run 正常完成，不长期占锁。详见 [运行时](runtime.md)。

## 调用结束事实与结果可读性

保存 Call 生命周期、派发事实、执行情况和交付情况，字段见[SQL 草案](../contracts/sql/001-core.sql)。宿主侧完整发送不证明插件执行；无法确认发送或执行时保留未知，不自动重放。已保存的结果不因后续响应发送失败变成交付失败，获准主体可查询原调用；调用收尾不等待消费方重连。

终态记录不被迟到报告覆盖。来源能验证时仅补记报告、来源与时间，不发布新有效产物、不执行修改提案、不恢复旧 Call/Action/Run；无可验证原连接/调用来源不得只凭自报 ID 补写。补充记录可供后续获准读取，但不为此保留失效连接。见 [工具与资源](tools-resources.md)。

## 提交成功与响应失败

一次业务修改的状态、对应业务记录/资源引用和 Action 成功结果必须在同一数据库事务提交；不再包含写入意图或去重绑定。事务失败则这些数据库变更均不生效，文件按既定先保存后登记流程处理孤立产物，不构成跨文件系统或插件外部副作用事务。

提交成功后响应发送失败不改变成功事实、不回滚或重新提交。调用方查询原 ID 读取结果；不能通过再次提交复用原结果。提交情况不明先核对持久化记录，不因响应丢失自动重做。客户端版本同步恢复展示，与是否收到响应分开。

## 事务所有者、暂存保护与恢复实现

runtime 为业务数据库唯一写入者；文件准备/审批/模型和插件执行均在写事务外，短事务重新核验状态、权限、版本并原子保存业务变更和结果。初始表结构与事务清单见[执行与持久化](../contracts/execution-storage.md)，尚未应用于真实数据库。

上传使用绑定主体/任务/操作的宿主 ID、有界顺序块和明确偏移；重复乱序块拒绝，不做缓存成功响应，不跨连接/重启续传。中断的未完成上传失效，完整交给持久 Action 的暂存产物按操作生命周期保留。暂存准备完成不等于业务发布。

持久 staging/pin 保护文件准备、发布及 DB 引用提交间隙，绑定 owner/runtime epoch；GC 检查实际引用及 owner 状态，不仅按年龄删除。必要执行清理未完成仍阻止终态；不可访问/不可提交的孤立文件删除失败可以后台维护，不永久锁执行。正式材料、答案、历史和有效恢复点不因空间紧张自动淘汰。

恢复旧数据必须本人确认，恢复点废止依据不能被恢复旧数据库覆盖。独立控制清单及数据库投影的推荐实现见契约，需真实崩溃验证。
