# 上下文管理与压缩

状态：本轮整批契约已由用户确认，尚未实现。schema、开发预算和版本化模板已有草案；摘要长度、估算器校准及语义效果仍需实现测试。外部 agent 的默认值不是本项目默认值。

## 活动上下文与原始记录

模型输入由固定规则、工作摘要、最近完整交互和按需读取的原始记录组成。固定规则包括宿主约束、当前请求及本轮权限边界，每轮由宿主明确提供，不依赖摘要保留。技能和 workflow 仍是知识与流程说明，不是授权。

工作摘要记录目标、进度、待解问题及相关引用，是有损导航，不是事实数据库或审批凭证。对话、正式答案和资源原件在本地保留；压缩只改变后续发送给模型的内容，不删除原件。记录保留仍受既有存储与任务删除规则约束，不引入完整事件溯源。需要细节时通过基础读取能力按 ID 或范围取回。

摘要与原记录或当前状态冲突时，以原记录和当前状态为准。学习水平等判断标为推断，不冒充用户事实。宿主始终重新核验实际权限和审批状态，不能从“摘要说用户已批准”推导有效授权。

## 三层处理顺序

1. 按需装载：只加载相关材料片段、能力摘要和必要状态，按需读取技能/工具正文。
2. 确定性缩减：长工具结果保存在受控资源中，上下文保留必要预览、执行状态和读取引用，不删除完整结果。
3. 语义摘要：前两步后仍超过安全输入预算，才生成摘要，并保留最近完整交互。调用和对应结果成组处理，不在二者中间截断。

首版不要求向量数据库或复杂记忆系统，不承诺模型记住所有细节。

## 请求前检查与同步压缩

每次模型请求前估算宿主规则、工具定义、摘要、近期交互、材料等全部输入，并预留模型输出及估算误差空间；不只按聊天记录长度或固定窗口百分比触发。具体预算数值通过测试确定。

需要压缩时暂停主推理，同步生成摘要后再继续；首版不并行后台压缩。压缩在完整交互的安全边界执行，不切割尚未收齐的工具参数或尚未结束的调用。

压缩使用确定的历史快照。页面交互和草稿保存继续，新输入不能被旧快照覆盖；恢复推理前重新读取必要的当前状态。排队规则仍适用，每任务至多一个未结束 Run，压缩不另开并行主 agent。

## 摘要请求与模型配置

Harness 发起独立、无工具权限的摘要请求，只生成候选摘要，不继续任务、不执行插件或修改业务数据；宿主负责校验、保存和安装摘要。默认使用当前主模型对应服务和模型，单独组装请求，不混入审批模型上下文，也不要求另配记忆模型。

允许用户另行指定压缩模型，但需要满足输入容量和输出格式要求，不因价格自动切换。只发送所属任务所需数据；另配服务时明确说明历史会发往该服务，不静默跨服务降级。

压缩调用次数、token 和耗时纳入当前 Run 预算，预算不足停止并说明原因，不能作为内部维护绕过限制。模型请求自身也必须满足容量和输出预留约束。

## 通用摘要与插件扩展

Harness 管理通用结构：目标、约束、已完成事项、证据引用、未完成请求和不确定性。格式及字段已有[核心 schema](../contracts/schemas/core.schema.json)草案；新宿主模板与研究候选均不代表已完成效果评测。

插件可以提供可选的保留说明，例如保留尚未解决的错误并引用对应作答；不能替换整个压缩提示词。说明有长度预算，只纳入当前任务启用且相关的插件说明。冲突时优先保障通用信息，不承诺满足所有保留要求。

保留说明不能要求跨任务读取、工具执行、保留凭据或把推断变成事实。精确成绩、作答和错题记录应经既有接口保存为任务数据，摘要只保留必要概括与引用。首版不增加压缩前后执行插件代码的专用 hooks；此限制针对宿主压缩扩展，不改变可信插件自行执行本地代码的既有边界。

## 候选校验、失败与取消

生成期间保留有效摘要和原始记录。程序校验候选的结构、长度、引用存在且属于当前任务、覆盖范围匹配，以及组装后的请求是否有足够余量；通过后才切换上下文。Schema 与引用有效不证明语义无遗漏。

格式错误或摘要过长等可纠正问题，在预算允许时最多进行一次纠正尝试。取消、认证错误和预算耗尽不进入纠正；仍失败则结束当前 Run，保留任务和已提交结果，不清空上下文或静默丢弃更多历史。用户可缩小请求、调整模型或预算后重新发起。状态编码见[执行契约](../contracts/execution-storage.md)，尚未实现。

如果主要问题是当前请求、工具定义或单个材料片段过大，应说明原因并转向减少装载或分段读取，不反复总结同一段历史。用户取消后，迟到摘要不得安装。首版不默认另调用第二个模型审核摘要含义，先用来源与测试集验证质量。

## 连续压缩与纠错

以上一版有效摘要和新增完整交互生成下一版。最近保留原文可以参与概括，但覆盖范围避免重复计入。重要约束、决定、完成状态和学习判断携带消息、作答或资源引用；来源不足标为不确定，不编造证据。

用户纠正旧目标或结论时更新当前结论，必要时保留替代关系，不把新旧说法并列为同时有效。涉及原话、数值、作答细节或冲突时，要求主 agent 回查原记录；这一提示要求不替代宿主强制授权校验。

发现摘要错误时可从相关原记录重建受影响内容；首版不按固定轮数自动重总结全部历史。连续摘要存在累计失真风险，引用仅帮助核验，不能证明没有遗漏，必须专门评测。

## 用户可见性与手动整理

自动压缩默认开启，显示“正在整理上下文”，完成后简短提示，不把摘要全文插入学习对话。详情可查看当前工作摘要、覆盖范围和来源，并标注模型生成、可能遗漏或出错，不展示内部推理。

用户可手动“整理上下文”，在当前执行的安全边界处理，不打断正在运行的工具；同样遵守预算和失败规则。无活跃 Run 时创建仅用于整理的 Run，完成后立即结束。整理不清空学习记录、不改变目标、不授权后续业务动作。

用户通过正常输入指出摘要错误，agent 回查后更新；首版没有专用摘要编辑器。错误提示区分服务错误、预算不足、单项输入过大与摘要校验失败，不统一笼统显示上下文不足。

## 验收与未决项

验收覆盖多次压缩后的未完成请求、用户纠正与来源保留，调用结果配对，历史注入命令，审批过期，数据版本更新，长输出，取消迟到和失败不破坏旧上下文。除缩减率外，观察事实与推断混淆、来源准确性、重复执行风险和回查成本；具体指标/阈值待实验，当前没有效果测试结果。

已有开发配额、摘要 schema/候选模板和插件说明选择规则；仍需预算估算器校准、长度参数、历史快照/安装实现及模型配置完整 schema。研究依据见 [方案比较](../research/context-compaction.md)，运行中断边界见 [Agent 运行时](runtime.md)。

## 模型配置与调度补充

另配压缩模型同样经过自动发现、必要时手动补充和角色测试；容量未知不使用猜测性保守预算启用。Run 未结束时相关压缩模型及渠道配置锁定，禁止中途修改。压缩请求与主推理、辅助审批及连接测试共同受请求并发限制，排队不释放配置占用；不自动更换服务或模型，详见 [模型服务](model-services.md)。

## 模板与开发预算基线

摘要、审批及主 agent 宿主规则作为版本化资产，运行记录绑定模板版本，首版无模板编辑器；候选正文见[接入契约](../contracts/integration.md)。插件不替换宿主规则。

token 估算优先匹配 tokenizer，否则明确估算加安全余量并参考 usage 校准；已知容量不能被猜测替代，视觉输入不能按零计。开发基线为最近 4 个完整交互组、输出预留 min(8192, 模型已配置输出上限)、上下文 10% 安全余量；不可靠估算可提高。当前请求和必要未完成信息不因组数丢失，最小必要上下文仍过大则失败。

插件保留说明确定性选择当前主 workflow 与待压缩历史中实际使用且当前仍启用能力；workflow、最近调用、最近读取优先，同级稳定 ID 排序，在长度预算内加入，不另调模型判断相关性。summary schema 已有草案，提示词效果及精确长度配置待实现验证。
