# 当前安全边界与审批

宿主负责对象范围、版本、执行资格和必要确认。
模型与插件提交的是申请，实际执行通过宿主入口。

## 进程和呈现边界

Renderer 使用 sandbox 和 contextIsolation。
任意 Node 调用、额外窗口和页面导航被关闭。
任务 View 使用 Shadow DOM 与主动行为校验。

插件后端是用户信任的本地代码。
task/global 限定宿主数据访问范围。
该范围不会把插件变为 OS 沙箱进程。
Monty 的计算限制另见[执行说明](code-execution.md)。

## 变更资格

| 操作 | 当前处理 |
| --- | --- |
| 当前任务对象读取 | 对象、来源与派发状态检查 |
| 新建同任务资源或数据 | 按宿主规则登记并执行 |
| 同 Run 新建对象的继续编辑 | 检查 creator_run_id 和自动编辑资格 |
| 其他数据替换或界面变更 | 按具体动作登记审批 |
| 数据删除 | 独立审批并检查进入引用 |
| 状态 reset 与丢弃输入 | 额外要求本人或宿主确认 |
| 插件信任和跨任务启用 | 本人明确确认 |
| 恢复、退役和资源清理 | 维护预约、预览及本人确认 |

授权绑定具体主体、参数、目标和版本。
提交前再次检查有效期、来源和撤权状态。
取消或重启撤销旧执行的提交资格。

## 手动与辅助审批

默认模式为手动审批。
辅助模式需要通过 approval 角色测试的模型。
启用时确认必要任务信息外发与可能费用。

模型只返回 approve、deny 或 escalate 及简短理由。
escalate、无效结果和评估失败转人工处理。
审批模型不能替用户确认信任或丢弃输入。

决定、有效性与处理状态分别存储。
历史批准不自动覆盖新动作。
执行成功与模型评估结果也分别记录。

## 凭据与外发

当前应用记住连接时使用明文 auth.json。
settings.json 保存不含密钥正文的配置引用。
文件写入使用私有目录、权限保护和冲突检查。
用户也可仅在内存使用连接。

任务正文通过选定服务的实际请求外发。
公开模型目录查询不携带任务材料或服务密钥。
改变历史处理模型需要明确确认。

## 安装包与本地元数据

两套打包流程共享[路径拦截规则](../../scripts/local-agent-files.mjs)。
本地代理配置、指引和笔记不得混入复制目录。
复制与成品检查发现禁止路径时直接失败。

规则按明确路径组件匹配。
应用 agent 模块、UI 和角色提示词继续保留。
回归见[桌面打包测试](../../tests/unit/desktop-packaging.test.ts)和[macOS 测试](../../tests/unit/package-agent-files.test.ts)。
