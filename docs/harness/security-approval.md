# 安全与审批

状态：本轮分层授权、插件信任与审批职责已确认；具体字段和配额待实现。

## 两种不同的信任

可执行插件是用户主动信任的本地代码，启动后可能自行访问宿主文件或网络。Harness 不承诺 OS 沙箱，也不能用接口审批限制插件全部行为。只有显式信任后才启动；全局级需人工确认，代码/启动配置更新重新确认。见 [插件接入](plugin-integration.md)。

插件协议消息、模型输出、材料和前端事件仍必须校验。信任插件代码不代表任意返回结果都是已授权宿主命令。Monty 内置工具及生成前端继续执行各自的隔离和无外联约束。

## 分层与范围

任务级读取所属任务全部业务数据，包括其他插件内容；全局级跨任务读取。范围内只读查询免逐次审批，仍检查实例有效性和数据类别。任一级别禁止读取密钥、系统凭据、授权凭证、模型私有推理链和宿主内存。

任务级动作只能针对所属任务；全局级动作一次明确一个目标任务。级别不是修改授权，审批不能提升级别。停用/撤销立即拒绝后续接口访问，但不能收回已读数据。

所有呈现单元归任务所有，来源只用于追踪。执行方获得有范围的修改权，不因产物归任务就允许主 agent 随意修改。读取 skill/workflow 不改变身份和权限；Run 范围由 harness 建立。插件基础读取范围不继承 Run 的临时限制或扩权。

## 权限审批与用户意图确认

权限审批决定允许执行什么；用户意图确认决定用户实际想要什么，二者必须分别表示。

- 权限审批支持 manual 与 assisted。
- 安装/启用可执行插件的信任、全局级启用与升级由用户本人确认，不模型代批。
- 学习问题、目标选择、未明确确认的任务删除和丢弃未保存输入不能由审批模型代答。
- 已明确表达的用户选择可作为依据，但模型不能推断并补出缺失的意图。

需要用户选择时交还控制权，按运行时规则结束 Run，之后回复开启新 Run；单纯等待权限审批则暂停依赖该结果的 Run。

## 权限审批顺序

1. 硬禁止或注册范围之外直接拒绝，不能审批放行。
2. 检查已有授权是否确实覆盖具体操作，不因“已安装”或“全局级”推导修改权。
3. 未覆盖则提交审批；所有修改都必须经过此入口，不能通过只读查询产生副作用。

硬限制包括内置 Monty 访问宿主文件/网络、生成页面外联、伪造身份、通过接口暴露宿主秘密。插件后端自行访问 OS 不是此入口能够控制的行为，不套用 Monty 限制。

## 手动与帮我批准

手动模式展示工具、目标、参数摘要、范围、副作用和权限变化；不能只展示主 agent 理由。凭据不明文显示。

帮我批准使用独立、无工具权限的模型调用，不是第二个持续 agent。宿主组装实际请求及必要上下文，主 agent 理由和材料视为不可信输入。输出只允许 approve、deny、escalate，经 schema 校验；无效响应、错误、超时或无法判断转人工，默认不执行。

## 异步动作与批准绑定

动作请求独立于 Run 保存；插件主动请求可以没有 run_id。绑定 action_id、目标任务、真实主体、级别、能力版本、参数摘要、范围、必要资源版本、有效期和策略版本；Run 发起的动作另关联 run_id。

待审批不占任务写入队列、插件通信通道或写锁。依赖审批的 Run 暂停，但查询、草稿保存及其他获准动作继续。批准后排队执行，再检查授权和版本；变化影响批准依据时拒绝旧动作；再次尝试必须显式创建新请求，不在同一 Action 上重开审批。

同任务至多一个未结束 Run，等待审批也计入。用户取消 Run 时取消其未完成动作/审批，迟到批准无效；没有关联该 Run 的插件主动动作不自动取消。插件停用、请求取消或授权撤销同样使相关许可失效。

派发插件工具前完成调用授权；返回的新修改提案再检查，不用“先执行后审批结果”代替调用前授权。插件已产生的外部副作用不保证撤销，未知结果不自动重试。

## 审计与验收

记录请求摘要、判断、简短理由、审批模式、服务和执行结果，不存私有推理链，密钥不入日志。审批服务只接收必要上下文，用户应知晓数据可能发往配置的服务。

必须验证级别越界拒绝、全局启用不可代批、用户意图不可代答、参数变化失效、待审批不堵塞控制通道、取消后迟到结果拒绝。Monty 与前端安全仍需各自验收；本地插件信任不能包装成恶意插件防御保证。

## 表单与存储确认

用户在当前表单输入产生的基础草稿保存是预先授权行为，无需逐次审批；插件/agent 改写仍检查动作授权。重置导致丢弃输入必须用户确认，不允许代批。

任务永久删除由本人确认后进入删除中，撤销接口和待处理动作；重启续清理不需要恢复旧 agent 授权。一般未完成业务执行和旧审批则不得在重启后自动继续。历史界面没有提交/执行能力，不通过重新授权运行旧脚本补齐历史展示。

## 导出确认与权限

导出默认学习材料，附带正式作答/反馈需用户明确选择；部分导出及覆盖目标文件需本人确认，不由 assisted 模型代办。预览提醒检查隐私，分类声明不等于内容已脱敏。

快照不冻结权限；任务删除或撤权阻止未完成导出。保存路径由系统对话框的用户选择产生，不接受插件或生成内容指定的任意写路径；agent 仅能建议文件名。该宿主能力不向 Monty 开放文件或网络访问。导出不运行旧脚本，不因缺失内容调用模型或插件补齐，详见 [导出契约](export.md)。

## 输入材料与预览

保存文件不代表允许执行其中代码、宏、脚本或外部引用，也不代表同意自动解析或全文发送模型。预览仅走明确支持的受控路径，禁止自动外联；活动格式需安全处理/转换，无法安全预览时说明不支持，不直接运行原文件。用户 HTML 转任务界面仍走呈现校验、授权和发布。

解析工具沿用调用前审批；未明确的费用、数据外发或结果取舍由用户决定，不能用权限批准代替需求选择。附件不全时仅用成功项继续也需用户明确决定。以上约束宿主流程，不承诺限制可信插件绕过接口的 OS 行为，见 [输入处理](input-processing.md)。

## 模型服务与配置保护

自动查询模型目录不携带任务材料，API Key 只发送给用户配置的服务，不发给 models.dev 或其他渠道。真实推理测试由用户主动触发，使用有界合成内容并提示费用；目录声明不代替能力测试或授权。配置记录/Run/日志不保存明文密钥。

未结束 Run 和已调度模型请求占用的模型/渠道禁止修改与删除，凭据也不能中途更换；需先取消或等待占用释放。无 Run 的辅助审批与连接测试同样占用。等待人工审批本身不产生独立模型请求占用，但所属 Run 的锁继续有效。请求失败不静默切换模型/服务/凭据，见 [模型服务](model-services.md)。

## 停止任务的执行门禁

显式停止任务使该任务旧执行提交资格与未完成动作/审批失效，包括无 Run 插件动作。停止中及已停止状态禁止新业务执行；批准不能绕过任务停止状态。全局插件保留既定只读范围，不保留修改资格。用户基础草稿保存和明确提交答案是保留的预先授权行为，不触发模型或工具。

停止中禁止恢复；已停止任务必须用户显式恢复，打开页面不构成恢复。恢复不恢复旧许可、请求或审批，插件新动作重新走统一入口，代码/启动配置变化重新确认信任。此规则不承诺控制可信插件独立的 OS 行为。具体时序见 [运行时](runtime.md)。

## 插件启用与撤销

安装不等于启用，启用不等于具体操作授权。用户明确选择任务插件及主 workflow，agent 仅可检索静态摘要并建议，不代选未启用插件。纯内容包无需本地代码执行确认或进程握手，但内容仍不能覆盖宿主规则；后端代码与前端脚本分别遵守各自信任和隔离边界。全局启用仍由用户在应用层确认跨任务范围。

执行占用阻止正常插件配置变更，但不阻止用户停用/撤销信任。撤销立即拒绝相关访问/调用并使依赖的未完成执行和迟到结果失效，保留历史内容，不能撤回已有副作用。全局停用提示跨任务影响；停用主 workflow 插件不自动选替代流程。

## 依赖不传递权限

共同启用必需依赖必须由用户确认，涉及全局范围或本地代码执行仍显式提示并完成对应确认。可选依赖不自动启用，依赖选择不能绕过占用限制。

跨级依赖和工具转调不授予被调用方的注册权限；harness 绑定真实来源、目标任务与授权，按调用范围检查返回/引用/修改的资源，越界拒绝，不能审批提升任务级主体。全局插件独立动作与受委托工具调用分别检查。宿主可追踪引用的检查不等于能识别可信本地插件混入文本的越界数据，也不改变其 OS 信任边界。

## 嵌套调用审批

子调用审批先于目标实例名额获取，审批动作返回标识后不占原 RPC、目标实例名额或任务写锁。父调用仍占自身实例并计入预算。获批重新检查来源、版本、取消状态及调用链，目标忙碌返回未执行，不预留或排队。父调用结束/取消/超时使未派发子调用失效，迟到批准不得创建独立后台执行。

普通审批拒绝可由父工具如实报告并决定其他授权工作；来源 Run/动作/父调用撤权或取消则必须停止相关执行，不能当作一般工具失败绕过。见 [插件接入](plugin-integration.md)。

## 审批有效期与等待门禁

有效执行计时、审批有效期、Run/独立动作总墙钟分别管理。只有宿主验证存在关联未完成审批并进入显式等待状态，才暂停相应有效执行计时；仅提交审批不暂停。等待期间该父调用只能查询、取消、接收结果，不得派发工具或提交业务修改；先退出等待恢复计时才能继续。其他获准主体及用户基础输入不因此冻结。

等待不释放既定占用、不重置预算；审批有效期和来源总墙钟不暂停，无 Run 动作同样受总时限约束。不冻结插件进程或承诺控制其自行 OS 行为。

审批到期而尚未派发/提交的操作返回未执行，并使旧批准入口失效；已合法派发调用不因审批自然到期单独终止，不自动续期或重复申请。仍有效的父调用/Run 可恢复计时并在剩余授权和预算内处理过期结果；总墙钟到期则终止来源及关联执行。批准与过期由宿主统一判定，迟到批准无效。审批模型请求自身的超时不是审批有效期：转人工仍不能延长已失效审批或绕过来源终止。见 [运行时](runtime.md)。

## 包内信任与外部环境边界

插件从受管理固定副本加载；包内文件或声明配置摘要不符时拒绝按旧批准启动/加载，必须显式重新导入，可执行代码或启动声明变化重新确认信任。检查不承诺 OS 不可变、运行中防篡改或包外依赖完整性。

外部解释器及第三方依赖由用户和插件负责，不固定路径或检查摘要，不因外部环境变化触发重新确认；失败报告而不自动修复。依赖声明属于受管理包内容，但不代表宿主已验证外部环境。见 [插件接入](plugin-integration.md)。

## 迁移恢复与永久删除

迁移维护期不开放正常业务及插件访问；恢复只恢复数据，不恢复旧执行许可或续跑审批。备份不明文导出系统凭据，缺少凭据由用户重新配置。

任务永久删除由用户确认其连带清理迁移恢复点的影响；先将包含该任务的恢复点标为不可恢复，再清理，清理中断不允许恢复失效备份。用户可明确删除恢复点，不自动创建替代；不承诺清除外部复制备份或介质残留。见 [存储与恢复](storage-recovery.md)。

## 局部数据 schema 的边界

agent 可为通用任务数据对象提供局部 schema，但不能据此注册宿主能力、提升权限或触发执行。宿主校验 schema 大小及复杂度，禁止远程引用和自定义校验代码；schema 创建后固定，改变结构另建对象。

数据创建/替换/移除仍走 write 授权和版本检查，业务字段不改变宿主运行状态、审批或凭据；命名空间不提供私有读取屏障，也不是秘密存储。保存不证明事实，引用保护不能因数据由 agent 创建而绕过。具体规则见 [工具与资源](tools-resources.md)。

## 默认权限与单次动作批准

普通聊天请求创建的主 agent Run 默认可读取本任务业务数据（排除宿主秘密），可新增任务数据和 View；不得跨任务，不默认覆盖已有内容或调整已有布局。新增 View 只能进入宿主允许的位置，不能遮挡既有内容，仍检查 schema、范围、配额和任务状态。默认允许也经过统一授权入口，不等于绕过校验；工具调用单独判断。

本 Run 新建且未被用户或其他执行方改动的 View/任务数据，可在同一 Run 内继续替换/更新，无需逐次审批。每次检查预期版本；用户产生输入、作答或其他执行方改动后，不再凭创建来源自动放行，按当前状态重新检查授权。该资格不包含移除、其他对象或整体布局，Run 结束即失效，不形成永久所有权。丢弃用户输入仍须本人确认。

批准默认只覆盖一个具体动作，可覆盖其中明确列出的多 View 操作，绑定目标、操作、内容及必要版本。同一动作继续执行/查询不重复审批；后续更换内容、增加目标或改变操作不得沿用。首版不提供长期或任意通配授权，assisted 也不能扩大未来权限。默认允许的操作不是从一次批准推导的长期许可。

View 事件仅提供工作来源、表单及提交版本上下文，不自动授予来源 View 修改权，不把用户答案当作授权。事件 Run 可读本任务并新增反馈 View/任务数据；替换已有内容或调整布局仍检查授权。事件明确要求修改时也走统一授权判断，页面不能自行声明已获批准。

## 可信只读调用与正常结果保存

Harness 充分信任已获用户信任并启用的插件声明，范围合法的只读工具调用默认免逐次审批，不要求证明代码真的只读或不外发数据，不额外审查/拦截其自行文件、网络等 OS 行为；插件风险由用户承担。宿主仍执行身份、任务范围、参数、配额和生命周期规则，插件通过宿主接口修改业务数据仍走修改授权，声明不提升接口权限。基础 list/read 在已有范围内同样免逐次审批。

内置 Monty 计算及其正常有界输出保存默认免逐次审批，仍要求获准输入、运行预算、结果校验和取消检查；不附带修改已有业务数据/View/布局的权限。未通过正式启用门槛或不可用时报告不可用，审批不能放宽无网络/无宿主文件限制或降级宿主执行。

获准调用的正常结果资源化属于调用组成部分，无需额外审批。小结果直接返回，大结果由宿主保存为新受管理资源并返回引用和有界预览；宿主决定位置及任务归属，不接受任意路径或跨任务写入。仍检查格式、引用权限、体积及调用有效性，迟到取消结果不发布为有效产物。结果内业务修改提案另行授权，不随结果自动执行。

## Call、Action 与 Approval 的关系

每次 call 始终登记持久化唯一 Call，默认允许的调用直接进入调度并记录授权依据，不额外创建空的调用授权 Action。需要额外审批时才建立关联 Action，批准后继续原 Call，不生成第二次调用。write 和插件主动业务修改有自己的 Action，可以没有 Call；工具结果中的修改提案另建 Action，不复用调用批准，也不因此生成新 Call。

调用授权 Action 的职责止于成功派发：批准后还需复核来源、权限、预算并取得执行名额，成功派发后该 Action 完成，Call 独立记录运行及结果。获批后来源失效或嵌套目标忙碌，Action 记录未派发原因、Call 记录未执行。工具之后失败不反向改写已经完成派发的 Action。业务修改 Action 则以提交成功为完成点。界面分别展示已批准、已派发与执行结果，不将动作完成当作工具成功。

Approval 是独立记录，单个 Action 最多关联一条。默认授权覆盖的修改 Action 无需创建 Approval；需要审批才创建。转人工沿用原记录与原有效期，保留模型评估，不重新起算期限。参数变化、过期或动作失效后不得在旧记录上反复审批或复活，重试按既定规则显式发起新请求。

## 审批决定、有效性与处理方式

审批决定、当前执行有效性和处理方式分别表示，字段编码见[执行与持久化](../contracts/execution-storage.md)，尚未实现。决定保留决定者、时间及理由；后续 Run 取消、撤权或过期使执行资格失效，但不抹去曾经批准的事实。实际执行仍复核来源、权限、版本和期限，不只查看决定。

转人工是处理方式变化，不是批准或拒绝。Assisted 返回 deny 即结束本次审批，操作不执行，不自动再询问人工或让主 agent 改写理由重复申请。只有 escalate、无效响应、错误、超时或无法判断才转人工，且不延长有效期。用户不同意拒绝时可明确发起新请求并选择手动审批，旧决定保留；硬规则拒绝不能人工放行。过期后的迟到批准请求被拒绝，不覆盖原记录为有效批准。

## 审批期限的执行准入点

工具调用在最终复核并派发时必须具有有效批准，获批后仍在排队也不能绕过期限。合法派发后，审批自然到期不单独中断 Call，由调用执行时限、来源总墙钟、预算、取消和撤权继续管理。

界面发布及数据修改在最终业务提交时必须仍有有效批准，开始校验/暂存不延长许可。工具结果中的业务修改提案另行授权，不沿用派发批准。来源取消或撤权与自然到期不同，仍使相关执行/业务提交资格失效，不能因已经派发而绕过。审批到期不是第二套工具执行超时。

## 批准绑定、恢复确认与开发期限

Action 四阶段与独立结果按[执行契约](../contracts/execution-storage.md)编码。原动作参数或所需版本变化时结束该动作，不修改绑定继续使用批准。恢复旧数据必须本人确认恢复时间、范围和较新数据替换风险，不能辅助审批代答。

审批开发有效期为创建起 15 分钟，转人工不续期；不属于任何去重窗口。审批输出不强制服务原生结构化模式，但必须严格 JSON 及本地 schema 校验，不提取/修复文本。宿主[审批模板](../contracts/prompts/approval-v0.1.md)版本化，首版无编辑器；模板不替代硬权限检查。
