# 工具与资源

状态：四原语、对象目录及开发配额已确认，输入输出 schema 已有草案；动态能力二级校验和 SDK 尚未实现。

## 面向模型的四个基础入口

| 入口 | 职责 |
| --- | --- |
| list | 列出有权访问的对象、对象类型或能力摘要，返回引用、简短元数据及可用状态，支持过滤和分页 |
| read | 按引用读取对象内容或片段，也可读取对象类型/能力的完整契约，包括操作说明、输入输出 schema、限制及示例 |
| write | 表达完整写入意图，创建、替换或执行对象类型允许的移除，由宿主校验、审批和提交 |
| call | 按能力标识和参数调用已启用工具，Monty 与插件工具均经此入口执行 |

这四项是首版模型工具入口，不是四个无限制内部方法。资源、记录、技能正文、界面状态等采用受管理对象引用；对象可存于 SQLite 或资源文件，不要求一个对象对应一个文件。引用不是授权，每次操作检查范围，不接受任意宿主路径。输入输出可使用资源引用，避免重复传输大内容。

## write 的意图与内部提交

创建指定对象类型、内容及目标位置；更新或移除指定对象引用、预期版本及类型允许的变更。小内容直接传入，大内容使用既有资源引用。界面可以一次提交多个操作，不要求逐 DOM 元素调用。不提供任意字段修改、通用 JSON Patch 或第五个 delete 工具。

模型一次提交完整写入意图，不手动编排 stage/commit。宿主内部继续完成权限、schema、版本、内容校验、必要审批、界面暂存与预览检查、受控提交。宿主内部接口及插件异步接口明确区分已提交、等待审批或失败，待审批返回可 read 的动作引用。模型侧 write 等待终态才返回工具结果，界面即时显示动作标识和审批进度，不要求模型轮询；已接收不等于已生效。校验或版本失败保留原状态，不自动合并或扩大范围。具体执行中状态与字段待 schema 化，不据此省略既有异步动作状态。

通用 write 不授予任意写权：运行记录、授权、凭据等宿主控制数据不能任意改写。不可变资源内容变化创建新版本，正式答案不可随意覆盖。移除 View 不删除历史、作答或底层资源，资源回收仍属宿主。永久删除任务、卸载插件等管理操作不通过通用 write 向模型开放，继续走专门宿主入口和用户确认。

## 按需发现契约

对象类型与能力契约也经 list/read 发现，不新增发现工具，不一次注入所有插件 schema。模型先看摘要，按需读取详细契约，再通过 write/call 使用；常用稳定基础约定写在四工具说明中，不强制每次重复查询。模型自报类型/schema 不能创建权限或改变宿主已注册契约。

未启用插件只提供供用户选择的静态发现摘要，不能借 read 契约加载未获准正文或执行能力。已启用能力的契约仍需运行时校验；动态参数不能绕过调用前授权或结果修改检查。

## 宿主机制与插件协议的区别

四原语仅约束面向模型的入口，不要求插件 JSON-RPC 或内部模块改为四个方法。界面 stage/commit、审批、调度、草稿自动保存、上下文压缩和导出打包仍保留内部职责，不分别成为模型工具。普通提问、说明和交还控制权使用正常回复，明确用户意图和权限审批的规则继续有效。

不因统一入口新增 shell、浏览器、网络搜索、OCR 或全格式解析；扩展由已启用插件提供，内置 Monty 仍保持单次、无网络和宿主文件访问。具体对象类型列表、list 过滤项、read 范围、write 变更 schema 和 call 信封后续对齐。

## 多格式输入

上传/选择资源由可信宿主处理，保存独立副本、MIME、摘要和基本元数据；资源版本不可变，不长期引用源路径，不监听同步源文件。重新导入或修改创建新版本，失败不退回源路径引用。文本支持按范围读取；图片在模型支持时可作为视觉输入。其他格式可接纳、保存并交给适合的能力处理，不保证核心理解其全部语义。

无解析能力时明确报告。派生表示关联原件和可用的页码、时间戳、单元格等定位；截断和解析失败显式标记。不得将输入材料里的指令当作宿主权限。

资源读取检查任务与主体授权，resource_id 不代表持有即有权访问。不能通过请求宿主绝对路径替代资源引用。

单独导入只保存登记，不自动启动 Run、解析或外发；随明确请求才按需处理。首版支持文件选择/拖入和明确添加为材料的文本，不内置网页抓取、目录递归或压缩包解包。多文件逐项提交，缺附件的请求先由用户决定是否部分继续。

解析复用已有工具协议，能力描述供 agent 选择，不默认全量尝试。派生结果绑定原件版本、处理能力版本和参数，可查询复用，重解析产生新结果，不自动刷新。大结果先资源化，直接响应有界，正文范围读取且明确截断。资源默认惰性，预览不执行活动内容或自动外联，详见 [输入处理](input-processing.md)。

## 一次性代码执行契约

**内置代码执行 tool 不提供持久化的任务代码工作区；此规则不约束插件自行管理的执行环境。** 每次调用由 tool 读取获准资源并转换为显式数据，执行代码不能自行读取宿主存储。

```text
宿主 tool 校验代码、输入与预算
  -> 显式传入普通数据/字节
  -> 一次执行，禁止网络与宿主文件访问
  -> 接收有界结果和打印输出
  -> tool 校验并保存输出，返回资源引用
  -> 执行环境销毁（所有退出路径均必须执行）
```

实现可以使用临时内存状态，但不能挂载宿主目录、保留会话变量、文件或进程供下次使用。输出持久化属于环境外的 tool，不是保存执行目录。取消后迟到结果不得落盘成为有效产物。

已确认采用 Monty 原生后端作为首版集成基线，接受受限 Python 子集，不支持任意第三方包，不并行建设 WASM 实现。生产限额、平台封装和完整验收仍待完成，详见 [选型与启用门槛](code-execution.md)。不得在沙箱不可用时退回宿主 Python、Node vm 或 shell。

返回协议必须处理大整数、非有限浮点、字节、集合和循环对象，采用明确编码或明确拒绝；不能假设任意结果可以直接 JSON 序列化。文件名仅作展示元数据，不能决定宿主写入路径。

## 插件工具接入

插件是用户信任的本地代码，自选语言、依赖和运行环境，不受 Monty 沙箱约束。首版通过本地子进程和双向 JSON-RPC 2.0 接入，不直接导入主进程；这用于接入与故障隔离，不是 OS 安全沙箱。详见 [插件接入契约](plugin-integration.md)。

任务级实例按任务运行，全局级按应用运行，进程可以复用；每实例串行工具调用，控制消息和只读查询不能被调用或审批等待堵住。注册先读静态声明、人工确认、再启动，不执行安装脚本。

调用前检查授权与具体参数，返回的修改提案再走统一动作入口。插件可主动查询级别范围内全部任务业务数据，并申请动作；动作一次一个任务，待审批不占写入队列。工具目录查询不等于工具执行。

取消先废止提交资格并请求停止，宽限后终止直接管理的进程；不自动重试，不保证回滚外部副作用或停止所有后代进程。日志、返回和错误有体积限制。

## 资源生命周期

资源分为用户原件、派生材料、工具输出和界面资产。保存前校验大小、数量和内容类型；应用私有目录不向生成页面直接开放。读取由受控资源接口提供，避免扩大成任意 file URL 通道。

删除任务撤销其资源访问与执行租约，关闭所属任务级插件实例；全局插件继续运行但不能访问已删除任务。宿主清理其独占资源及凭据引用；存在其他合法引用的资源按引用规则保留。过期草稿、孤立资源、失败执行临时输出需要回收。具体保留期限待产品确认，不默认无限记录敏感内容。

## 插件产物与存储提交

小产物显式通过有界消息返回，大文件使用受控分块上传，资源创建走统一授权。返回的宿主路径只作为数据，不自动打开；文件名只作显示元数据，不控制存储路径。

临时接收内容未校验/提交前不成为可引用资源。先校验并保存不可变文件，再以数据库事务登记和建立引用，成功后报告完成。失败/取消清理临时数据，孤立文件延后回收且避开进行中的保存。缺失/损坏历史资源明确报告，不静默重生成。

任务删除人工确认永久执行，不做回收站；先撤销访问、执行和上传，再清理。中断后继续维护清理，不恢复 agent；共享引用仍有效的资源保留。完整规则见 [存储与恢复](storage-recovery.md)。

## 插件工具转调

插件经 harness 调用其他工具仍属于执行而非查询，绑定真实来源、目标任务、授权及宿主维护的调用链。跨级依赖不提升调用方权限，全局工具返回/引用/修改的资源按本次调用范围检查；插件独立动作按原注册级别处理，不能混用身份。

当前调用链不得重复进入同一插件实例，直接拒绝而不等待；转调深度、次数、耗时有界，继承来源预算和取消关系，无 Run 动作也有独立限额。此检查不阻塞控制与查询，也不约束插件自行 OS 调用，不保证识别普通文本中的越界数据。见 [插件接入](plugin-integration.md)。

## 嵌套调度与结果语义

顶层调用可有界排队，嵌套转调先完成授权，再尝试获取目标实例名额；忙碌返回明确未执行，不排队、不自动循环重试。审批不预占目标实例，父调用仍占自身实例与预算；父调用结束、取消或超时使未派发子调用失效，已派发执行沿取消关系处理。

子结果区分成功、未执行、失败、取消和未知。普通失败由父工具决定结束、部分返回或在授权与预算内继续；必要步骤未完成必须标明失败/部分完成并引用子结果。来源取消、超时、撤权不能忽略，未知效果不能按未发生重试。宿主不判断领域业务是否完整，具体状态编码待 schema 化。

## 审批等待计时

工具有效执行超时与审批有效期、来源总墙钟分别管理。只有宿主验证的显式审批等待才暂停相应有效计时，等待期间该父调用不派发工具或提交业务修改；恢复工作先恢复计时。等待不重置预算或释放实例占用，来源总墙钟和审批期限持续计时。审批过期为未执行结果，来源总时限到期则终止关联执行。详见 [运行时](runtime.md)。

## list 的基础查找边界

list 支持对象类型、所属范围、时间、状态等已定义字段筛选，以及名称、简短描述等元数据关键词匹配，结果明确标注匹配范围。名称未匹配不表示正文不存在相应内容。首版不自动扫描文件正文、展开压缩包或建立语义索引；全文/语义/学科检索由扩展能力经 call 提供，返回引用仍需权限检查。筛选字段和匹配规则待 schema 化。

## read 只读取已有表示

文本及结构化对象返回有界内容或指定片段，附版本、范围、截断标记及续读方式。图片在权限允许且当前模型支持视觉时，可作为本次读取的模型输入；不支持时明确提示，不静默丢图。

PDF、音视频、Office 等返回元数据、资源引用和已有派生表示引用，不隐式解析、OCR、转码或外发。需要转换时显式 call 对应能力，再 read 产物。模型侧不返回大段无意义二进制/Base64；插件原始字节读取仍走受控资源接口，不必经模型上下文。

## 变化后重读最新内容

read 返回对象版本，续读携带该版本。未变化时继续；发现变化时中断当前续读并明确要求从头读取最新版本，不返回新版本的后续片段供混读。模型放弃本轮旧片段，重新读取最新内容，不继续读取旧版本或拼接新旧内容。

重读受调用次数和时间预算限制，持续变化导致无法完成一致读取时明确提示，不无限重试。具体限额、范围和续读字段待定义。版本检查不冻结对象，不保证读完后内容不再变化；后续 write 仍检查预期版本。不可变资源和正式历史引用仍保持原有含义，不把对指定不可变版本的读取擅自替换为另一资源版本。

## write 的独立请求身份

每次新提交独立登记，不提供写入意图键、参数摘要比较或去重保留窗口。原操作可按 ID 查询；相同内容不代表相同执行结果，新的请求仍须通过正常授权和版本检查。

## call 的唯一 ID 与最小执行契约

每次 call 都是新的调用，harness 在登记时生成并持久化唯一调用 ID，再进入审批或调度。模型/插件不能自行指定或复用该 ID。能力和参数相同也分别管理和执行，不做调用意图去重或参数结果缓存。调用 ID 用于关联审批、队列、状态、结果、取消和父子调用，不是去重键，也不同于模型服务或 JSON-RPC 的消息关联 ID。

已有调用通过 read 及调用引用查询，再次 call 不表示查询或续接。结果未知时不自动重新 call，以免重复外部副作用。write 和插件动作申请也不提供去重，不保证外部效果恰好一次；内部关联到同一调用的审批/状态通知不是新的模型 call。

模型侧默认等待执行终态及有界结果，由宿主管理授权、调度及审批等待，不要求模型反复 read 轮询。界面可在登记后展示调用 ID、进度和状态，不必等模型收到终态。审批仍按已确认的等待计时、总时限、取消和失效规则执行，不因同步式模型体验阻塞控制通道。

首版不提供脱离来源执行的后台调用模式；父子调用、Run 和独立动作的既有生命周期继续适用。插件间异步 RPC 可以立即返回动作引用，不要求其等待方式与面向主模型的工具返回一致。

一次 call 仅指定一个已启用能力标识及符合该能力 schema 的参数，真实主体、任务和执行范围由宿主绑定。一个调用 ID 对应一次执行。能力自身可声明批量输入，多能力组合由 agent 决定，插件内部转调沿用调用链规则；call 不内置批处理步骤、分支、循环或跨能力事务。调用 ID、结果信封等具体字段仍待 schema 化。

## 模型工具请求的串行处理

同一响应中的 list/read/write/call 按返回顺序串行处理，每项派发前重新校验权限、版本、来源状态和预算。审批等待阻止后续项派发，成功后才能继续。失败、拒绝、过期、忙碌或未知结果停止本批剩余请求，未派发项明确标记前序未成功导致未执行，不伪装为自身失败。

有效来源可在剩余预算内将结果交还模型重新判断，不自动重发整批；来源取消/超时/撤权不再推理。序列不是事务，已提交成果保留，单次 write 内既定界面原子提交不变。插件内部子失败处理与跨任务并行不受此规则替代。见 [运行时](runtime.md)。

## 参数错误与显式修正

参数不符合契约时不执行，返回结构化错误类别、字段位置、原因及必要修正提示。宿主不猜测补齐目标、不替换能力、不放宽 schema 或强制转换错误类型；契约明确声明的默认值可以应用，不属于猜测性修复。

版本冲突返回当前获准的版本信息或引用，由模型重新读取并判断，不自动覆盖。权限错误只能说明合法处理路径，不建议通过切换主体或扩大范围绕过，反馈不得泄漏越权数据。

修正后由模型显式发出新请求，仍受预算及前序失败停止本批规则约束。write 每次新提交均由宿主分配新 ID；call 每次生成新的宿主调用 ID，不把重发当成原调用续接。具体错误字段及默认值规则待 schema 化。

## 有界结果与保存失败

小结果直接返回有界内容；大结果由宿主按既有权限、配额和提交规则保存为受管理资源，返回执行状态、资源引用及有界预览。预览明确标注截断，不能冒充完整结果；状态、错误及必要引用不能因正文过大被截掉。需要正文时用 read，仍遵守版本和范围规则。

不隐式调用模型总结、筛选重要内容或改写工具结论，不新增隐藏模型费用。结果保存不因来自工具而绕过授权，也不放开任意文件路径。

超过允许保存体积或无法安全保存时，明确报告结果接收/保存失败，区分已知执行情况与产物保存情况；不知道是否执行成功时保留未知，不能推断工具未执行或自动重跑。不得返回不存在或未完成保存的资源作为有效产物。已产生副作用不因保存失败自动回滚；具体结果信封、预览长度及体积上限待定义。

## 通用任务数据对象

提供最小的、带 schema 的通用任务数据对象，用于计划、观察、实验参数等领域状态，不新增记忆工具。通过 list/read 查找和读取，通过 write 创建、整体替换或类型允许的移除；更新与移除检查授权及预期版本。对象包含类型、结构化内容及来源信息，大文本/文件使用资源引用，不无限嵌入正文。

插件可声明领域 schema；无合适 schema 时，agent 可在创建通用对象时提供局部受限 schema。宿主验证 schema 本身并限制大小、复杂度，禁止远程引用和自定义校验代码。局部 schema 仅约束该对象结构，不注册宿主类型/工具/权限或执行规则。对象创建后 schema 固定，改变结构须创建新对象，不隐式迁移旧数据。

只保留当前数据版本与必要审计（来源、操作、版本等），不默认保存每次修改的完整内容、不提供任意回滚。正式作答、已发布界面及其他历史证据必须保存当时所需的不可变快照或资源版本，不能仅指向可变对象。修改/移除不得改变历史证据；存在无法安全解除的引用时拒绝移除。

数据仍受任务级/全局级读取和修改授权管理，命名空间不是私有屏障，不作为秘密存储。业务字段不能修改 Run、审批、权限或凭据。保存不自动触发模型/工具/流程，也不证明内容为事实，观察与推断继续区分。具体对象信封、schema 子集、引用及审计字段待定义。

## 单对象写入与提交时快照

普通 write 一次针对一个目标对象，不提供通用跨对象事务。界面对象内可包含多个 View 操作，沿用已确认的发布原子性；正式答案与对应事件同事务保存等宿主保证继续保留，不因此允许任意对象混合提交。

任务数据更新与界面更新若为两次 write，分别报告结果，不自动回滚、补偿或重试。需要一致历史依据时，提交方明确声明采用的数据对象及预期版本，不隐式依赖可变的最新值，也不默认复制整个任务状态。

宿主在界面或正式记录提交时检查所声明的数据版本，匹配后自动固化所需快照并绑定新内容或记录；版本变化拒绝该提交，要求重读，不静默采用新版本或拼接旧片段。快照是本次提交的内部产物，不新增模型工具，不允许顺便修改源对象，不扩展为通用跨对象写事务。

源对象后续更新或移除不改变已保存快照，快照及其资源引用沿用历史保留与回收规则。快照记录当时采用的数据，不证明内容真实或教学判断正确。具体引用字段、快照结构与事务实现待定义。

## 界面目标与显式引用

模型修改界面时，Surface 是唯一顶层 write 目标，View 是其中的操作目标，不另设独立 View 模型写入口。只提交所需 View 创建、整体替换、移除或布局操作，不重传整页；多个操作仍按一次界面发布原子提交。沿用 Surface 预期版本及涉及的 View、状态和资源检查，不相关 View 并发修改仍可能保守冲突，不自动合并。

任务数据、工具参数及结果中的对象/资源引用使用宿主可识别的显式结构，具体字段待 schema 化。普通字符串即使形似 ID，也不产生读取、授权或引用保留效果。宿主校验显式引用的访问范围，在保存时登记需要保护的资源；引用本身不授予权限。HTML/CSS 使用专门的受控资源格式，由解析器校验并登记，不扫描普通字符串猜测。

可变任务数据引用必须携带预期版本，不自动跟随最新值。read 默认只返回当前对象及其引用，不自动展开；显式读取目标时版本不符返回冲突，调用者重新读取最新内容后决定是否更新引用方。引用不要求保留目标旧版全文；长期依据使用不可变快照。

当前任务数据对象的显式引用阻止目标被移除，包括目标已更新而引用仍绑定旧版本的情况。拒绝时仅展示获准的引用来源；先获准整体替换或移除引用方解除引用，再移除目标，不自动级联删除或改写，不提供跨对象事务。目标更新仍允许，旧引用随后产生版本冲突。独立历史快照不阻止源对象移除，但继续保护快照所需资源；永久删除任务沿用整体清理流程，不要求用户逐个解除任务内部引用。

允许循环引用，不强制业务关系无环。宿主不自动递归展开、更新或复制引用链；显式读取受预算约束。历史快照只固化提交方明确声明的对象及版本，不递归冻结关联对象，未明确纳入的可变目标不因此获得历史保留保证。循环关系需先显式解除引用再移除，不隐式级联处理。

## 执行与交付分别记录

生命周期状态、执行情况和结果交付情况分别建模。执行情况至少区分未执行、成功、部分完成、失败、取消和结果未知；交付情况至少区分不适用、待处理、已交付和交付失败，具体字段/编码待定。

执行成功但输出保存失败应保留两项事实，不推断未执行、不自动重跑；执行失败而错误报告已交付也不能记为执行成功。交付失败使本项未完整成功，停止模型工具序列后续项，既有成果保留。取消不代表已发生副作用被撤回。

## 四原语与默认授权

list/read 在所属范围内默认允许。主 agent 的 write 可新增本任务数据和 View；同 Run 新建且未经用户/他方改动的内容可继续更新，每次仍检查版本，不包含移除或整体布局。已有内容修改无默认许可时审批，批准仅覆盖具体动作，不生成长期/通配授权。View 事件本身不授予来源单元修改权。

call 信任已获信任并启用插件的只读声明，合法范围内免逐次审批，不审查插件真实 OS 行为。Monty 计算及正常有界输出保存同样默认允许，但不突破运行限制、启用门槛或获得已有内容修改权。所有入口仍执行范围、参数、预算与生命周期检查。

获准调用的小结果直接返回、大结果保存为新受管理资源均无需另批；宿主决定位置/归属，校验引用和体积，失效调用不发布有效产物。正常结果保存不等于执行其携带的业务修改提案，后者仍另行授权。具体授权事实字段待定义，见 [安全与审批](security-approval.md)。

## Call 与审批记录关联

每次 call 都登记唯一 Call；默认允许时记录授权依据后调度，不创建空 Action。需要额外审批才关联调用授权 Action，批准后继续原 Call，不新建调用。调用授权 Action 在成功派发时完成，执行结果归 Call；业务修改 Action 在提交时完成，write 或结果修改提案可有 Action 而没有 Call。

Action 最多关联一条 Approval，处理方式转人工不重建或延长期限，决定与有效性分开。拒绝、过期、失效不在旧动作重开审批。调用派发、业务修改提交时分别检查有效批准；合法派发调用不因审批自然到期终止，来源取消/撤权继续生效。正常结果保存与结果修改提案仍分别处理。详见 [安全与审批](security-approval.md)。

## Call 生命周期、派发与可读结果

Call 使用已登记、等待中、执行中、收尾中、已结束五阶段，具体字段编码待定。已登记表示调用 ID 已持久化；等待中记录审批或允许排队的名额等原因；执行中涵盖派发与等待工具返回，不证明插件已经开始执行；收尾中接收、校验、保存结果或进行取消/异常清理；已结束表示宿主管理的必要收尾完成，不再推进调用。执行情况与结果交付情况独立记录，终态不倒退。

首版不强制插件接收握手。宿主确认完整请求已写入受管理传输通道，即记录派发完成，适用的调用授权 Action 完成；这不证明插件已读取或执行。明确尚未发送为未派发/未执行；发送过程失败且无法确认完整送达为派发未知，Action 不伪报成功或明确未派发，Call 不推断未执行。已完成发送后丢失结果，保留派发完成事实，Call 结果未知。所有未知情况均不自动重发，唯一 ID 不构成恰好一次保证。

进入收尾后不再派发新的业务工作；正常返回可完成获准结果保存，取消/失效后的迟到输出不能成为有效产物。已结束后若收到能由宿主确认原连接和调用来源的有效响应，可补充执行报告及来源/时间，不改写原结束记录、不恢复 Call/Action/Run、不继续后续工具或发布产物/修改提案。不能仅凭插件自报调用 ID 认领，不要求保留失效连接等待补报。新 Run 可读取获准的补充事实。

“结果已交付”以宿主完成接收、校验及必要保存，提供可读结果为准，不等待模型/插件/用户确认消费。小结果记入调用记录，大结果保存有效资源并生成引用，状态、错误和截断信息齐全；界面可显示“结果已保存”。之后发送失败、模型请求失败或页面关闭另记，不改为交付失败，也不重跑工具；获准主体查询原 Call 即可读取。校验/保存失败仍为交付失败，不因工具报告成功而放行。

插件实例的工具执行名额保持到 Call 必要收尾完成并进入已结束才释放，不能仅因收到结果或取消响应提前放行。同实例下一次调用等待，其他实例/任务及查询、响应、取消等控制消息不冻结。已保存结果发送失败不等待消费方重连。此名额释放与调用授权 Action 在发送完成时结束是不同边界。

## 不提供业务去重

write、call、插件动作申请、业务请求和表单事件提交均不按客户端标识、相同参数或内容合并，不复用旧执行结果。每次有效新提交由宿主生成唯一操作/事件 ID，重新检查授权、版本和状态；ID 仅管理该次操作。客户端消息关联 ID 不成为业务幂等键。此前写入意图去重及终态后 1 小时窗口已撤销，不实现参数规范化摘要比较。

查询原操作使用原 ID，不触发执行。再次提交属于新操作，可能产生新结果或副作用，也可能因当前版本/权限被拒绝；不保证相同请求成功两次。响应丢失或结果未知不自动重发。表单每次明确提交生成新的记录（通过校验后），界面在提交期间禁用按钮减少误触，不以内容或客户端标识合并。版本校验、事务原子性、旧许可失效和同一已登记动作不复活仍保留。

## 字段级工具契约与开发限制

对象读写目录、四工具字段、显式 references、局部 schema 子集和完整界面生成示例集中见[对象与四工具](../contracts/objects-tools.md)，结构见[核心 schema](../contracts/schemas/core.schema.json)。小界面可内联，大内容引用统一 bundle；Surface 仍是唯一界面 write 顶层。

list 使用稳定排序的不透明游标，分页为实时弱一致，不保存长期快照；并发变化可能遗漏/重复条目，操作时重新鉴权。read 对文本采用行范围和宿主管理游标，超长行可分段；版本变化从最新重读。对象/能力完整内容继续按需加载。

无响应且无宿主操作 ID 时查询近期操作列表；仅连接关联能确认才自动定位，不按相同参数认领结果，不重发。开发单次正文/预览分别为 32 KiB/8 KiB，具体完整限制见[默认配置](../contracts/development-defaults.json)，不把状态和错误随预览截掉。
