# Agent 运行时

状态：运行行为已确认，状态编码和转换表已有契约草案；尚未实现运行时。

## 执行模型

每个任务一个主 agent，同一任务的推理请求串行处理。插件不是独立 agent，不建立插件间自主协商或子 agent 调度。页面本地交互和输入保存不等待模型完成。

无 workflow 也可理解用户请求、按需读取资源、发现已安装能力、调用基础工具并构建界面。禁止自动安装插件；缺少能力明确反馈，不虚构执行结果。

## Workflow 不等于工作流引擎

Workflow 是带元数据的流程说明，描述目标、步骤、条件、等待与完成标准；主 agent 理解并推进。Harness 不解释领域阶段图、不验证教学步骤顺序、不维护 entry_stage/stages 状态机。

可记录模型提出的当前计划或进度，但它们是可修订的任务数据，不是权限来源，也不是宿主证明的教学结果。安全检查、工具 schema 和预算始终程序化执行，不依赖流程说明。

v0.1 每任务至多由用户选择一个主 workflow，避免多个流程提示竞争。Skill 和工具可以按需组合；流程说明不能覆盖宿主规则。

## 最小循环

```text
接收持久化事件
  -> 获取当前 run 与执行权限上下文
  -> 组装当前目标、相关资源、能力和必要历史
  -> 调用模型
  -> 解释响应：工具 / 用户问题 / 界面更新 / 完成
  -> 执行权限检查、必要审批及 schema 校验
  -> 调用工具并记录结果
  -> 继续、等待用户或结束
```

流式文本可以即时显示；不完整工具参数和界面脚本不得边生成边执行。模型自报身份、授权或完成不等于宿主已经执行该动作。

## 上下文与能力归属

默认加载能力摘要，按需读取正文。材料、工具结果和页面输入是数据，不得升级为系统指令。上下文包含当前目标、最近交互、相关状态和可定位证据，不无限追加全量历史。

上下文采用固定规则、工作摘要、最近完整交互和按需读取原记录。每次请求前按完整输入与输出预留检查预算，依次按需装载、确定性缩减、必要时同步语义压缩；不并行后台压缩。摘要是有损导航，不删除原记录、不证明授权。独立无工具摘要请求默认使用主模型，成本计入 Run；候选校验后替换，可纠正失败最多重试一次，仍失败结束 Run。详见 [上下文管理](context-management.md)。

执行身份和范围由 harness 根据请求来源与已有授权建立，模型不能自报身份。读取 skill/workflow 只提供知识，不改变身份或合并权限。主 agent 通用产物归任务所有；特定区域的修改通过宿主授予的范围能力完成。

View 事件提供来源和版本上下文，不授予来源 View 修改权。普通请求及事件 Run 可读本任务业务数据并新增任务数据/View，不能默认覆盖已有内容或调整已有布局；工具调用单独检查。具体默认权限与单次批准见 [安全与审批](security-approval.md)。

插件读取使用注册级别：任务级读所属任务全部业务数据，全局级跨任务读取，不随 Run 范围缩小；插件没有默认修改权。不能把插件级别、主 agent 的 Run 范围和内容归属混为一谈。

## 模型接入

首版接入明确版本/能力约定的 OpenAI-compatible Chat Completions，支持流式输出、工具调用、取消及标准错误。记录服务能力，例如视觉输入、工具调用、上下文限制；不以“compatible”推断支持全部特性。

主 agent 与审批模型使用不同角色配置和独立消息上下文，可以共用服务和模型。审批不是主 agent 的子流程自批。模型请求只发送任务需要的资料，不泄漏其他任务或凭据。

## Task、Run 与动作

Task 长期保存目标、材料、界面和历史，Run 处理一次用户请求或推理事件，可包含多轮模型与工具调用。Run 生命周期分为运行中、等待中、已完成、已失败、已取消、已中断，具体字段编码待定，不是 Task 的教学阶段；Task 自身生命周期字段另行定义。

每任务至多一个未结束 Run，waiting 也计入；新推理请求排队。用户可以明确取消当前 Run 再处理新请求，不自动抢占。Run 结束不等于显式停止任务或删除任务；关闭任务页面不停止执行。

等待权限审批时暂停当前 Run；提出学习问题或需要用户意图选择并交还控制权时结束 Run，用户回答开启新 Run。临时资格不继承，下一轮重新按默认规则和具体动作判断授权；首版不提供长期或通配授权。

插件无活跃 Run 也能申请动作。动作有独立 ID 和审批状态；确定性动作不启动模型，需要推理才排队创建 Run。待审批不占任务写入队列，批准后与主 agent 更新共用统一写入口；执行前重新校验权限和版本。

审批暂停不冻结任务：查询、本地交互、输入保存和其他获准动作继续。Run 恢复必须重新读取可能变化的状态。插件回调查询不能被串行工具执行占住通信通道。

## 取消和恢复

### 模型输出中途断开

流式说明可即时展示但标明未完成；工具调用完整接收、解析和校验后才能派发。断开时已提交 View、资源和其他结果保留，不回滚；残缺调用不执行，已派发结果未知的调用不自动重试，不重跑整轮。

只有本次模型请求尚未收到任何输出、且错误明确属于暂时性故障时，允许预算内有限自动重试；认证/参数错误直接提示。收到部分输出后断开将 Run 标为中断，用户继续时创建新 Run，依据保存的执行记录和当前状态处理，不原样重放失败请求。

### 取消与应用重启

取消当前 Run 不删除 Task，也不撤销已提交内容；其关联的未完成动作和待审批请求失效。使用 run 租约/fencing 检查拒绝旧执行结果；无 Run 的插件动作使用各自动作许可和实例有效性检查。插件独立动作不因无关 Run 取消而失效。

取消或超时的插件调用先请求停止，宽限期后终止直接管理的进程；不自动重试，不保证清理后代进程或回滚外部副作用。内置 Monty 仍严格单次销毁，不使用插件复用规则。

事件持久化后才确认接收，accepted 不等于完成；队列限量但不去重，每次有效提交独立登记。重启只恢复数据，不自动继续 Run、调用工具或恢复旧执行进程。未结束且尚未确立结束边界的 Run 按执行中断收尾；已经确立边界的保留拟结束状态及首要原因。旧临时授权和审批入口失效，核对必要残留后完成清理，不恢复旧执行，保留记录供展示。

用户明确继续后创建新 Run，重查参数、版本和授权，不从中断代码位置续跑。待处理动作（含无 Run 动作）不在启动时静默执行；已派发结果未知的插件调用明确标记未知，不自动重试。已确认任务删除的清理作业可继续，这是维护动作而非恢复 agent。详见 [存储与恢复](storage-recovery.md)。

输入草稿与 View 版本协调，旧题答案不自动应用到新题。恢复后的审批重新检查有效期、参数和授权。

## 预算

每个 run 限制模型调用次数、token/成本预算、工具调用次数、墙钟时间、输出体积与重试次数，具体数值待验证。压缩调用次数、token 和耗时也计入当前 Run，压缩预算不足结束本次 Run 并解释；其他预算终止状态编码待定。不静默无限循环，网络重试不自动等于工具副作用重试。

## 导入与请求启动

单独导入只保存和登记，不启动 Run 或解析调用。附文件的明确请求等待导入完成再开启或排队 Run；部分附件未成功时，默认不启动该请求，由用户选择仅用成功文件继续或补齐后发送。取消导入保留已成功文件，不自动触发推理。

Agent 按任务需求发现并选择解析工具，不默认执行全部候选；关键费用、外发或结果取舍尚未明确时先确认用户意图。失败换工具不能扩大请求、权限或预算。优先查询可用派生资源，大结果分段读取，见 [输入处理](input-processing.md)。

## 模型配置占用与跨任务调度

自动发现模型、补全参数，关键参数无法确定才局部手动配置，不采用猜测性容量兜底；真实合成请求由用户点击测试并启用，按角色验证。服务失败不自动切换模型、渠道或凭据。

请求提交记录配置选择，尚未启动的任务请求不锁配置；启动前复核，配置变化需用户确认，启动 Run 后占用相关模型与渠道。未结束 Run、已进入调度的独立模型请求占用期间均禁止修改/删除对应配置，等待审批或服务名额不释放占用。共享渠道锁定不妨碍未占用模型独立参数编辑。

跨任务模型请求受应用级/渠道级并发限制并公平排队，主推理、压缩、辅助审批、连接测试均计入。并发名额仅在实际请求期间占用，与配置锁分开；取消排队请求不得再发送。详见 [模型服务](model-services.md)。

## 任务停止与显式恢复

页面可见性与执行状态分离：切换任务、关闭任务页面仅改变展示，应用运行时已启动执行可继续，审批保留在统一待办入口。取消当前 Run 不等于停止整个任务，前者不取消无关插件独立动作。

用户显式停止任务时，先通过同一任务写入协调机制确立停止边界，将任务置为“停止中”，禁止新业务执行，废止旧执行的提交资格，取消该任务未完成 Run、未启动请求、未完成动作及审批。包括无 Run 的独立插件动作，不仅是当前 Run 的子动作。停止生效前已提交的成果保留；尚未提交的业务修改及迟到结果拒绝，不回滚已提交成果。

随后取消模型请求和工具执行、卸载自定义脚本区域、停止任务级插件；不响应取消的插件在宽限后终止直接管理的进程。全局插件无需退出，仍可按原范围只读查询，但不能修改停止中的或已停止的任务。不能承诺撤回已发网络请求、外部副作用或清理插件全部后代进程。

宿主管理范围内的清理完成后进入“已停止”；清理异常明确显示，不伪称全部进程已退出。“停止中”不允许恢复，避免新旧执行交叠。状态编码和清理重试接口见[执行契约](../contracts/execution-storage.md)，尚未实现。

停止中和已停止时仍允许受信任的基础阅读、展开折叠、表单填写、草稿自动保存及明确提交答案。答案与事件仍事务保存，但不进入推理队列，提示“答案已保存，尚未处理”；用户保存是明确例外，不是给 agent/插件开放业务写权限。自定义脚本区域展示静态表示，不运行脚本。

重新打开任务不自动恢复。用户显式恢复仅重新开放后续执行能力，允许当前有效脚本重新初始化、仍受信任且已启用的任务级插件按需启动，不恢复原进程或脚本内存。可加载与当前内容版本兼容的已保存界面状态，但不得自动提交或重放操作。代码或启动配置变化仍需重新确认信任。

恢复本身不创建 Run、不调用模型、不重放旧请求、审批、工具调用或停止期间的作答。用户明确发起新请求后按需读取已保存记录；恢复后插件可提出新的动作申请，仍需授权与审批。退出应用不承诺后台继续，重启恢复数据但不自动续跑。

## 插件选择与能力配置稳定性

新任务默认仅有基础能力。用户通过按能力类型分类的界面整体启用插件，并单独选择至多一个主 workflow。安装仅使静态摘要可发现，agent 可以建议但不能自行启用；正文只在启用后按需加载。纯内容包不启动进程，启用可执行插件也不立即调用工具。全局启用不自动注入所有技能或流程。

未结束 Run（含审批等待）或插件动作/调用存在时，禁止新增启用、切换流程或更新/替换相关版本。用户停用或撤销信任始终允许，取消依赖执行并拒绝迟到结果；主 workflow 所属插件停用则清除选择，不自动替换。配置变更不创建 Run、不改写历史，新请求才使用新配置。全局变更须等待相关占用全部释放。见 [插件接入](plugin-integration.md)。

## 工具转调的执行预算

Harness 维护转调来源、目标任务和调用链，拒绝当前链重复进入同一插件实例，不以排队代替拒绝。无环转调仍限制深度、总次数及耗时，继承来源执行的预算与取消关系；无 Run 动作有独立限额，不因转调创建无限新预算。各次工具调用继续检查权限，控制消息和只读查询保持响应。具体字段和限额待定义；嵌套调用遇到忙碌实例直接返回未执行，不等待目标实例名额，见 [插件接入](plugin-integration.md)。

## 嵌套转调等待与失败传播

顶层调用可有界排队，嵌套转调不等待忙碌目标实例、不自动重试。需要审批时先返回动作标识，等待期间父调用仍占用自身实例与原预算，不预占子目标或任务写锁；获批复核后再尝试获取目标名额，忙碌则明确未执行。

父调用结束/取消/超时使尚未派发子调用失效，已派发子调用按取消关系处理，不允许迟到批准独立续跑。普通子失败不强制父失败，可在授权预算内处理并报告部分结果；必要步骤缺失不得报全部成功。来源取消、超时、撤权必须终止相关执行，结果未知不得自动重放。详见 [插件接入](plugin-integration.md)。

## 审批等待与分层时间预算

分别管理有效执行超时、审批有效期和来源执行总墙钟上限。Run 与无 Run 的独立动作均有包含审批等待的总墙钟上限；审批自身有效期同样有限。模型请求、工具实际运行及普通执行等待继续遵守各自超时，不与人工审批共用单一时长。

仅创建审批请求不暂停有效执行计时。父调用必须明确进入宿主验证的等待状态，宿主核实存在关联且尚未完成的审批；只有该状态暂停相应有效执行计时。等待期间该父调用可查询、取消和接收结果，但不能派发其他工具或提交业务修改；继续业务须先退出等待并恢复计时。主 agent 直接等待审批同样由宿主管理等待与恢复。

等待不重置已消耗时长、调用次数、token 或成本，不释放既定父实例、未结束 Run 和模型配置占用。审批有效期及来源总墙钟持续计时；其他执行自己的计时不因父调用等待而自动暂停。此机制不是 OS 进程冻结，不承诺停止可信插件自身计算或 OS 操作，也不能通过自报等待延长运行。

审批有效期到期时，尚未派发/提交的对应操作返回“未执行：审批已过期”；已合法派发调用不因审批自然到期单独终止，旧入口失效，不自动续期或重复申请。父调用退出等待、恢复计时，按普通子调用失败处理；主 agent 接收过期结果后可在剩余预算内解释或处理，不执行原操作、不自动重复申请。用户之后要执行需新请求并重新检查。

来源 Run/独立动作总墙钟到期则终止来源及关联子调用，不能作为普通子失败忽略。宿主统一判定批准/过期竞态，迟到批准不能激活已失效操作；过期结果也不能恢复已取消、超时或撤权的来源。具体时长、状态字段与错误码待定义及测试。

## 模型工具入口

首版模型通过 list/read/write/call 操作受管理对象或调用已启用能力，不直接使用宿主文件路径。对象类型与能力契约按需发现，未启用插件仅摘要可见。普通提问/说明使用正常回复，不新增交互工具。

write 一次表达完整写入意图，内部仍校验、审批、暂存及提交；模型不自行编排发布步骤。等待审批时内部/插件接口返回动作引用，模型侧 write 则由宿主等待终态才返回工具结果，版本失败不自动合并。call 统一承载 Monty/插件调用，但不绕过现有授权、预算、嵌套调用或取消规则。见 [工具与资源](tools-resources.md)。

## 读取变化与写入重试

read 续读发现对象变化后，模型放弃本轮旧片段，从最新内容重新开始，不拼接新旧版本。重读计入次数/时间预算，持续变化无法一致读取时明确终止该读取，不无限循环；后续写入仍检查预期版本。

每次 write/动作新提交由宿主分配新唯一 ID，独立检查授权、版本并处理，不按标识、参数或内容复用旧结果。查询原操作使用原 ID；重发是新操作，未知结果不自动重发。call 同样每次独立登记。

## call 的模型等待与调用身份

每次 write/动作新提交由宿主分配新唯一 ID，独立检查授权、版本并处理，不按标识、参数或内容复用旧结果。查询原操作使用原 ID；重发是新操作，未知结果不自动重发。call 同样每次独立登记。

一次 call 执行一个能力，模型侧默认等待终态和有界结果，宿主管理等待及审批，界面可独立显示进度；不要求主模型轮询，不提供脱离当前来源执行的后台模式。不在 call 中加入流程步骤、分支、循环或跨能力事务；能力自身可有批量输入，插件嵌套调用仍受原有约束。插件异步 RPC 的动作引用返回方式不变。见 [工具与资源](tools-resources.md)。

## 同一模型响应的工具请求序列

首版同一 Run 内按模型返回顺序串行处理工具请求，不自动并行。每项派发前重新检查权限、版本、取消状态及预算，不以接收整批时的一次校验替代。等待审批暂停该序列，不越过等待项执行后续请求；批准且成功后继续。

前序未成功（失败、拒绝、审批过期、实例忙碌或结果未知）时停止本批剩余请求，未派发项明确记录“未执行：前序请求未成功”，不能记为其自身执行失败。已成功成果保留，多项工具请求不是事务，不因后续失败回滚；单项界面提交的原子性仍按既有协议。

来源 Run 有效且预算允许时，把实际结果交还模型重新判断，不自动重试失败项或重发整批。来源取消、超时或撤权则终止相关执行，不再调用模型重新规划。等待审批不是失败，也不能仅凭已接收/已登记就视为成功。

上述规则约束模型响应中的请求序列，不改变跨任务并行、插件控制消息响应、页面本地交互或插件父工具对普通子调用失败的处理。具体序列关联与未执行结果编码待定义。

## 工具错误与结果接收

参数错误由宿主拒绝并返回结构化反馈，不猜测修正目标、能力或类型；契约声明的默认值除外。模型在有效来源和预算内显式修正，write 每次新提交由宿主分配新 ID，call 重发是新调用；不自动重试本批。

大结果资源化并返回状态/引用/截断预览，不隐式调用模型总结。结果接收或保存失败与工具执行失败分开记录：不能推断未执行、不能自动重跑或回滚外部效果，未知情况保持未知。结果交付未成功时仍遵守前序未成功停止本批规则。详见 [工具与资源](tools-resources.md)。

## write 审批与模型结果时序

模型侧 write 与 call 一样等待终态。宿主登记动作后即时向界面显示标识和待审批状态，暂停本批工具序列，不发起下一次主模型请求；查询、用户输入与其他获准操作继续。批准后复核权限和版本再提交；成功、拒绝、过期或提交失败后才交回对应工具结果，来源取消/超时后不再继续推理。

内部/插件异步接口可以先返回动作引用，不表示主模型已收到完成结果；read 仍可查动作，正常执行不依赖模型轮询。生命周期、执行事实与结果交付分别记录，交付失败按本项未完整成功停止后续工具，不能因执行成功而假报完整成功。见 [工具与资源](tools-resources.md)。

## Run 新增内容的临时修改资格

主 agent 可在本 Run 内继续完善本 Run 新建且未被用户或其他执行方改动的 View/任务数据；每次检查版本，不包含移除、其他对象或整体布局。用户输入/作答或他方修改后不再凭创建来源放行，丢弃输入仍本人确认，Run 结束资格失效。View 事件不隐含改题授权，可新增反馈但覆盖旧内容另行检查。

批准只绑定当前具体动作，不自动产生未来许可。范围合法的可信插件只读调用、Monty 计算及获准调用的正常输出保存默认免逐次审批，但任务停止、取消、预算和接口范围检查仍适用。结果中的业务修改提案另走授权。见 [安全与审批](security-approval.md)。

## Run 生命周期与统一结束边界

Run 使用以下六类生命周期状态，等待原因、结束原因及拟结束状态分别记录，字段编码已有[执行契约](../contracts/execution-storage.md)草案。

| 状态 | 含义 |
| --- | --- |
| 运行中 | 推进本轮执行，包括模型请求和工具处理 |
| 等待中 | 等待审批、模型请求名额等条件，或进行不可逆的结束清理 |
| 已完成 | 本轮正常结束，包括交还用户，不表示学习目标完成 |
| 已失败 | 已知错误或预算耗尽导致结束 |
| 已取消 | 用户取消或任务停止、撤权等触发取消 |
| 已中断 | 流式响应中途断开、进程崩溃或重启导致无法继续 |

未启动请求只存在于任务请求队列，不提前创建占位 Run。等待中仍属于未结束 Run。提出学习问题或要求用户选择后，Run 正常结束，以“交还用户”区别于普通响应完成；界面可显示等待用户回答，但问题存在于任务记录，不保持活跃 Run 或配置占用。权限审批等待则仍属未结束执行。终态不可恢复，用户回答/继续创建新 Run。Run 中断不代表所有调用结果未知，各调用事实独立保存。

宿主确立结束边界时，立即停止后续派发、撤销关联执行的继续提交资格，并固定拟结束状态与首要原因；取消同时废止相关审批和未派发调用。需要清理时进入等待中并标明“结束清理中”（取消时可显示“正在取消清理”），请求停止模型和工具，必要时按宽限期终止直接管理的进程。正常完成也不能留下仍获准执行的关联工作。只有必要清理完成才进入对应终态，释放本任务 Run 名额及相应配置占用；其他占用者的锁不受影响。读取与用户输入保存继续。

结束清理不可逆，不能恢复原 Run。迟到批准不派发，迟到结果不能更新任务数据/界面，仅可补充必要执行事实，例如已产生外部效果；不能作为继续业务的依据。重试清理仅停止、关闭和释放宿主管理资源，不重跑模型/业务工具，不提供忽略清理直接恢复的入口。清理异常真实展示，不伪称终态或释放完成。

首要原因按宿主接受并确立结束边界的顺序固定，不以不同进程的时间戳争夺。取消先确定后工具报错仍归已取消；预算失败先确定后用户取消不改失败原因；正常完成先进入收尾后关闭失败，保留正常业务结论并单独显示清理异常，清理完成前仍非终态。后续事件只补充，不覆盖首要原因或各调用事实。

重启不等待已消失的旧内存执行，废止旧许可并核对必要残留，不续跑旧业务；已确立结束边界的记录保留原因，其余未结束 Run 按中断收尾。清理只覆盖宿主直接管理的执行，不等待外部副作用撤回，也不承诺终止插件全部后代进程。清理处置接口及实现测试仍待补齐。

## 调用、动作与审批生命周期分离

Call 始终登记，默认允许路径只记录授权依据，不强制创建 Action；需审批时关联调用授权 Action，批准后派发原 Call。Action 成功完成派发后结束，Call 继续独立管理执行/交付事实，工具失败不改写派发 Action。业务修改 Action 的完成点是提交，结果修改提案另建 Action，不生成额外 Call。

单个 Action 最多一条独立 Approval，默认授权覆盖可无审批记录。决定、有效性及处理方式分开；转人工沿用原期限，deny 结束审批，不自动重新申请。旧审批/动作不复活。尚未派发的调用在期限内才可准入；已经合法派发不因审批自然到期终止，仍受来源总墙钟、取消与撤权等规则。Action 完成不意味着 Call 或所属 Run 完成，也不提前释放它们的占用。具体字段见后续 schema，行为见 [安全与审批](security-approval.md)。

## Call 收尾与结果消费

Call 的五阶段独立于 Run 六状态：已登记、等待中、执行中、收尾中、已结束。执行中不证明插件已开始；进入收尾不再派发新业务，正常结果可校验保存，失效结果不发布。实例名额在必要收尾完成后才释放，Action 派发完成不提前释放；控制消息继续。

工具结果完成宿主接收、校验和必要保存、可供读取即为已交付，不等下一轮模型消费。后续发送失败单独记录，不将保存事实改成失败或重跑工具。派发不确定/丢失结果不自动重发；终态后来源可验证的报告只补充事实，不恢复执行，新 Run 可按权限读取。详见 [工具与资源](tools-resources.md)。

## 执行配置、重启与状态编码

Action 采用 registered/waiting/executing/ended，结果及原因独立；清理等待不可回到业务执行。Run/Call/Approval 的状态编码和竞态收敛见[执行与持久化契约](../contracts/execution-storage.md)，不是领域工作流状态机。

Run 固定预算配置版本，正常修改只作用于新执行。开发基线为 60 分钟总墙钟、40 次实际模型请求、200 次四工具及派生调用、200000 累计输入输出 tokens；主推理/摘要/辅助审批/实际重试均计数。同次调用不因经过内部模块重复计数。默认无货币额度，预算前预留、usage 缺失明确估算，已发失败请求不直接计零。完整限额见[开发配置](../contracts/development-defaults.json)。

后台崩溃允许 5 分钟内最多 3 次自动重启，仅维护、撤销旧资格及收尾，不能恢复旧业务；连续失败提供人工重试。必要清理失败后 1/5/15 秒有界重试，耗尽保留状态和原因供手动重试。已失效孤立文件删除可延后，不永久占 Run/config/实例名额。
